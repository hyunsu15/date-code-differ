# 2026-09-02 — 데이터 스키마 비교를 붙인다

## 왜

소스만 견줘서는 답이 안 나오는 질문이 있다. **"운영과 테스트의 테이블이 지금 같은가."**

DB 스키마 덤프는 이미 텍스트로 쌓이고 있었지만 볼 방법이 없었다. 이 도구가 이미
좌우(환경·날짜)를 고르는 자리를 갖고 있으니, 그 선택을 그대로 나눠 쓰면 화면 하나만
더 만들면 된다.

## 무엇을 안 했나 — 텍스트 diff

**덤프를 파일 목록에 끼워 넣어 줄 단위로 견주지 않았다.** 그렇게 하면 첫 실행에서
못 쓰는 결과가 나온다. Oracle 딕셔너리를 그대로 흘린 텍스트라, 값을 곧이곧대로 비교하면
없는 변경이 생기는 자리가 세 곳 있다. 셋 다 파서에서 흡수했다.

### 1. `SYS_C0011234` 가 화면을 뒤덮는다 — 제일 큰 것

Oracle 은 `NOT NULL` 컬럼마다 제약을 자동으로 만들고 이름을 **DB 시퀀스로** 붙인다.
그 번호가 데이터베이스마다 다르다. 그래서 운영 ↔ 테스트를 견주면 **내용이 완전히 같아도
제약 수백 개가 전부 "변경" 으로 뜬다.** 이 도구의 대표 용도가 바로 그 비교라 그냥 두면
기능이 죽는다.

`SCHEMA.systemNamePattern`(기본 `^(SYS_|BIN[$])`)에 걸리는 이름은 접는다. NOT NULL
여부는 이미 컬럼 줄의 `NULLABLE` 에 있어 잃는 정보가 없다. **다만 조용히 지우지 않는다** —
몇 개를 접었는지 밴드와 섹션 머리에 그대로 남긴다. 제외 목록에서 "제외 N" 을 굳이
남겨 둔 것과 같은 이유다.

예시 폴더로 확인: 운영 2026-09-01 ↔ 테스트 2026-09-01 에서 SYS_C 번호가 전부 다른데도
`TB_CUST` · `TB_ORD_DTL` 은 **동일**로 잡히고, 접은 수(16)만 남는다.

### 2. `DATA_LENGTH` 는 문자형에서만 뜻이 있다

`NUMBER` 는 늘 22, `DATE` 는 늘 7이다. 내부 저장 크기라 아무 뜻이 없는데 그대로 비교하면
타입이 같은 컬럼이 달라 보인다. 세 필드(`DATA_LENGTH` · `DATA_PRECISION` · `DATA_SCALE`)를
표시용 타입 하나로 합치고 **그것을** 견준다.

| 원본 | 화면 |
| ---- | ---- |
| `NUMBER · 22 · 15 · 2` | `NUMBER(15,2)` |
| `NUMBER · 22 · 10 · 0` | `NUMBER(10)` — 자릿수 0 은 정수라는 뜻이라 안 적는다 |
| `VARCHAR2 · 20 · — · —` | `VARCHAR2(20)` |
| `DATE · 7 · — · —` | `DATE` |

`NULLABLE` 이 `N` 이면 NOT NULL 이다 (Oracle 딕셔너리 규약 — 컬럼 이름이 "널 허용인가"
를 묻는다). 화면에는 `NOT NULL` 을 찍고 널 허용은 빈칸으로 둔다.

### 3. 다중 컬럼 기본키·인덱스는 여러 줄로 흩어져 온다

`POSITION` 을 달고 컬럼마다 한 줄씩 온다. 줄 단위로 견주면 컬럼 하나 추가된 것이
"신규 1 + 기존 그대로" 로 갈라져 무슨 일이 났는지 안 보인다. `(테이블, 이름)` 으로 묶고
위치 순으로 이어 `ORD_NO, ORD_SEQ` 한 줄로 만든 다음 견준다.

## 화면

**위쪽 좌우 선택(환경·날짜)은 코드 화면과 그대로 나눠 쓴다.** 고르는 자리를 두 벌 두면
탭을 옮길 때마다 다시 골라야 하고 "지금 무엇을 견주나" 가 둘로 갈린다. 대신 아래 3단
(밴드·옵션바·본문)은 통째로 갈린다 — 코드의 무시 옵션(공백·주석)은 스키마에 하나도
안 맞고, 스키마에는 제 옵션이 따로 있다.

### 날짜는 자동으로 맞추되 반드시 밝힌다

스키마 덤프는 배포와 주기가 달라 고른 날짜에 딱 맞는 파일이 없는 것이 보통이다.
**그 날짜 이하로 가장 가까운 것** — 그 시점에 실제로 걸려 있던 스키마 — 을 고른다.
고른 결과를 숨기면 엉뚱한 날짜를 보면서도 모르므로, 다르면 `2026-08-01 →` 를 남기고
드롭다운으로 직접 바꿀 수도 있게 뒀다.

### 종류는 목록이 아니라 뷰어에서 가른다

`컬럼` · `제약` · `인덱스` 셋은 서로 나란한 객체가 아니라 **한 테이블의 속성**이다.
사이드바에서 갈라 두면 같은 테이블을 세 번 눌러야 한다. 그래서 사이드바는 테이블 목록
하나로 평평하게 두고, 종류는 뷰어 안 3개 섹션으로 나눴다. 밴드의 종류 칩은 목록을
좁히는 **필터**로 쓴다 — "이번에 인덱스만 바뀐 테이블" 을 뽑아 보는 일이 잦다.

### 표는 나란한 두 판이 아니라 한 줄에 좌우를 합친다

이름으로 짝지어진 줄이라 `왼쪽 → 오른쪽` 을 한 줄에 두면 바뀐 곳이 눈에 바로 든다.
판을 갈라 두면 순서가 어긋난 순간 눈이 계속 왔다 갔다 한다. 양쪽이 같은 줄은 값을
**한 번만** 적는다 — 같은 글자를 두 번 두면 그게 화면의 대부분을 차지해 바뀐 한 줄이
묻힌다.

기본키 변경은 목록과 카드 머리에 `⚠` 를 올린다. 빈도는 낮고 위험은 크다. 다만
**양쪽에 다 있는 테이블에서만** 본다 — 신규·삭제 테이블은 키까지 통째로 생기거나
없어지는 것이 당연해서, 거기에 경고를 붙이면 알림이 흔해져 진짜 신호가 묻힌다.

## 설정

위치는 **프리셋 안**(`schemaRoot`), 형식은 **`SCHEMA` 상수**에 뒀다. 위치는 고치면
바로 반영되고 형식은 서버를 다시 시작해야 하므로 반영 시점이 다른 둘을 섞지 않는다.

```ts
// SOURCE_PRESETS 안, excludeFile 바로 아래
schemaRoot: '/data/db-schema',   // 비우면 '스키마 비교' 탭이 뜨지 않는다

// SCAN 옆
export const SCHEMA: SchemaConfig = {
  fileName: 'snapshot_{env}_{date}.txt',
  separator: ',',
  systemNamePattern: '^(SYS_|BIN[$])',
}
```

`schemaRoot` 를 프리셋 안에 둔 것은 `excludeFile` 과 같은 성격(루트와 무관한 별도 경로)
이라서다. 덕분에 접속 정보(호스트·계정·키·인코딩)를 그대로 공유하고, 서버의 로컬/SSH
읽기 코드도 그대로 쓴다. 예전에 만들어 둔 `config.ts` 에 이 항목들이 없어도 동작한다 —
`ENV_FOLDERS` 와 같은 방식으로 없으면 기능만 꺼진다.

**필드 순서는 파일이 스스로 들고 있다.** 종류마다 첫 줄에 헤더가 오므로
(`[COLUMN],TABLE_NAME,COLUMN_NAME,…`) 거기서 읽는다. `NVL(TO_CHAR(DATA_LENGTH,''))`
처럼 감싸여 와도 함수 껍데기를 벗겨 컬럼명만 뽑는다. SELECT 목록에 컬럼이 하나 늘어도
이 도구를 고칠 필요가 없다.

## 외부 API 변경

**기존 엔드포인트의 동작은 그대로다.** 요청에 파라미터 하나가 늘고, 응답은 안 바뀐다.

| | |
| --- | --- |
| 추가 | `GET /api/v1/schemas/snapshots?leftEnv=&rightEnv=` — 환경별 스키마 날짜 목록 |
| 추가 | `GET /api/v1/schemas?leftEnv=&rightEnv=&left=&right=` — 좌우 스키마 대조 |
| 변경 | 소스 파라미터에 `schemaRoot`(String, 선택) 추가. 안 보내면 스키마 기능이 꺼진다 |
| 변경 | `?refresh=1` 이 스키마 캐시도 비운다 |

`SnapshotSource` 인터페이스에 `listFileNames(dir)` 이 하나 늘었다 — 스키마는 날짜가
폴더가 아니라 파일 이름에 있어 폴더를 한 번 읽어야 한다. 호출은 환경 폴더당 한 번이라
SSH 왕복이 늘지 않는다 (목록 `ls` 1회, 비교 `cat` 좌우 1회씩).

## 덧 — 실패를 알림으로 띄우고, 화면에서 바로 접는다

돌려 보니 두 군데가 걸렸다.

### 1. "스키마가 안 된다" — 실패가 안 보였다

못 읽은 줄이 생겨도 옵션 바에 `⚠ 못 읽은 줄 4` 한 줄이 전부였다. 목록을 보고 있으면
지나치고, 봤더라도 **무엇이 문제인지 알 수가 없었다** — 구분자가 틀린 것과 앞머리 태그가
다른 것이 화면에서 똑같이 "테이블 0개 · 못 읽은 줄 N" 으로 보이는데 고칠 곳은 서로 다르다.

세 가지를 넣었다.

- **파서가 못 읽은 줄의 원문을 들고 온다** (`SchemaSnapshot.malformedSample`, 앞 3줄).
  수만 알려 주면 원인을 가릴 수 없다.
- **원인을 짚는다** (`diagnoseMalformed`) — 설정한 구분자가 한 줄에도 안 보이는데 다른
  후보가 모든 줄에 보이면 그것을 지목하고, 앞머리가 아는 종류가 아니면 그 태그를 보여주고,
  앞머리 자체가 없으면 그렇게 말한다.
- **알림(토스트)** — `src/lib/toast.ts` + `features/toast/Toasts.tsx`. **오류는 저절로
  사라지지 않는다.** 잠깐 떴다 지나가면 못 본 것과 같다. 같은 내용은 겹쳐 뜨지 않는다.

실제로 쉼표 구분 덤프를 물려 보니 이렇게 뜬다.

```
⚠ 못 읽은 줄이 4개 있습니다
구분자가 안 맞습니다 — 설정은 '|' 인데 파일은 ',' 로 갈라져 있습니다.
change/config.ts 의 SCHEMA.separator 를 고치고 개발 서버를 다시 시작하세요.

파일에는 이렇게 적혀 있습니다:
  [COLUMN],TB_ORD,ORD_NO,VARCHAR2,20,,,N
```

### 2. 코드 비교에서 파일을 접을 방법이 사실상 없었다

`excludeFile` 은 있었지만 **팀이 함께 쓰는 규칙 파일**이다. 고치려면 파일을 열어 고치고
새로고침해야 하고, SSH 로 볼 때는 그 파일이 원격에 있어 손댈 수도 없다. 그런데 실제로
자주 필요한 건 "지금 이 파일은 안 볼래" 다 — 거기에 팀 규칙 파일을 고칠 수는 없다.

**내 제외 목록**을 따로 뒀다 (`features/settings/localExclude.ts`). 파일 목록 항목의
`⊘` 를 누르면 접히고, 이 브라우저에만 남는다. `⚙ 위치` 에 여러 줄을 적는 칸도 뒀다
(적용을 안 눌러도 바로 반영 — 목록의 버튼과 같은 목록을 고치기 때문이다).

판정 규칙은 `src/lib/excludeList.ts` 하나를 그대로 쓴다. 두 목록이 다른 문법을 가지면
어느 쪽에 무엇을 적었는지 기억해야 한다.

**서버는 안 건드렸다.** 응답을 받은 뒤 화면이 얹는다 — 팀 규칙은 서버 몫, 내 목록은
화면 몫으로 갈라 두면 서버에 상태가 늘지 않는다.

접기는 양쪽 다 **거르는 게 아니다.** 합쳐 세어 `제외 5 (내 2) · 변경 1` 로 알린다.

### 곁가지로 잡은 것

`SettingsPanel` 의 로컬 모드가 `schemaRoot` 를 안 들고 있었다. ⚙ 위치에서 값을 직접
고치면 스키마 폴더 설정이 조용히 날아갔다 — 칸을 만들면서 함께 고쳤다.

### 외부 API 변경

없다. 알림도 내 제외 목록도 전부 화면 쪽이다. 응답에 진단용 필드 둘이 늘었다
(`malformedSample` · `malformedHint`) — 기존 필드는 그대로다.

테스트 397개 통과 (스키마 진단 6 · 내 제외 목록 10 추가).

## 덧 3 — 컨트롤을 코드 비교와 한 자리로 모은다

스키마 화면이 **자기 날짜 피커를 따로 갖고 있었다.** 헤더의 환경·날짜 칸과 같은 일을
하는데 생김새가 살짝 달라 어색했고, 탭을 옮길 때마다 어느 쪽을 봐야 할지 헷갈렸다.

**헤더 컨트롤 하나가 두 모드를 다룬다.** 목록만 모드에 따라 갈아 끼운다.

```tsx
const picker = mode === 'schema'
  ? { left: schemaLoaded.left,  right: schemaLoaded.right,  selection: schemaSelection, ... }
  : { left: leftLoaded.items,   right: rightLoaded.items,   selection, ... }
```

**목록과 선택은 갈라 둔다.** 스키마 덤프는 배포와 주기가 달라 날짜가 코드와 다르고,
탭을 오갈 때 상대 쪽 선택이 흔들리면 "지금 무엇을 보고 있나" 가 무너진다. 실제로
코드에서 6월로 옮긴 뒤 스키마 탭에 갔다 와도 양쪽이 각자 값을 지키는 것을 확인했다.

스키마 탭을 **처음 열 때만** 코드에서 고른 날짜에 맞춰 준다 (`matchSchemaDate`).
그 뒤로는 고른 값이 그대로 남는다 — 코드 날짜를 의존성에 넣으면 코드를 만질 때마다
스키마 선택이 따라 흔들린다.

덕분에 **운영↔운영 · 테스트↔테스트**가 스키마에서도 그냥 된다. 같은 환경이면
`normalizeSelection` 의 "이후가 이전보다 최신" 규칙이 코드와 똑같이 걸린다 —
따로 만든 것이 없다. 예시로 운영 8월→9월을 보면 기본키 변경이 잡힌다.

밴드에서 날짜 피커를 걷어냈고(`SchemaBand` 가 요약과 종류 칩만 갖는다), 목록을 읽고
고르는 일은 App 으로 올렸다. SchemaPane 은 받은 날짜로 대조만 한다.

### 글자 크기도 같이 쓴다

옵션바의 글자 버튼을 `features/settings/FontSize.tsx` 로 빼서 두 화면이 나눠 쓴다.
크기는 "내 눈에 맞는 정도" 라 화면마다 따로 기억할 이유가 없고, 탭을 옮길 때마다
글자가 커졌다 작아지면 그게 더 거슬린다. 스키마 표도 `--code-size` 를 그대로 쓴다.

### 캡처를 하나 깨뜨렸다가 되돌렸다

`scripts/shot.html` 에 스키마 장면을 더하면서 모듈 최상위에 `return` 을 넣었다.
문법 오류라 스크립트가 통째로 안 돌았고, `npm run shots` 가 **일곱 장을 전부 같은
그림으로 덮어썼다** (박스도 번호도 없는 기본 화면). 바이트까지 같아서 바로 드러났다.

`git checkout` 으로 되돌리고 `if/else` 로 고쳐 다시 뽑았다. 설명서 7장에
`08-schema.png` 를 더했다.

## 덧 4 — `NN` 을 `NOT NULL` 로 편다

컬럼 타입 뒤에 `NN` 이라고만 찍고 있었다. **읽는 사람이 한 번 더 해독해야 하는 글자**라,
이 화면을 처음 보면 그게 무슨 뜻인지 물어봐야 한다. 실제로 물어보는 일이 생겼다.

셋을 함께 고쳤다.

1. **줄임말을 편다** — `NN` → `NOT NULL`. 아낀 두 글자보다 "이게 뭐지" 를 없애는 쪽이 낫다.
2. **값과 자리를 가른다** — `SchemaCell.note` 를 새로 뒀다. 예전에는 타입 문자열에 이어
   붙여(`VARCHAR2(20) NN`) 한 덩어리로 읽혔는데, 그러면 타입이 바뀐 것인지 널 여부가
   바뀐 것인지 눈으로 가르기 어렵다. 이제 회색 칩으로 떼어 그린다.
3. **왜 중요한지 툴팁으로** — "널(빈 값)을 넣을 수 없는 컬럼입니다. 이 표시가 붙거나
   풀린 것도 변경으로 잡습니다."

`note` 는 **좌우 비교에 값과 똑같이 들어간다** (`sameCell`). NOT NULL 이 붙거나 풀린 것은
엄연한 변경이고, 예시 폴더의 `TB_PAY.APRV_NO` 가 바로 그 경우다.

널 허용에는 아무것도 안 적는다. 그쪽이 보통이라 둘 다 적으면 화면의 절반이 늘 같은
글자로 차고, 정작 눈에 띄어야 할 NOT NULL 이 묻힌다.
