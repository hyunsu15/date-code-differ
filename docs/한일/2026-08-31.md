# 2026-08-31 — 독립 실행 서버(`server/main.ts`) · 라우팅을 vite 에서 떼어내기

## 왜

화면에 이렇게 떴다.

```
불러오지 못했습니다. Unexpected token '<', "<!doctype "... is not valid JSON
```

**SSH 오류가 아니었다.** `/api/v1/*` 요청이 API 에 닿지 못하고 SPA fallback 으로 빠져
`index.html` 이 **200 OK** 로 돌아왔고, [client.ts](../../src/api/client.ts) 의
`return (await res.json())` 이 거기서 죽은 것이다. `!res.ok` 분기를 안 탔다는 게
200 이라는 증거였다 — 그 분기는 이미 `.catch(() => null)` 로 감싸여 있다.

원인은 구조다. API 가 **vite 플러그인**이라 `vite dev` / `vite preview` 안에서만 산다.
`dist` 만 정적 서버에 올리면 API 가 통째로 없고, 하위 경로에 배포하면
클라이언트가 쓰는 루트 절대 경로 `/api/v1` 이 엉뚱한 곳을 가리킨다.

함정이 하나 더 있었다. 매칭되지 않는 `/api/v1/*` 경로는 `next()` 로 흘러 화면 파일이 된다.

```
GET /api/v1/nope  →  200 OK, text/html, "<!doctype html>"
```

오타 하나가 SSH 오류처럼 보이는 구조였다.

## 무엇을 했나

### 1. 라우팅을 `server/api.ts` 로 뺐다 — vite 를 모르는 파일

`codeRepositoryPlugin.ts` 안에 `createHandler` 가 갇혀 있어 vite 밖에서 쓸 수 없었다.
그대로 `export` 만 붙이면 독립 서버가 **"플러그인"이라는 이름의 파일**에서 핸들러를
가져오게 된다. 그래서 옮겼다.

```
api.ts                    라우팅 (vite 를 모른다)
  ├─ codeRepositoryPlugin.ts   vite 어댑터   (212줄 → 40줄)
  └─ main.ts                   독립 실행 어댑터
```

핸들러 타입도 `Connect.NextHandleFunction`(vite) 대신 `ApiHandler` 를 직접 정의했다.
모양은 같아서 `server.middlewares.use()` 에 그대로 꽂힌다.

라우팅 로직은 **한 줄도 바꾸지 않았다** — 옮기기만 했다.
`test/sshCommands.test.ts` 의 import 경로 한 줄이 따라 움직였다.

### 2. `server/main.ts` — 한 포트에서 화면과 API 를 함께

`node:http` 위에 얹었다. 같은 출처라 클라이언트의 `/api/v1` 이 그대로 맞고
CORS 도 프록시 설정도 필요 없다 — **`client.ts` 는 손대지 않았다.**

- `/api/v1` 로 시작하면 접두사를 떼고 핸들러에 넘긴다 (connect 가 하던 일)
- **미매칭 API 경로는 JSON 404 로 끝낸다.** 위의 함정을 여기서 막는다
- 그 외는 정적 파일, 확장자 없는 경로만 `index.html` 로 떨어진다
- `assets/` 아래는 이름에 내용 해시가 붙어 있어 `immutable` 로 오래 캐시하고,
  `index.html` 은 `no-cache` — 그 해시를 가리키는 지도라서 캐시하면 배포해도 옛 화면이 남는다
- 경로 탈출은 `normalize` 후 **결과가 STATIC_DIR 안인지 다시 확인**한다.
  `%5C`(역슬래시)처럼 OS 마다 다르게 해석되는 입력이 있어 normalize 만 믿지 않는다

환경 변수는 `PORT`(8080) · `HOST`(0.0.0.0) · `STATIC_DIR`(`../dist`) 셋.

`../dist` 기본값은 두 배치에서 모두 맞는다 — 저장소에서 바로 실행하든
(`server/main.ts` → `dist/`) 번들을 배포하든 (`backend/main.mjs` → `dist/`) 같은 자리다.

> ⚠ **이 API 에는 인증이 없다.** 대상 폴더를 읽고 ssh 를 실행한다.
> 사내망 안이나 리버스 프록시 뒤에 둔다. 같은 장비에 nginx 를 세운다면
> `HOST=127.0.0.1` 로 바깥 노출을 막는다.

### 3. `scripts/build-server.mjs` — 서버를 단일 파일로

esbuild 로 `server/main.ts` 를 `backend_next/main.mjs` 하나로 묶는다 (**59 KB**).

번들로 낸 이유는 배포 산출물을 하나로 줄이기 위해서다. 소스를 그대로 옮기면
`server/`, `src/lib/`, `src/types.ts`, `change/config.ts`, `node_modules/diff`,
`package.json`(`type: module`)을 빠짐없이 복사해야 하고 그 목록을 계속 관리해야 한다.

런타임 npm 의존은 **`diff` 하나뿐**이라 통째로 인라인된다
(`prismjs` 는 `src/lib/highlight.ts` 에만 있고 화면 전용이라 안 딸려온다).

`.mjs` 로 내는 이유: 옆에 `package.json` 이 없어도 Node 가 ESM 으로 읽는다.
`target: node20` — 운영 서버 Node 가 최신이 아니어도 돌게 했다
(`import.meta.dirname` 이 들어온 20.11 이 밑줄).

`npm run build` 가 화면과 서버를 함께 만든다. `npm start` 도 추가했다 —
Node 22.18+ 는 `.ts` 를 그대로 실행하므로 빌드 없이 독립 서버를 띄워 볼 수 있다.

### 4. `update.sh` · `rollback.sh` 의 `backend` 스왑을 켰다

두 스크립트에 주석 처리된 채 남아 있던 줄을 풀었다. 오류 문구는 이미 `backend_next`
를 언급하고 있었다 — 원래 이 그림이었던 것으로 보인다.

```
backend_next → backend,  dist_next → dist   (이전 버전은 *_prev 에 보존)
```

## 확인한 것

번들(`backend_next/main.mjs`)을 `STATIC_DIR=dist_next` 로 띄워 실측했다.

| 요청 | 결과 |
| ---- | ---- |
| `GET /` | 200 `text/html`, `Cache-Control: no-cache` |
| `GET /assets/index-*.js` | 200 `text/javascript`, `max-age=31536000, immutable` |
| `GET /api/v1/snapshots?mode=local&root=./sample-code` | 200 JSON (스냅샷 4개) |
| `GET /api/v1/snapshots?mode=ssh&host=없는호스트` | 502 JSON `SSH_UNREACHABLE` |
| **`GET /api/v1/nope`** | **404 JSON `NOT_FOUND`** (고치기 전: 200 HTML) |
| `POST /api/v1/snapshots` | 404 JSON `NOT_FOUND` |
| `GET /assets/nope.js` | 404 |
| `GET /some/route` | 200 `index.html` (SPA 경로) |
| `/%2e%2e%2fpackage.json` · `/..%5Cpackage.json` · `/assets/../../package.json` | 전부 404 — 탈출 못 함 |

- `npm start` (소스 `.ts` 직접 실행) 동작 확인 — Node v24.18.0
- `npm run dev` API 정상 — 플러그인 리팩터가 개발 서버를 깨지 않았다
- `update.sh` → `rollback.sh` 를 임시 폴더에서 왕복 실행, `backend`·`dist` 둘 다 스왑·복원 확인
- `npm test` 200개 통과, `npm run typecheck` 통과

## 외부 API 변경

- **응답 스키마·상태 코드·오류 코드 전부 그대로.** 라우팅 코드는 옮기기만 했다
- 독립 서버에서만: 없는 `/api/v1/*` 경로가 **HTML 200 → JSON 404 (`NOT_FOUND`)** 로 바뀐다.
  vite 개발 서버는 여전히 `next()` 로 흘려 HTML 을 준다 (그쪽 미들웨어 체인은 vite 것이다)
- `server/api.ts` 가 새 진입점 — `readSourceConfig` 를 여기서 가져온다
  (`codeRepositoryPlugin.ts` 에서 옮겨 왔다)
- `package.json`: `build` 가 서버 번들까지 만든다 · `start` 추가 · `esbuild` devDependency 추가

  (화면 번들도 프리셋을 갖고 있어 어차피 함께 빌드된다)
