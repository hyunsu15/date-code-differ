# 2026-10-23 — 날짜 고르기: 변경된 날짜만 · 날짜마다 변경 수

## 왜

날짜 폴더는 배포가 없던 날에도 쌓여서, 날짜 목록을 다 보면 어느 날 실제로 바뀌었는지 헷갈린다는 지적.
요청: 변경된 날짜만 보기(기본) / 전체 보기, 기본 내림차순 + 오름차순, 고르는 단계에서 날짜와 변경 개수를 알 수 있게.

## 무엇을 했나

- **서버** `GET /api/v1/snapshots/changes` (`server/snapshotChanges.ts`) — 날짜마다 **바로 앞 날짜 대비** 추가·삭제·변경 파일 수.
  - 배포 없던 날(앞 날짜와 똑같은 폴더) = 0. 가장 오래된 날짜는 `base: null`.
  - SSH 는 목록을 만들 때 이미 받은 체크섬으로 가른다 — 추가 접속 없음. 로컬은 크기가 같은 파일만 본문을 읽어 견준다.
  - 파일 단위·바이트 기준(무시 옵션 미적용). 팀 제외 목록은 적용 — 늘 바뀌는 임시 파일로 모든 날짜가 "변경" 이 되지 않게.
  - 날짜 쌍마다 캐시, ⟳ 새로고침이 비운다. 날짜 목록과 **따로** 물어 날짜 칸이 늦게 뜨지 않게 했다.
- **화면** 날짜 칸의 브라우저 `datalist` 를 직접 그린 목록으로 바꿨다 (토글·두 줄 표시가 datalist 로는 안 된다).
  - 위: `변경된 날짜만 | 전체`, `최신순 | 오래된순` — 처음은 변경된 날짜만 · 최신순, localStorage `cd-date-list` 에 남는다.
  - 줄: `2026-08-01  11개 바뀜` / `추가 7 · 삭제 1 · 변경 3 · 07-15 대비`. 숨긴 게 있으면 "변경 없는 날짜 N개 숨김 · 전체 보기".
  - 지금 고른 날짜는 변경이 없어도 목록에 남긴다. 숨긴 날짜도 직접 치면 찾아진다(`0815`). ↓↑ · Enter · Esc.
  - 세는 동안·실패 시에는 거르지 않고 전체를 보여주며 그 사실을 적는다. 스키마 탭은 세지 않는다(순서만).
- 하다가 고친 것: 토글을 연달아 누르면 앞의 변경이 묵은 값으로 덮이던 것(최신 값에 얹도록), 오른쪽 칸에서 "08-15 대비"
  대신 긴 날짜가 나오던 것(짧은 이름을 날짜 이름에서 바로 뽑도록).
- 확인: 예시 폴더 복사본에 배포 없던 날 2개(08-15 · 07-15)를 만들어 — API 가 0 을 내고, 목록이 기본으로 숨기고, 전체·오래된순·
  타이핑·마우스·키보드 선택이 맞게 동작. 스키마 탭은 순서 토글만.
- 테스트: `snapshotChanges.test.ts`(순수 견주기 · 제외 · 실제 로컬 폴더로 0 과 같은 크기 다른 내용) 6건, `dateList.test.ts` 13건.
- 사용설명서 2장(새 절 + 10-dates 스크린샷), API.md(1-1 절 · 캐시 표), README 갱신.

# 2026-10-23 — "변경된 날짜만" 은 바뀐 날짜만, 검색은 따로 전체에서

- 사용자 요청: 변경된 날짜만일 때는 "N개 바뀜" 인 것만, "변경 없음" 은 필요 없음. 전체일 때 다. 검색은 독립적으로 전체에서.
- "변경된 날짜만" 에서 **지금 고른 날짜라도 바뀐 날짜가 아니면 뺀다**(예전엔 남겼다). **가장 오래된 날짜("처음 날짜")도 뺀다** —
  "바뀜" 표시가 아니므로. 둘 다 "전체" 나 검색으로 고를 수 있다. 숨긴 수는 "바뀐 게 없는 날짜 N개 숨김 (변경 없음 · 처음 날짜)".
- 검색은 원래도 거르기와 상관없이 전체에서 찾았지만 화면에 드러나지 않았다 — 찾는 동안 토글 자리에 `전체 날짜에서 검색 · N개`.
- 확인(배포 없던 날 2개를 넣은 복사본): 변경된 날짜만 = 08-01 · 07-01 두 줄, 전체 = 다섯 줄, "07" 검색 = 숨긴 07-15 까지 두 줄.

# 2026-10-23 — "변경된 파일만 / 테이블만" 체크박스를 목록 끝 접힘 줄로

## 왜

바뀐 것을 위로 올리는 정렬이 생기면서 체크박스는 "아래쪽 동일한 것들을 보일지" 만 정하게 됐다. 사용자와 상의:
체크박스를 없애고 늘 다 펼치면 실제 규모(수백~수천 파일)에서 검색·`[` `]` 이동·렌더가 흐려지므로,
**목록 안에서 접기**로 바꾸기로 했다 — 화면의 다른 접기("제외 N" · "동일한 N줄 접힘" · 날짜 "N개 숨김")와 같은 방식.

## 무엇을 했나

- `SameFold`(features/files) — 목록 맨 아래 `▾ 동일한 파일 N개 — 펼치기` / `▴ … 접기`. 스키마는 "테이블".
  코드 파일 목록(`FileList`)과 스키마 테이블 목록(`TableList`)이 같이 쓴다.
- `lib/changedFirst.ts` 에 `splitSame`(두 묶음) · `shownItems`(지금 보이는 것) 추가. 고른 항목 맞추기 · `[` `]` 이동은 보이는 것만 따른다.
- **검색은 접기와 상관없이 전체에서** — 검색 중에는 바뀐 것 중 맞는 것 아래에 `동일한 파일 중 N개` 와 그 항목들. 검색어를 지우면 다시 접힌다.
- 날짜·환경을 바꾸면 다시 접힌다. 파일을 고를 때는 그대로(접히면 고른 파일이 사라진다).
- 목록 머리 "파일 N개" → "바뀐 파일 N개"(검색 중 "찾은 바뀐 파일"). 체크박스 두 개 제거.
- 확인(운영 08-01 → 09-01): 코드 = 바뀐 9 + 접힘 8, 펼치기/접기, "ord" 검색 = 바뀐 1 + 동일 중 3, 지우면 접힘, 날짜 변경 시 다시 접힘.
  스키마 = 바뀐 4 + 접힘 3, "CUST" 검색 = 바뀐 TB_ORD(컬럼 이름으로) + 동일 중 TB_CUST.
- 테스트 2건 추가 (전체 505개 통과). 사용설명서 3·4·7장, README, 스크린샷 갱신.

# 2026-10-23 — 날짜 고르기를 "변경 이력"(이전·이후 한 쌍씩)으로

## 왜

"뭔가 이상하다" 는 지적. 비교는 이전·이후 **쌍**인데 목록 숫자는 날짜 **하나**(그 날짜 vs 바로 앞 날짜)에 붙어 있어,
목록에서 본 숫자와 고른 뒤 결과가 어긋났다. 칸마다 따로 거르니 스키마처럼 이전 칸이 텅 비는 일도 있었고,
처음 기본값(최신 · 그 바로 앞 날짜)이 배포 없던 날끼리면 빈 비교가 떴다. 사용자와 기획을 맞춘 뒤 만들었다.

## 무엇을 했나

- 목록 위 탭 **[변경 이력 | 날짜 직접]** (같은 환경일 때). 기본은 변경 이력 · 최신순.
  - 변경 이력: 바뀐 일 하나 = `이전 → 이후` 한 줄(`파일 9개 바뀜` / `추가 2 · 삭제 3 · 변경 4`). 누르면 두 칸이 **함께** 정해진다.
    줄의 숫자가 그대로 화면 결과다. 지금 비교와 같은 줄에 `지금 보는 비교`.
  - 쌍의 앞쪽은 **그 내용이 처음 생긴 배포일** — 배포 없던 날은 따로 줄이 생기지 않는다(`dateList.changeHistory`).
  - 날짜 직접: 이 칸만 고른다. 배포일에만 점과 흐린 `이날 파일 N개`(그날 들어온 변경 — 고른 뒤 차이로 읽히지 않게).
- 환경이 다르면 이력이 성립하지 않아 날짜 직접만 + 맨 위 `운영 최신 ↔ 테스트 최신` 빠른 선택. 각 칸에 자기 환경 배포일 표시.
- 처음 열 때(같은 환경, 코드 탭) **가장 최근 변경**으로 맞춘다(앞 배포일 → 최신). 사람이 날짜를 고른 뒤에는 손대지 않는다.
- 없앤 것: "변경된 날짜만 / 전체" 토글(두 탭이 대신), "변경 없음" · "처음 날짜" 줄, "N개 숨김" 줄. 예전 저장값은 뜻이 같은 탭으로 옮긴다.
- 그대로: 최신순·오래된순, 칸에 직접 쳐서 검색(이 칸의 전체 날짜), ↓↑ Enter Esc. 서버 API 는 그대로 썼다.
- 확인(배포 없던 날 3개를 넣은 복사본): 처음 = `08-01 → 09-05`(예전 기본값이면 09-01 → 09-05 빈 비교) 바뀐 파일 9개,
  이력 3줄, 둘째 줄 누르면 07-01 → 08-01 · 바뀐 파일 11개(줄 숫자와 같음), 날짜 직접 배포일 표시, 운영 ↔ 테스트 빠른 선택,
  스키마 `08-01 → 09-01 · 테이블 4개 바뀜`(예전처럼 이전 칸이 비지 않는다).
- 테스트: 날짜 목록 테스트를 새 모델로 다시 씀 (전체 503개 통과). 사용설명서 2장 · README · 10-dates 갱신.
- 2차로 미룸: 이력 두 줄을 Shift+클릭해 여러 변경을 묶어 보기(날짜 직접으로 대신 가능).
