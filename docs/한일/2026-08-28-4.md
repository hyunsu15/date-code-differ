# 2026-08-28 (4) — ssh 오류에 실행한 명령 붙이기 · 붙여넣기 가능한 명령 · `~` 루트 버그

## 왜

SSH 가 실패하면 화면에 "인증에 실패했습니다" 같은 문장만 떴다.
**무슨 명령이 실패했는지가 없었다.** 원격 명령은 이 도구가 조립하므로
(`ls -1F --`, `find ... -exec wc -c {} +`, `if test -d ...`), 화면만 봐서는
ssh 문제인지 · 계정 문제인지 · 우리가 만든 명령이 그 서버에서 안 먹는 건지 가릴 수 없었다.

명령을 붙이기 시작하니 **그 명령이 붙여넣어지지 않는다**는 문제가 곧바로 드러났고,
그걸 파다가 `~` 루트에서 파일 목록이 통째로 비는 버그까지 나왔다.

## 무엇을 했나

### 1. 모든 `SSH_*` 오류에 실행한 명령을 붙인다

`formatSshCommand(args)` 를 `sshCommands.ts` 에 추가했다. argv 를 한 줄로 만든다.

```
인증에 실패했습니다.
...

실행한 명령:
ssh -o ConnectTimeout=10 -o StrictHostKeyChecking=yes deploy@build-01 "ls -1F -- ~/'release'"
```

옵션·`user@host` 처럼 안전한 인자는 따옴표 없이 두고, 공백이 든 원격 명령만 감싼다.
비밀번호는 애초에 argv 에 싣지 않으므로 이 문자열로 새어 나갈 것이 없다.

### 2. `"$HOME"` 을 걷어냈다 — 붙여넣으면 깨지는 명령이었다

`~/release` 를 `"$HOME"/'release'` 로 바꿔 왔다. 큰따옴표 안이면 어느 셸에서나
확장된다는 이유였는데, **표시할 때 역슬래시 escape 가 생긴다**(`\"\$HOME\"`).

윈도우 PowerShell 에 붙여넣으면 이렇게 된다 (실측):

```
붙여넣은 것 : ssh ... "ls -1F -- \"\$HOME\"/'release'"
실제로 넘어간 것 : ls -1F -- " \C:\Users\KOSCOM\/'release'
```

PowerShell 은 역슬래시를 escape 로 보지 않고 `$HOME` 을 자기가 먼저 푼다.
따옴표가 깨진 채 원격으로 넘어가 원격 셸이 `unexpected EOF while looking for matching '"'` 로 죽는다.

**고침.** 뒤쪽만 인용한 `~/'release'` 로 둔다. POSIX 는 틸드 접두사가 인용되지 않은 채
첫 `/` 앞에 있으면 확장한다고 정해 두었고, sh·bash·dash 에서 확장을 확인했다.
큰따옴표도 `$` 도 없으니 표시용 명령에 escape 가 아예 생기지 않는다 —
bash 와 PowerShell 양쪽에서 그대로 통과한다(실측).

테스트로 못 박았다: 어떤 루트 모양이든 표시용 명령에 역슬래시·`$` 가 없어야 한다.

### 3. `~` 로 시작하는 루트에서 파일 목록이 통째로 비던 버그

**증상.** 접속도 되고 날짜 폴더도 보이는데 **파일만 0개**. 오류도 안 난다.

**원인.** `find` 에 절대 경로를 넘기면 그 경로를 그대로 앞에 붙여 출력한다.
루트가 `~/release` 면 원격 셸이 틸드를 확장하므로 돌아오는 경로는
`/home/deploy/release/...` 인데, `parseFileSizes` 는 우리가 아는 문자열
`~/release/...` 로 시작하는 줄만 인정했다. 전부 걸러졌다.

**고침.** 폴더로 먼저 들어가서 `find .` 을 돌린다. 출력이 `./상대/경로` 로 오므로
원격이 틸드를 무엇으로 확장했는지 **몰라도 된다.**

```
cd ~/'release/2026-08-01' 2>/dev/null && find . -type f -exec wc -c {} + 2>/dev/null || true
```

`parseFileSizes(stdout)` 는 이제 스냅샷 경로 인자를 받지 않는다 (`./` 로 시작하는 줄만 인정).

### 4. `SSH_TIMEOUT` 코드 신설

문서(`docs/API.md`)에는 있었는데 코드에 없었다. 시간 초과는 stderr 가 비어 있어
`error.message` 를 쓰게 되는데, 거기엔 argv 가 통째로 들어 있어 **명령이 두 번 찍혔다.**
따로 문장을 만들고 "개발 서버 터미널에서 비밀번호를 기다리는 중일 수 있다"를 덧붙였다 —
`BatchMode` 를 켜지 않으므로 이게 가장 흔한 원인이다.

### 5. 화면에서 줄바꿈이 접히던 자리

파일 읽기 실패 안내(`.empty p`)에 `white-space` 가 없어 여러 줄 메시지가 한 줄로 붙었다.
`.error-detail` 클래스를 붙여 그대로 보여준다. 상단 배너(`.banner`)는 이미 `pre-wrap` 이었다.

### 6. 존재 확인용 명령을 통째로 없앴다 (`test -d`, `SnapshotSource.exists()`)

```
처음 : if test -d ~/'release'; then echo __OK__; else echo __NO__; fi
다음 : test -d ~/'release'
지금 : (없음)
```

`/snapshots` 요청마다 목록을 읽기 **전에** 한 번 더 붙어서 루트가 있는지 물었다.
목적은 "폴더 없음(404)"과 "그 밖의 실패(502)"를 갈라 안내하는 것.

그럴 필요가 없었다. **ssh 는 원격 명령의 종료 코드를 그대로 돌려주고 자기 실패는 255 로
알린다**(ssh(1)). 그래서 날짜 목록을 읽는 `ls` **하나로** 둘이 갈린다 —
`ls` 가 실패하면(원격 코드) 루트를 못 읽은 것이고, 255 면 접속 문제다.

- `SnapshotSource` 에서 `exists()` 를 뺐다 (로컬·SSH 양쪽)
- `listSnapshotDirs()` 가 루트를 못 읽으면 `ROOT_NOT_FOUND` 를 던진다.
  로컬은 `ENOENT`/`ENOTDIR` 을, SSH 는 "원격 명령이 낸 종료 코드"를 근거로 삼는다
- 플러그인은 `ROOT_NOT_FOUND` 만 404 로, 나머지 `SourceError` 는 502 로 보낸다
- **`/snapshots` 요청마다 ssh 접속이 한 번 줄었다** (접속을 재사용하지 않으므로
  비밀번호를 묻는 서버라면 프롬프트도 한 번 준다)

실측 — 종료 코드로 정말 갈리는지 확인했다.

| 상황 | 결과 |
| ---- | ---- |
| 로컬: 있는 폴더 | `["2026-08-01"]` |
| 로컬: 없는 경로 | `ROOT_NOT_FOUND` (404) |
| 로컬: 폴더가 아닌 파일 | `ROOT_NOT_FOUND` (404) |
| SSH: 없는 호스트 (실제 ssh, exit 255) | `SSH_UNREACHABLE` (502) |

## 확인한 것

원격 셸이 명령 문자열을 해석하는 상황을 `sh -c` 로 재현해 루트 모양별로 돌렸다.

| 루트 | 존재 확인 | 날짜 목록 | 파일 목록 |
| ---- | -------- | -------- | -------- |
| `/home/deploy/release` (절대) | OK | OK | OK |
| `~/release` (내 홈) | OK | OK | **고치기 전 0개 → 이제 OK** |
| `release` (상대, 접속 시 홈 기준) | OK | OK | OK |
| `/data/스냅샷 모음` (공백·한글) | OK | OK | OK |
| `~deploy/release` (다른 계정 홈) | 그 계정이 있는 서버에서만 확장된다 |

붙여넣기는 bash 와 PowerShell 양쪽에 실제로 넣어 argv 를 찍어 확인했다 — 네 명령 모두 그대로 통과.

복합 구문(`&&` · `||` · `2>/dev/null`)은 원격에서 정상 해석된다.
ssh 는 마지막 인자를 원격 **로그인 셸**에 통째로 넘기므로 복합 구문이 그대로 해석된다.
다만 로그인 셸이 csh/tcsh 면 이 구문도, `2>/dev/null` 도 안 먹는다 — POSIX 셸 전제다.

## 외부 API 변경

- 응답 스키마는 그대로 (`{ code, message }`)
- `SSH_*` 오류의 `message` 끝에 `실행한 명령:` 두 줄이 추가된다
- `SSH_TIMEOUT` 코드가 실제로 나가기 시작한다 (문서엔 이미 있었다)
- `ROOT_NOT_FOUND`(404) 는 그대로지만, 이제 별도 확인 명령이 아니라 날짜 목록 조회에서 나온다
