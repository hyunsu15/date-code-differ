# 2026-09-01 — 무시 옵션이 실제로 먹게 고치고, 처음부터 켜 둔다

## 왜

네 가지가 한 덩어리로 묶여 있었다. 전부 **"보고 싶은 것만 남는가"** 라는 한 가지 질문이다.

1. **주석 무시가 여러 줄 주석에 안 먹었다.** 판정이 줄 하나만 보고 있어서 파일 머리말이
   통째로 살아남았다. 정작 Pro*C 소스에서 제일 흔한 주석 모양이 그것이다.
2. **작성자 줄** 때문에 로직이 같은 파일이 "바뀐 파일" 로 올라왔다.
3. **무시 옵션이 전부 꺼진 채로** 열려, 열 때마다 네 개를 손으로 켜야 했다.
4. **새로고침을 누르면 화면이 비었다.** 무시 체크박스를 아무거나 눌러야 다시 채워졌다.

## 무엇을 했나

### 1. 새로고침 뒤에 비교가 다시 돈다 (`5bd910a`)

비교 effect 가 목록의 **출처**(`leftLoaded.source`)만 보고 있었다. 새로고침은 위치도
날짜도 그대로 둔 채 목록만 다시 읽는 일이라 그 값이 안 바뀐다. effect 가 다시 돌지
않으니 `loadSnapshots` 가 비워 둔 비교 결과가 빈 채로 남았고, 체크박스를 눌러
`options` 가 바뀌어야 그제야 비교가 돌았다 — "체크박스를 눌러야 새로고침이 먹는다" 는
증상의 정체다.

목록 **객체**를 통째로 의존성에 뒀다. 목록을 새로 넣는 곳은 `loadSnapshots` 뿐이고
거기서 매번 새 객체를 만들므로, 넓혀도 비교가 더 자주 돌지는 않는다.

### 2. 여러 줄 주석을 통째로 무시한다 (`ec7b5b6`)

`isDroppedLine` 은 줄 하나를 정규식으로 봤다. 그래서 아래 세 줄 중 어느 것도 주석으로
잡히지 않았다 — 여는 줄과 닫는 줄은 별이 여러 개라 패턴에서 벗어나고, 가운데 줄은
그 자체로는 그냥 글자다.

```c
/*****
 주석값
 *****/
```

파일을 위에서부터 훑으며 "지금 블록 주석 안인지" 를 들고 가는 `markDroppedLines` 로
바꿨다. 문자열 리터럴 안(`strcpy(buf, "/*")`)은 주석으로 보지 않는다.

**덤으로 더 큰 것을 하나 잡았다.** 주석 기호 목록에 `#` 이 들어 있어서, 주석 무시를
켜면 `#include` · `#define` 이 **통째로 비교에서 빠지고 있었다.** 대상 언어(Pro*C ·
PL/SQL)에서 `#` 은 전처리기 지시자이지 주석이 아니다. `;` 도 문장 끝이라 함께 뺐다.
`--` 는 남기되 뒤에 영숫자가 바로 붙으면(`--i;`) 감소 연산자로 본다.

> 실제로 예시 폴더의 `ord_common.h` 는 `#define ERR_ISIN_LMT` 한 줄이 추가된 파일인데,
> 고치기 전에는 주석 무시를 켜면 그 변경이 사라져 "같은 파일" 로 보였다 (아래 결과 참고).

### 3. 작성자 표기 줄을 빼는 옵션 (`f123f3f`)

`작성자 : 홍길동` · `작 성 자 :` · `수정자` · `변경자` · `@author` 를 비교에서 뺀다.
뒤에 `:` 를 요구해 코드에 우연히 들어간 낱말과 가른다.

주석 무시와 **따로** 뒀다. 주석을 켜면 머리말 안의 작성자 줄도 어차피 빠지지만,
주석은 보면서 이름 줄만 빼고 싶은 경우가 있다.

### 4. 무시 옵션을 켠 채로 열고 브라우저에 남긴다 (`f0d8736`)

공백 · 빈 줄 · 주석 · 작성자를 켠 채로 연다. 대소문자만 꺼 둔다 — C·PL/SQL 에서
`Total` 과 `total` 은 서로 다른 이름이라 켜면 진짜 차이를 덮는다.

`cd-ignore` 로 localStorage 에 남는다. 옵션은 앞으로도 늘 수 있어(이번에 `ignoreAuthor`
가 그랬다) **항목마다 따로** 검증하고, 없거나 망가진 항목만 기본값으로 채운다 —
옵션 하나가 이상하다고 나머지 선택까지 날리지 않는다.

### 5. 처음 열면 좌우가 운영 ↔ 테스트 (`8f6788c`)

저장된 선택이 없으면 양쪽 다 `DEFAULT_ENV_ID` 였다. 이 도구를 여는 이유가 대개
"지금 운영과 테스트가 얼마나 벌어져 있나" 인데, 그걸 보려면 열 때마다 한쪽을 손으로
바꿔야 했다. 왼쪽은 `DEFAULT_ENV_ID`, 오른쪽은 목록에서 그다음 환경으로 연다.

예전 저장값(환경 id 문자열 하나)은 그대로 양쪽 다 그 환경으로 읽되, **아는 id 일
때만** 그렇게 본다 — 망가진 값이 첫 항목으로 떨어지면서 "양쪽 다 운영" 이라는
멀쩡해 보이는 선택으로 둔갑하고 있었다.

## 뒤이어 — 대표 주석으로 다시 훑었다

"다른 주석도 이상한 데 없는지 봐 달라, `#if`/`#fi` 도 주석 아니냐" 는 요청으로 한 번 더 봤다.

### 6. 주석 42가지 · 작성자 19가지로 훑어 구멍 다섯 개 (`4331827`)

머릿속으로 맞다고 넘기지 않고 **실제로 돌려 봤다.** 표를 만들어 기대값과 맞춰 보니
다섯 개가 어긋났다.

- **주석 1건** — 줄 끝 역슬래시(`// 주석 \`)로 다음 줄까지 주석이 이어지는 C 규칙.
  컴파일러가 두 줄을 한 주석으로 읽으므로 여기서도 그렇게 읽는다.
- **작성자 4건** — `/*==== 작성자 : 홍길동 ====*` 처럼 상자 테두리가 앞에 붙은 줄,
  그리고 `최종수정자` · `최종 수정자` · `최초작성자` 처럼 수식어가 붙은 줄.

이미 맞던 것도 테스트로 고정했다: 한 줄 주석 안의 `/*` 가 블록을 열지 않는 것,
블록 주석이 겹치지 않고 첫 닫힘에서 끝나는 것, 문자열 안의 주석 기호, 안 닫힌 블록.

`작성일` 은 일부러 그대로 뒀다 — 날짜는 이름과 달리 읽을 값이다.

### 7. `#if 0` — 주석은 아니지만 죽은 코드다 (`ignoreDeadCode`)

`#if` / `#endif` 는 주석이 아니라 **조건부 컴파일**이다 (`#fi` 는 C 에 없는 문법이고,
셸의 `if … fi` 와 헷갈리기 쉽다). `#ifdef DEBUG` 안의 코드는 빌드 옵션에 따라 실제로
돌기 때문에 주석 취급하면 `#include` 때와 똑같은 사고가 난다.

다만 **`#if 0`** 은 다르다. 블록 주석이 겹쳐지지 않아 여러 줄을 한꺼번에 죽일 때 쓰는
관용구고, 어떤 빌드에서도 안 돈다. 그래서 옵션을 따로 하나 두고 기본으로 켰다.

- `#if 0` · `#if FALSE` · `#if (0)` — `#if` 안에서 정의되지 않은 이름은 0 으로 치므로
  `FALSE` 는 정의돼 있든 없든 거짓이다.
- PL/SQL 의 `$IF FALSE $THEN` … `$END` 도 같은 규칙으로 본다.
- 안에서 다시 열린 `#if` 는 세어서 **짝이 맞는 `#endif`** 까지 뺀다.
- `#else` · `#elif` 가지는 살아 있으므로 거기서 멈춘다.
- 주석·문자열 안에 적힌 `#if 0` 에는 속지 않는다 (판정을 **주석을 걷어낸 줄**로 한다).
- `#ifdef NEVER` 처럼 이름으로만 죽여 둔 것은 빼지 않는다 — 정의 여부를 알 길이 없다.

죽은 코드 17가지로 확인했다. 헤더 가드(`#ifndef ORD_H`)가 안 빠지는지도 함께 봤다.

## 남겨 둔 것

- **코드 뒤에 붙은 주석은 함께 비교한다.** `x = 1; /* 설명 */` 에서 설명만 바뀌면 그 줄은
  변경으로 잡힌다. "주석 전용 줄" 만 빼는 것이 기존 범위라 그대로 뒀다 — 비교 키에서
  주석을 떼어내면 눈에 보이게 다른 두 줄이 "같음" 으로 표시돼 오히려 헷갈린다.
- `--DROP TABLE` 처럼 `--` 뒤에 영문이 바로 붙은 SQL 주석은 감소 연산자와 구분할 수 없어
  주석으로 보지 않는다. 못 지운 주석이 한 줄 더 보이는 쪽이, 코드 한 줄이 조용히
  사라지는 쪽보다 낫다.
