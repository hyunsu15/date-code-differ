# 2026-08-31 — 운영/테스트/개발을 **이름 접두사**가 아니라 **하위 폴더**로

## 왜

화면 위 `[전체][운영][테스트][개발]` 이 실제 서버에서 아무 일도 하지 않았다.

기능이 고장난 게 아니라 **가정이 틀렸다.** 8-28 에 넣은 것은 한 폴더에 스냅샷이
이름으로 섞여 쌓이는 경우(`prod_20260801` · `test_20260801`)를 전제로, 폴더명이
접두사로 시작하는지 보고 거르는 필터였다.

실제 배치는 이렇게 **폴더로 나뉘어** 있다.

```
/home/deploy/release/
├─ prod/  20260801/  20260901/
├─ test/  20260801/
└─ dev/   20260901/
```

여기서 `prod` 로 거르면 걸리는 폴더 이름이 `prod` 하나뿐이라 — 그것도 날짜 폴더가
아니라 환경 폴더다 — 비교할 날짜가 나올 수가 없다. 원하는 동작은 거르기가 아니라
**루트를 `release/prod` 로 내려가는 것**이었다.

## 무엇을 했나

### 1. 거르기를 버리고 "루트에 이어 붙이기" 로 바꿨다

핵심은 이 한 줄이다. 고른 환경의 `path` 를 프리셋의 `root` 뒤에 붙이고,
그 결과를 **그 요청의 위치로 그냥 쓴다.**

```ts
// src/features/settings/envFolder.ts
export function withEnv(source: SourceConfig, path: string): SourceConfig {
  if (!path.trim()) return source
  return { ...source, root: joinRoot(source.root, path) }
}
```

덕분에 **서버에는 환경이라는 개념이 없다.**

| | 전 (접두사) | 후 (환경 폴더) |
| --- | --- | --- |
| 거르는 곳 | 서버 `listSnapshots(…, prefix)` | 없음 — 루트가 이미 그 환경이다 |
| 요청 | `&root=…/release&prefix=prod` | `&root=…/release/prod` |
| 비교·파일 API | 접두사를 모른다 (루트는 공용) | 같은 루트로 물어본다 |
| 캐시 키 | 접두사와 무관 | `root` 가 키에 있어 환경별로 저절로 갈린다 |

세 번째 줄이 원래 조용한 결함이었다. 목록만 접두사로 좁히고 비교는 공용 루트로
물어보던 구조라, 이번 방식은 그 갈림 자체를 없앤다.

### 2. `source` 를 `useMemo` 로 붙잡았다

`withEnv` 가 새 객체를 만들기 때문에 그냥 계산하면 렌더마다 다른 값이 되고,
목록을 다시 읽는 `useEffect` 와 "목록이 이 위치의 것인가" 를 보는 비교 `useEffect` 가
둘 다 이 값을 의존성으로 쓰고 있어 **무한 재요청**이 된다.

```ts
const source = useMemo(
  () => withEnv(sourceSelection.source, envPath(envId)),
  [sourceSelection.source, envId]
)
```

환경을 안 고른 경우 `withEnv` 가 **받은 객체를 그대로** 돌려주는 것도 같은 이유다.

### 3. 경로 잇기 규칙

```ts
joinRoot('/home/deploy/release/', '/prod/')  // → '/home/deploy/release/prod'
joinRoot('~/release', 'prod')                // → '~/release/prod'
joinRoot('D:\\release', 'prod')              // → 'D:\\release/prod'
joinRoot('/srv/release', 'rel/qa')           // → '/srv/release/rel/qa'
```

- 구분자는 `/` 로 낸다. 원격은 POSIX 뿐이고, 로컬은 서버가 `path.resolve` 로 다시 푼다
- 앞은 건드리지 않는다 — `~` 를 정규화하면 원격 셸이 확장할 기회를 뺏는다
  (`quoteRemotePath` 가 틸드를 따옴표 밖에 두는 것과 같은 이유)

### 4. 이름을 바꿨다 — 하는 일이 달라졌으므로

| 전 | 후 |
| --- | --- |
| `FOLDER_PREFIXES` / `DEFAULT_PREFIX_ID` | `ENV_FOLDERS` / `DEFAULT_ENV_ID` |
| `FolderPrefix.prefix` | `EnvFolder.path` |
| `ALL_PREFIXES_ID = 'all'` (전체 보기) | 없음 — 항상 환경 하나가 골라져 있다 |
| `src/features/settings/folderPrefix.ts` | `src/features/settings/envFolder.ts` |
| localStorage `cd-prefix` | `cd-env` |
| 서버 `matchesPrefix`, `prefix` 쿼리 | 삭제 |

### 5. 첫 항목(**전체** → **루트**)을 다시 없앴다

처음엔 **루트**(내려가지 않음)를 목록 맨 앞에 남겨 뒀다. 날짜 폴더가 루트에 바로 있는
배치(예시 폴더 `sample-code`)를 위해서였는데, **기본값이 그것이라 첫 화면이 깨졌다.**

```
[루트][운영][테스트][개발]   [이전  prod ▾] → [이후  test ▾]
                                     ↑ 날짜가 아니라 환경 폴더가 올라온다
```

환경 폴더를 쓰는 배치에서 루트를 읽으면 `listSnapshotDirs` 가 `prod` `test` `dev` 를
돌려주고, 그게 그대로 날짜 칸을 채운다. 날짜로 읽히지도 않아 `sortKey` 는 빈 문자열이다.

그래서 **선택지에서 뺐다.** `ENV_FOLDERS` 에 하나라도 적혀 있으면 항상 그중 하나가
골라져 있고, 루트를 그대로 읽고 싶으면 **배열을 비운다** — 그러면 고르는 자리도 사라진다.
같은 뜻을 두 가지로 표현할 수 있게 두면 하나는 반드시 함정이 된다.

`ROOT_ENV_ID` · `ROOT_ENV` 는 지웠고, 없는 id 는 **첫 항목**으로 떨어진다
(예전 저장값 `'root'` 도 여기로 흡수된다).

### 6. 예시 폴더(`sample-code`)를 같은 배치로 바꿨다

템플릿에 `prod` 를 적어 두면 예시 폴더가 안 열리고, 안 적어 두면 이 기능이 예시에서
아예 안 보인다. **예시 폴더를 실제 배치와 같게 만드는 쪽**을 골랐다.

```
sample-code/
├─ prod/   2026-06-01/  2026-07-01/  2026-08-01/  2026-09-01/    ← 있던 4개를 그대로 옮겼다
└─ test/   2026-08-01/  2026-09-01/                              ← 새로 만든 것 (ord 패키지만)
```

`test` 를 `prod` 의 복사본으로 두면 환경을 바꿔도 화면이 그대로라 **뭘 확인하는지 알 수 없다.**
그래서 테스트 쪽 `2026-09-01` 에는 운영에 아직 안 올라간 변경을 하나 심었다 —
`chk_isin_limit()` (종목별 주문 한도)과 `ERR_ISIN_LMT`. 같은 날짜 조합이 환경에 따라
다르게 나온다.

| 환경 | `2026-08-01 → 2026-09-01` |
| --- | --- |
| 운영 | 패키지 5개 · 파일 17개 (cmm 삭제 · rpt 신규 · ord/pay 변경 · stl 동일) |
| 테스트 | 패키지 1개 · 파일 4개, `ord_create.pc` 에 한도 검증 한 덩어리가 더 붙는다 |

곁다리로 `test/comparison.test.ts` 의 fixture 루트가 `./sample-code` → `./sample-code/prod`
한 줄 따라 움직였다. 날짜 폴더 이름은 그대로라 그 아래 단언은 손대지 않았다.

템플릿(`config.example.ts`)에는 `prod` · `test` 를 넣고 `dev` 는 주석으로 뒀다
(예시 폴더에 `dev` 가 없으므로 — 버튼만 있고 폴더가 없으면 눌렀을 때 404 다).
`change/config.ts` 는 실제 서버에 맞춰 운영·테스트·개발 셋을 두고 `DEFAULT_ENV_ID = 'prod'`.

> 그래서 **`change/config.ts` 로 예시 폴더를 볼 때 `개발` 버튼은 404 다** — 예시에 `dev` 가 없다.
> 예시로 셋 다 눌러 보고 싶으면 `sample-code/dev` 를 만들거나, 그 항목을 빼면 된다.

- 브라우저 실측 (`npm run dev`)

  - SSH 프리셋에서도 그대로 — 오류에 붙는 **실제 실행 명령**으로 확인했다.
    `withEnv` 가 `mode` 를 보지 않고 `root` 만 바꾸므로 로컬/원격이 갈리지 않는다

    | 고른 환경 | 원격에서 실행된 명령 |
    | --- | --- |
    | 운영 | `ls -1F -- '/home/deploy/release/prod'` |
    | 테스트 | `ls -1F -- '/home/deploy/release/test'` |
    | 개발 | `ls -1F -- '/home/deploy/release/dev'` |
    | 운영 (`~/release` 루트) | `ls -1F -- ~/'release/prod'` — 틸드는 따옴표 밖에 남는다 |

    **운영** → 이전 `20260801` · 이후 `20260901` (날짜다) + diff 정상,
    **테스트** → `…/test` 로 200, 날짜는 그대로 나오고 "변경된 패키지 없음",
    **개발** → 날짜가 1개라 안내 문구가 어느 환경인지 함께 알려준다
  - 새로고침 후 선택 유지 (`cd-env`)
  - 예시 폴더(`내 PC 폴더` 프리셋)로 **운영 ↔ 테스트** 전환 —
    운영은 패키지 5개·파일 17개, 테스트는 `ord` 하나·파일 4개로 실제로 달라진다

## 외부 API 변경

  (환경은 `root` 에 이미 붙어서 온다). 응답 형태·상태 코드·오류 코드는 그대로
- 비교 API 2개는 손대지 않았다

## 남은 것 — 다른 PC 의 `change/config.ts`

`config.ts` 는 커밋되지 않으므로, 이미 돌고 있는 곳의 파일에는 아직 `FOLDER_PREFIXES` 가 있다.
그 상태로 받으면:

- `npm run dev` / `build` 는 **돈다.** 환경 고르는 자리만 화면에서 사라진다
  (설정을 `import * as` 로 읽어 없으면 기능만 끄기 때문). 시작할 때 안내가 한 줄 뜬다
- `npm run typecheck` 는 **깨진다** — `FolderPrefix` 타입이 더 이상 없다

고치는 법 — `change/config.example.ts` 의 `ENV_FOLDERS` 블록을 복사해 옛 블록과 바꾸고,
`import type` 줄의 `FolderPrefix` 를 `EnvFolder` 로 고친다. 템플릿의 배열은 **비어 있으니**
(예시가 주석으로 들어 있다) 그 서버의 실제 환경 폴더 이름으로 채워 넣어야 한다.

```ts
export const ENV_FOLDERS: EnvFolder[] = [
  { id: 'prod', label: '운영', path: 'prod' },   // ← 실제 폴더 이름으로
]
export const DEFAULT_ENV_ID = 'prod'
```

날짜 폴더가 루트에 바로 있는 서버라면 배열을 비운 채로 두면 된다.
