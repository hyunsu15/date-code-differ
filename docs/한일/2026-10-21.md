# 2026-10-21 — 환경을 좌우 한꺼번에 바꾼다

## 왜

환경(운영/테스트)은 좌우가 각각 고른다. 운영↔테스트 비교에는 그게 맞지만,
"운영 8/1→9/1 을 봤으니 테스트 8/1→9/1 도 보자" 처럼 **같은 비교를 환경만 바꿔** 반복할 때는
두 번 골라야 하고, 그 사이 한 번은 원치 않는 운영↔테스트 비교가 불려 온다.

## 무엇을 했나

- 헤더 날짜 칸 옆에 **🔗 환경 묶기** 토글을 넣었다. 켜는 순간 오른쪽이 왼쪽 환경으로 맞춰지고,
  켜져 있는 동안은 어느 쪽에서 골라도 양쪽이 함께 간다. 코드·스키마 탭이 같은 컨트롤이라 둘 다 적용된다.
- 판정은 `envFolder.ts` 의 `pickEnv` · `linkEnvPair` 순수 함수로 두고 테스트를 붙였다.
  켠 상태는 `cd-env-linked` 로 localStorage 에 남는다 (기본은 꺼짐 — 처음 열면 여전히 운영↔테스트).
- 아이콘은 동기 스크롤 토글과 같은 🔗 — 이 화면에서 "좌우가 함께 움직인다" 는 뜻으로 맞췄다.
- 환경이 하나 이하로 설정돼 있으면 버튼을 그리지 않는다.
- 사용설명서 2번에 사용법을 더하고 스크린샷을 다시 찍었다 (03-picker 에 ⑤ 추가).
  촬영 스크립트가 앞 장면의 묶기 값을 물려받지 않도록 `cd-env-linked` 를 매번 지운다.

## 외부 API 변경

없음. 환경은 원래 루트 경로에 붙어 나가는 값이라 서버 요청 모양이 그대로다.

# 2026-10-21 — 비교 결과를 공지용 md 보고서로 내려받는다

## 왜

비교 결과를 사내에 공지하려면 화면을 캡처하거나 숫자를 손으로 옮겨 적어야 했다.
옮기다 틀린 숫자가 공지로 나가면 바로잡기 어렵다.

## 무엇을 했나

- 헤더에 **⬇ 보고서** 버튼을 넣었다. 맨 위 표(환경 · 종류 · 변경 건수 · 날짜)와 바뀐 파일·테이블 목록만 담는다.
  사용자와 템플릿을 먼저 맞춘 뒤 서론·목적·비교 기준·링크는 빼고 간단하게 정했다.
- 숫자는 화면과 같은 기준이다 — 제외 목록·내 목록·스키마 종류 토글로 접은 것은 빼고 센다.
  예시 폴더로 확인: 소스 12건(화면 "변경 12"), 스키마 3건(밴드 "3/7").
- 스키마는 탭을 열 때만 읽어서, 누를 때 화면과 같은 순서(목록 → 날짜 맞추기 → 대조 → 접기)로 읽는다.
  실패하면 소스만 담아 받고 "스키마는 보고서에서 빠졌습니다" 알림을 띄운다 — 모르고 공지하면 "스키마 변경 없음" 으로 읽힌다.
- 소스 본문은 넣지 않는다. UTF-8 BOM 을 붙여 메모장에서 한글이 깨지지 않게 했다.
- 버튼이 늘어 1024px 에서 헤더가 두 줄이 됐다 — 1100px 이하에서는 앱 이름 글자를 접어 한 줄로 맞췄다.
- 테스트: `report.test.ts`(표 내용·정렬·생략·이스케이프·파일 이름), `schemaForReport.test.ts`(날짜 맞추기·환경 바뀐 뒤 바로잡기·접기·실패 전달, `fetch` 만 대체).
- 사용설명서 8장 신설(이후 장 번호 한 칸씩 밀림), 스크린샷 09-report 추가, README 갱신.

## 외부 API 변경

없음. 기존 `GET /api/v1/schemas/snapshots` · `GET /api/v1/schemas` 를 그대로 부르고, 파일은 브라우저에서 만든다.

# 2026-10-21 — 보고서의 스키마 날짜를 소스 날짜에 가장 가깝게 맞춘다

## 왜

"보고서 스키마 날짜가 없으면 무작위로 고르는 것 같다" 는 지적. 예시 폴더(스키마 덤프 8/1 · 9/1)로 재현했다.

- 운영 6/1 → 7/1 소스 보고서에 **스키마 8/1 → 9/1** 이 실렸다. 7월 비교에 9월 변경이 섞인 것.
  날짜 맞추기가 "그 날짜 이하" 만 봐서 이하가 없으면 맨 끝(8/1)으로 튀었고, 두 날짜가 같은 덤프가 되자
  화면 컨트롤의 순서 규칙(오른쪽이 더 최신)이 오른쪽을 9/1 로 밀어냈다.
- 스키마 탭에서 한 번 고른 날짜가 있으면, 그 뒤 소스 날짜를 바꿔도 보고서가 옛 스키마 날짜를 그대로 썼다.

## 무엇을 했나

- `matchSchemaDate` 를 **날 수로 가장 가까운 덤프**(앞이든 뒤든, 같으면 앞의 것)로 바꿨다. 키를 숫자로 빼면
  달이 바뀔 때 틀려서(0801 − 0730 = 71) 날짜로 바꿔 잰다. 스키마 탭 첫 진입도 같은 함수라 같이 바뀐다.
- 보고서는 스키마 탭에서 고른 날짜를 쓰지 않고 **늘 소스 날짜에 맞춘다.** 순서 규칙도 걸지 않는다.
- 같은 환경에서 두 날짜가 같은 덤프로 맞춰지면 견주지 않고 `—` + "두 날짜 사이에 덤프가 없어 비교하지 않았습니다" 를 적는다.
- 덤프 날짜가 소스와 다르면 표 아래에 "2026-07-01 대신 2026-07-03" 처럼 적는다.
- 확인: 운영 6/1 → 7/1 로 받으면 스키마 줄이 `— | 2026-08-01` 과 사유로 나온다 (예전: 8/1 → 9/1 의 3건).
- 테스트: 날짜 맞추기 6건, 보고서 주석 4건, 스키마 읽기 4건으로 갈아 끼웠다 (전체 449개 통과).
