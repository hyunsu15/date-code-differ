## ssh-login 과 ssh 자체 비밀번호 처리의 충돌 해결

`npm run ssh-login` 으로 넣은 비밀번호와, ssh 가 스스로 묻는 것들이 서로 부딪히는 문제를 잡았다.
네 갈래였다.

### 1. askpass 가 **모든 질문**에 비밀번호를 답하고 있었다 (핵심)

`SSH_ASKPASS_REQUIRE=force` 는 비밀번호뿐 아니라 ssh 의 **모든 프롬프트**를 askpass 로 보낸다.
그런데 `askpass.mjs` 는 무엇을 묻는지 보지 않고 항상 비밀번호를 내놓았다.

처음 접속하는 서버에서 이렇게 된다.

```
Are you sure you want to continue connecting (yes/no/[fingerprint])?   ← ssh 의 질문
secret123                                                              ← askpass 의 답
→ "yes" 가 아니므로 Host key verification failed
```

비밀번호를 넣었는데도 접속이 안 되고, 화면 오류만으로는 원인을 알 수 없다.

**실측으로 확인한 것** — ssh 는 물어볼 문구를 askpass 의 **첫 인자**로 넘긴다
(`["Enter passphrase: "]`). 즉 문구를 보고 판단할 수는 있었다.

**그런데 문구를 넘겨받지 않기로 했다.** 두 가지 이유다.

- 문구에는 **원격 서버가 보낸 글자**가 섞일 수 있다 (keyboard-interactive).
- Windows 는 `.cmd` 래퍼를 거치는데, `%*` 로 넘기면 **cmd.exe 가 그 문구를 다시 해석**한다.
  악의적인 서버가 보낸 문구가 명령으로 실행될 수 있는 통로가 된다.
  (실제로 여러 줄 문구는 cmd.exe 를 통과하면서 잘려 나가기도 했다)

**대신 비밀번호가 아닌 질문을 ssh 단계에서 없앴다** — `StrictHostKeyChecking=yes`.
호스트 키가 없으면 **묻지 않고** 바로 실패한다. 원래도 자동 수락은 하지 않았으니
정책은 그대로고, "묻지 않는다" 만 확실해졌다. 안내 문구는 예전처럼
`known_hosts` 에 등록하라고 알려준다.

askpass 는 더 단순해졌다 — 인자를 받지 않고, 보관 중인 비밀번호가 없으면
**빈 답 대신 실패**한다 (빈 문자열을 내보내면 ssh 가 빈 비밀번호로 인증을 시도한다).

### 2. ssh-login 이 화면과 다른 서버에 비밀번호를 넣고 있었다

`ssh-login` 은 `change/config.ts` 의 SSH 프리셋만 봤다. 하지만 화면은
**직접 입력** 값을 쓸 수도 있고, SSH 프리셋이 여러 개면 `--target` 없이는 아예 멈췄다.
그래서 비밀번호를 넣어도 화면에는 "비밀번호가 없습니다" 가 계속 떴다 — 키가 어긋나서다.

개발 서버가 **비밀번호를 기다리는 대상**을 기억하게 했다.

```
GET /api/v1/ssh-credentials  →  { "pending": "deploy@build-01:2222", "registered": [...] }
```

대상만 담는다. 비밀번호 값은 어떤 경로로도 나가지 않는다.
`ssh-login` 의 대상 결정 순서는 `--target` → **pending** → config 프리셋이고,
어디서 정해졌는지 화면에 찍는다.

```
[code-diff] 접속 대상: deploy@build-01:2222  (화면이 기다리는 접속)
```

### 3. 키 인증 대상에 비밀번호를 넣어도 아무 말이 없었다

기본 프리셋은 `auth: 'key'` 다. 이 상태로 `ssh-login` 을 실행하면 비밀번호는 저장되지만
ssh 는 `BatchMode=yes` 로 키 인증만 해서 **영원히 쓰이지 않는다.**
이제는 받지 않고 멈추면서, 무엇을 바꿔야 하는지(`auth: 'password'` 또는 ⚙ 위치) 알려준다.
단 화면이 이미 비밀번호를 기다리는 중이면 이 검사를 건너뛴다 — 그때는 화면 설정이 비밀번호 인증이다.

### 4. `--target user@host` (포트 생략) 이 400 으로 거부됐다

포트를 생략하면 22 로 채워 보관 키와 같은 형태로 맞춘다.
`normalizeConnectionTarget` 하나를 서버와 CLI 가 함께 쓴다 — 형태가 갈리면 또 어긋난다.

### 고친 파일

| 파일 | 한 일 |
| ---- | ----- |
| `scripts/askpass.mjs` | 인자를 받지 않는다. 비밀번호가 없으면 빈 답 대신 실패 |
| `scripts/askpass.cmd` · `.sh` | 문구를 넘기지 않는 이유를 주석으로 명시 |
| `server/source/sshCommands.ts` | `StrictHostKeyChecking=yes` (묻지 않는다) |
| `server/source/passwordStore.ts` | `normalizeConnectionTarget`, 기다리는 대상(pending) |
| `server/source/sshSource.ts` | 비밀번호가 없거나 틀리면 그 대상을 pending 으로 남긴다 |
| `server/codeRepositoryPlugin.ts` | `GET /ssh-credentials`, target 정규화 |
| `scripts/ssh-login.mjs` | 대상 결정 순서, 키 인증 보호, 출처 표시 |

### 검증

- 타입 검사 통과, 테스트 **215개 전부 통과**. 새로 21개 추가.
  - `askpass.test.ts` — 자식 프로세스로 실제 계약(표준출력·종료코드) 확인. 래퍼가 인자를 넘기지 않는 것도 단정.
  - `sshLogin.test.ts` — 가짜 개발 서버를 띄우고 스크립트를 실제로 실행해, **어느 대상으로 POST 하는지** 확인.
  - `passwordStore.test.ts` — 대상 정규화·pending.
- 실제 OpenSSH 로 확인: `SSH_ASKPASS` + `.cmd` 래퍼로 암호화된 키의 패스프레이즈를 받아가는 것을
  Windows OpenSSH(`C:\Windows\System32\OpenSSH\ssh-keygen.exe`)에서 직접 돌려봤다.
- 개발 서버로 전 과정 확인: 화면 요청(비밀번호 인증) → `pending` 기록 → `ssh-login` 이
  **대상 지정 없이** 그 서버를 잡음 → 등록 후 재요청이 비밀번호 단계를 통과.

### 외부 API 변경 여부

**기존 엔드포인트의 동작은 그대로다.** 아래 하나가 늘었다.

```
GET /api/v1/ssh-credentials  →  { pending, registered }
```

`npm run ssh-login` 전용이고 **대상만** 알려준다. 비밀번호 값은 나가지 않는다.
`POST /api/v1/ssh-credentials` 는 `target` 의 포트 생략을 **허용**하도록 넓어졌다 (전에는 400).
스펙은 [API.md](../API.md) 참고.
