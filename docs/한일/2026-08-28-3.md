# 2026-08-28 (3) — SSH 비밀번호 흐름 전부 걷어내고 순수 ssh 로

## 왜

SSH 접속이 원인을 알기 어려운 방식으로 실패했다.
직접 만든 비밀번호 전달 장치(`npm run ssh-login` → 서버 메모리 → `SSH_ASKPASS`)가
붙어 있어서, 실패했을 때 **ssh 문제인지 우리 장치 문제인지 가려낼 수가 없었다.**

장치 자체도 값을 치렀다.

- askpass 는 묻는 문구를 보지 않고 비밀번호를 답한다 — 비밀번호가 아닌 질문이 하나라도
  뜨면 거기에 비밀번호가 답으로 들어가 엉뚱한 실패가 된다. 그걸 막으려고 ssh 옵션·플랫폼별
  래퍼 스크립트·대상 추적(`pending`)까지 딸려 왔다
- 화면이 보는 대상과 `ssh-login` 이 넣는 대상이 어긋나면 "넣었는데도 비밀번호가 없습니다"

전부 **비밀번호를 대신 넣어 주려다** 생긴 것이다. 그래서 그 층을 통째로 걷어냈다.
지금은 `execFile('ssh', ...)` 로 OpenSSH 를 그대로 돌리고, 인증은 ssh 에 맡긴다 —
개인키 · ssh-agent · `~/.ssh/config`.

판단 기준이 하나로 줄었다. **터미널에서 `ssh 계정@서버` 로 되는 것이 화면에서도 된다.**

## 무엇을 지웠나

| 지운 것 | 하던 일 |
| ------- | ------- |
| `scripts/ssh-login.mjs` | 터미널에서 비밀번호를 받아 개발 서버로 보냈다 |
| `scripts/askpass.mjs` · `.cmd` · `.sh` | ssh 가 물으면 대신 답했다 (`SSH_ASKPASS`) |
| `server/source/passwordStore.ts` | 비밀번호·대기 대상을 프로세스 메모리에 들고 있었다 |
| `POST`/`GET /api/v1/ssh-credentials` | 위 둘을 잇던 엔드포인트 |
| `SshSourceConfig.auth` · `SshAuthMode` | 인증 방식 선택 (`key`/`password`) |
| ⚙ 위치의 **인증 방식** 토글 | 화면에서 고르던 자리 |
| 배너의 "비밀번호를 넣었습니다 · 다시 시도" | 비밀번호 재시도 버튼 |
| `server/http.ts` 의 `readJsonBody` | 쓰는 곳이 POST 하나뿐이었다 |
| `npm run ssh-login` | package.json 스크립트 |

테스트도 함께 지웠다 — `askpass.test.ts` · `passwordStore.test.ts` · `sshLogin.test.ts`.

## 무엇이 남았나

`sshOptions` 가 분기 없이 둘로 고정된다.

```
-o ConnectTimeout=10
-o StrictHostKeyChecking=yes  ← 호스트 키 자동 수락 안 함
[-p 포트] [-i 개인키]
```

## 이어서 — `BatchMode` 도 뺐다

처음엔 `BatchMode=yes` 를 조건 없이 걸었다. 프롬프트가 뜨면 요청이 멈추니까.
그런데 그러면 **비밀번호로만 열리는 서버에 들어갈 길이 아예 없어진다** — 공개키를 등록할 수
없는 서버가 있으면 도구를 못 쓴다. 그래서 뺐다.

지금은 키로 안 붙으면 ssh 가 직접 물어본다. 묻는 자리는 화면이 아니라
**`npm run dev` 를 띄운 터미널 창**이다 (OpenSSH 는 비밀번호를 stdin 이 아니라 콘솔에서 읽는다).

### 대가 — 명령마다 묻는다

접속을 재사용하지 않는다. 원격 명령마다 `ssh` 를 새로 띄운다.

| 동작 | ssh 접속 수 | 날짜 30개·파일 200개면 |
| ---- | ---------- | ---------------------- |
| 날짜 목록 로딩 | 2 + 날짜 폴더 수 | 32번 |
| 좌우 비교 | 파일 수 × 2 | 400번 |
| 파일 하나 열기 | 2 | 2번 |

`listSnapshots` 가 폴더마다 `find` 를 한 번씩 돌리고(`snapshotRepository.ts`),
`compareSnapshots` 가 파일마다 좌우를 `cat` 한다(`comparisonService.ts`). 캐시가 있어
두 번째부터는 줄지만 개발 서버를 재시작하면 원점이다.

키를 등록해 두면 이 횟수는 아무 의미가 없다 — 묻지 않으니까. 그래서 문서마다
`ssh-copy-id` 를 권하되, **막지는 않는다.**

### `SSH_TIMEOUT` 을 새로 만든 이유

프롬프트를 아무도 받아주지 않으면 `COMMAND_TIMEOUT_MS`(30초) 뒤에 `execFile` 이 자식을 죽인다.
이때 stderr 가 비어 있어서 그냥 두면 "원격 명령이 실패했습니다" 로 뭉뚱그려진다 — **원인을
찾을 수 없는 실패**다. 터미널 창이 안 보이는 환경(IDE 내장 실행·백그라운드)에서는 이 경로로만
떨어지므로, `error.killed` 를 보고 "터미널 창을 확인하세요" 라고 짚어 준다.

### 검토했다가 버린 것 — `ControlMaster`

터미널에서 한 번만 로그인하고 소켓을 재사용하면 32번이 1번이 된다. 비밀번호 서버에 딱 맞는
해법인데, **Windows 기본 OpenSSH 가 다중화를 지원하지 않는다.** 이 PC 에서 직접 확인했다.

```
ControlMaster 있음 → getsockname failed: Not a socket   ← DNS 조회도 못 감
ControlMaster 없음 → Could not resolve hostname ...     ← 정상적인 실패
```

(OpenSSH_for_Windows_9.5p2)

인증 실패(`SSH_AUTH_FAILED`)는 무엇을 해야 하는지까지 적어 준다 —
`ssh 계정@서버` 로 먼저 확인하고, 매번 묻는 게 번거로우면 `ssh-copy-id` 로 등록하라고.

## 외부 API 변경

**있다.** 브라우저는 이 중 어느 것도 쓰지 않았으므로 화면 동작에는 영향이 없다.

| 변경 | 내용 |
| ---- | ---- |
| 삭제 | `POST /api/v1/ssh-credentials` — 유일한 POST 였다. 이제 API 는 **GET 뿐** |
| 삭제 | `GET /api/v1/ssh-credentials` |
| 삭제 | 위치 파라미터 `auth` (남아 있어도 무시된다) |
| 삭제 | `GET /snapshots` 의 `forgetPassword` 플래그 |
| 삭제 | 오류 코드 `SSH_PASSWORD_REQUIRED` · `SSH_PASSWORD_REJECTED` |
| 추가 | 오류 코드 `SSH_TIMEOUT` — 30초 초과 (대개 프롬프트를 아무도 안 받은 경우) |
| 의미 변경 | `SSH_AUTH_FAILED` — "키 인증 실패" → 인증 실패 전반 |

localStorage 에 `auth` 가 남아 있던 브라우저도 그냥 무시하고 읽는다 (설정으로 올라오지 않는다).

## 대가

**비밀번호로 접속하면 명령마다 묻는다** (위 표). 매번 치기 싫으면 `ssh-copy-id` 로 공개키를
등록해야 한다 — 문서는 그렇게 권하지만 강제하지 않는다.

접속이 실패할 때 원인이 ssh 하나로 좁혀진다는 건 그대로다. 직접 만든 층이 없으니
터미널에서 재현되는 것이 전부다.
