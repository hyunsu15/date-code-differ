# 2026-10-22 — 보고서의 스키마 변경을 항목별 문장으로 적는다

## 왜

보고서 스키마 절이 `수정 | TB_ORD | 컬럼 1 · 인덱스 1` 꼴이라 애매하다는 지적.
"수정" 이 테이블 상태(양쪽에 다 있음)인지 안의 항목인지, 인덱스가 생긴 건지 없어진 건지 보고서만으로 알 수 없었다.

## 무엇을 했나

- 바뀐 항목마다 한 줄씩 `테이블 | 구분 | 이름 | 내용` 으로 적는다 (`features/report/schemaChanges.ts`).
  기호(+ − ~) 대신 짧은 문장 — 사용자 요청. 예: `타입 변경: NUMBER(15,2) → NUMBER(18,2)`, `추가: 비유니크 (ORD_STAT, ORD_DT)`, `NOT NULL 설정`.
- 말은 비교 방향에 맞춘다. 같은 환경은 추가·삭제·변경, 다른 환경은 `테스트에만 있음` · `타입 다름: 운영 … · 테스트 …` —
  환경 간에는 어느 쪽이 맞는 상태인지 도구가 모르므로 "추가" 라고 단정하지 않는다.
- 통째로 생기거나 없어진 테이블은 한 줄 + 개수만, 기본키 줄은 `⚠ 기본키` 를 앞에 단다.
- 예시 폴더로 확인: 운영 8/1 → 9/1 은 11줄(테이블 4개), 운영 → 테스트 9/1 은 5줄로 나온다.
- 테스트: `schemaChanges.test.ts` 11건(실제 덤프 모양을 파서·대조에 태워 확인), 보고서 표 연결 1건 갈아 끼움. 전체 460개 통과.
- 사용설명서 8장 예시와 문장 규칙 표 갱신.

# 2026-10-22 — 스키마 화면도 무엇이 어떻게 바뀌었는지 말로 보여준다

## 왜

보고서를 문장으로 바꾼 뒤, 화면도 바로 인지되지 않는다는 지적. 줄 앞 `+ ~ −` 는 뜻을 알아야 읽혔고 `~` 가 타입인지
NOT NULL 인지 알 수 없었다. 없는 쪽의 `—` 는 "없음" 으로 읽히지 않았고, 목록의 `●●● 7줄 +2 −1 ~1 +1 ~1` 은
어느 종류의 숫자인지, `변경` 배지는 테이블 상태인지 안의 항목인지 헷갈렸다.

## 무엇을 했나

- 말 만드는 곳을 `features/schema/schemaWording.ts` 하나로 모았다(보고서용 `report/schemaChanges.ts` 를 옮김).
  화면 칩·목록·섹션 머리와 보고서 문장이 같은 말을 쓴다.
- 줄 앞 칩: `추가` · `삭제` · `타입 변경` · `NOT NULL 설정/해제` · `종류·컬럼 변경`. 환경이 다르면 `테스트에만` · `운영에만` · `타입 다름`.
- 없는 쪽은 `없음` + 툴팁(`운영 2026-08-01에 없음`).
- 목록: 둘째 줄을 `컬럼 4 · 제약 1 · 인덱스 2` 로. 배지는 테이블이 통째로 한쪽에만 있을 때만(`테이블 추가` / `테스트에만`).
- 섹션 머리 `+2 −1 ~1` → `추가 2 · 삭제 1 · 변경 1` (환경이 다르면 `테스트에만 2 · 다름 1`).
- 이 변경으로 안 쓰이게 된 `schemaView.changedRows` 와 점·숫자 CSS 를 지웠다.
- 확인: 운영 8/1 → 9/1, 운영 → 테스트 9/1 두 화면, 라이트 테마, 880px 좁은 화면.
- 테스트: 칩·목록·섹션 머리 7건 추가 (전체 467개 통과). 사용설명서 7-1 · README 화면 표 갱신, 08-schema 다시 찍음.

# 2026-10-22 — 스키마 말을 추가 · 삭제 · 변경 하나로 맞추고 색 범례를 둔다

## 왜

"`테스트에만` 이 애매하다 — 테스트에만 있고 삭제됐다는 거냐" 는 지적과, `에만` 표현이 어색하다는 의견.
원인: 줄 색(초록 추가 · 빨강 삭제 · 주황 변경)이 이미 왼쪽 → 오른쪽 방향의 뜻을 갖고 있는데, 환경이 다를 때만
말을 `운영에만` · `다름` 으로 바꿔서 빨간 줄에 `운영에만` 이 붙었다. 색과 말이 서로 다른 방식으로 같은 사실을
말해 "운영에만 있고 + 삭제됨" 두 가지로 읽혔다. 어제 "환경 간엔 추가라고 단정하지 않는다" 며 넣은 것을 되돌린다.

## 무엇을 했나

- 말은 **추가 · 삭제 · 변경** 셋뿐, 환경이 같든 다르든 왼쪽 → 오른쪽으로 읽는다 (`schemaWording.ts` 에서 환경 분기 제거).
  `타입 변경` · `NOT NULL 설정/해제` · `종류·컬럼 변경` · `테이블 추가/삭제` 도 같은 규칙.
- **색 · 말 범례**를 표 이름 줄 오른쪽에 둔다 — 지금 고른 이름으로 푼다:
  `추가 — 테스트에는 있고 운영에는 없음` · `삭제 — 운영에는 있고 테스트에는 없음` · `변경 — 양쪽에 다 있지만 값이 다름`.
  같은 환경이면 날짜로(`2026-09-01에는 있고 2026-08-01에는 없음`). 툴팁: 환경 간엔 어느 쪽이 맞는지 판단하지 않는다.
- 보고서 스키마 절 머리에 같은 범례를 한 줄(`> 추가: … · 삭제: … · 변경: …`)로 넣었다.
- 좁은 화면에서 범례가 테이블 이름을 잘라 먹던 것 → 이름은 줄이지 않고 범례가 다음 줄로 내려가게.
- 확인: 운영 → 테스트(빨간 줄 = `삭제` = "운영에는 있고 테스트에는 없음" 이 한 가지로 읽힘), 운영 8/1 → 9/1, 1024px, 라이트 테마.
- 테스트: 문구 테스트를 새 말로 다시 쓰고 범례 4건 · "에만/다름 이 다시 나오지 않음" · 보고서 범례 줄 추가 (전체 476개 통과).
- 사용설명서 7장(색·말 표, ⑦ 범례) · 8장 예시, README, 08-schema 스크린샷 갱신.

# 2026-10-22 — 코드 비교에서 펼친 구간을 다시 접는다

## 왜

"변경만" 보기에서 `동일한 N줄 접힘` 을 누르면 펼쳐지기만 하고 다시 접을 방법이 없었다 (사용자 지적).
한 번 편 구간은 파일을 다시 열기 전까지 화면을 차지했다.

## 무엇을 했나

- `buildBlocks` 가 펼쳐 둔 구간을 `opened: true` 로 표시한다 (`RenderBlock.opened`).
- 화면은 그 자리 맨 위에 `▴ 동일한 N줄 펼침 — 클릭하면 다시 접습니다` 를 단다 — 접힘 줄이 있던 자리, 같은 모양.
  펴고 접는 자리가 같아야 "눌렀던 데를 다시 누르면 된다" 로 읽힌다. 접힘 줄 아이콘도 `⋯` → `▾` 로 짝을 맞췄다.
- 30줄 넘는 구간은 아래에도 `여기까지 — 다시 접습니다` 를 단다. 아래에서 접으면 접힌 줄이 화면 가운데로 오게 옮긴다
  (안 옮기면 수십 줄이 사라지며 보던 자리를 잃는다). 나란히 보기는 좌우 두 판에 같은 줄을 달아 줄 높이가 어긋나지 않는다.
- 확인: `ord_create.pc`(운영 → 테스트)에서 48줄 펴기 → 위·아래 접기 줄(좌우 91행 일치) → 아래에서 접기 → 접힌 줄이
  화면 안(192px / 505px), 오른쪽 판도 같은 자리. 23줄은 위 줄만. 통합 보기도 같은 규칙.
- 테스트 2건 추가 (전체 479개 통과). 사용설명서 5-1 · README 갱신.
