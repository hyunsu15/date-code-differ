# 2026-08-27

## 신규 프로젝트 `code-diff` 구축

`comparsion-aicode` 를 참고해 **날짜 스냅샷 기준 소스 비교 도구**를 TypeScript 로 새로 만들었다.
참고 프로젝트와의 차이: 비교 대상이 브라우저에 올린 파일이 아니라 **외부 폴더의 날짜별 스냅샷**이다.

### 외부 폴더 읽기 (신규)

- `.env` 의 `CODE_ROOT` 로 날짜 폴더들의 부모 경로를 지정. 브라우저는 임의 경로를 읽을 수 없어 Vite 플러그인(`server/`)에 읽기 전용 API 를 붙였다.
- `CODE_EXTENSIONS`(기본 `pc,pch,h,sql,pks,pkb`)·`CODE_MAX_FILE_BYTES` 로 대상 범위를 조정한다.
- 경로 탈출을 3중으로 막았다 — 스냅샷 id 검사 / 상대경로 정규화(`..`·절대경로 거부) / 최종 절대경로가 스냅샷 안인지 확인. 심볼릭 링크는 따라가지 않는다.

### 좌/우 스냅샷 선택 + 패키지 요약 (신규)

- 헤더에서 이전/이후 날짜 폴더를 고른다. 폴더명에 `YYYYMMDD` 가 있으면 최신순 정렬, 없으면 이름 역순.
- 날짜 폴더 바로 아래 디렉터리를 **패키지**로 보고, 파일을 고르기 전에 어느 패키지가 신규·삭제·변경됐는지 상단 밴드에 요약한다. 칩을 누르면 파일 목록이 그 패키지로 좁혀진다.

### 코드 표시 범위 (신규)

- 기본값을 **변경만**(문맥 3줄, 나머지 접힘)으로 두고, **전체** 버튼으로 파일 전체를 diff 색과 함께 보도록 했다. 문맥은 0/3/8/25줄에서 고른다. `Alt+A` 로 전환.
- 파일 목록도 기본이 "변경된 파일만" 이다.

### 참고 프로젝트에서 가져온 것

- diff 엔진(`lib/diffEngine.ts`)·토크나이저·검색·하이라이트는 그대로 이식. 좌우 명칭만 AI/전문가 → 이전/이후로 바꿨다.
- 좌우 동기 스크롤, diff 포인트 이동(IntersectionObserver 추적 포함), 접기/펼치기, 코드 검색도 그대로 유지.

### 새로 만든 것

- **Pro\*C 문법 하이라이트** — Prism 의 `c` 를 확장해 `EXEC SQL … ;` 블록 안을 SQL 로, 호스트 변수(`:h_ord_no`)를 따로 칠한다. `.pks`/`.pkb` 는 SQL 로 매핑.
- **예시 외부 폴더** `sample-code/` — 날짜 스냅샷 3개(2026-06-01/07-01/08-01)에 수정·신규·삭제·신규 패키지 케이스를 모두 넣었다.

### 성능

- 파일 목록과 유사도는 서버가 계산해 **숫자만** 보낸다. 코드 본문은 선택한 파일 하나만 받아온다.
- 비교 결과를 `(left, right, 무시옵션)` 키로 메모리 캐시한다. 외부 폴더가 바뀌면 화면의 ⟳ 새로고침으로 비운다.

### 구현 중 고친 문제

- **신규/삭제 파일이 전체 통계에서 빠져 유사도가 과대평가**되던 문제. 한쪽에만 있는 파일도 빈 파일과 비교해 통계를 채우도록 고쳤다. 결과: 07-01→08-01 유사도 95% → 66%, 패키지 변경 줄 수 0 → 317줄로 실제 변경량을 반영하게 됐다.
- **파일을 바꾸면 본문이 도착하기 전까지 새 파일 제목 아래 이전 파일 코드가 보이던 문제.** `content.path` 가 선택한 파일과 일치할 때만 렌더하도록 하고, 그 사이에는 로딩 표시를 띄운다. 읽기 실패 시 무한 로딩이 되지 않도록 오류 상태도 따로 뒀다.
- 비교할 파일이 0개일 때 "전체 유사도 100%" 로 보이던 문제. 파일이 있을 때만 요약 카드를 띄운다.

### 정리한 것

- 참고 프로젝트의 diff 끄기 모드(`buildPlainRows`, `RowKind.plain`)는 이 도구의 요구사항에 없어 이식하지 않고 제거했다. 붙여넣기 모달·드롭존 관련 CSS 도 함께 정리.

### 검증

- 타입 검사 통과, 프로덕션 빌드 통과.
- 테스트 63개 전부 통과 (`npm test`). diff 엔진 이식분 + 신규 모듈(`fileTypes`, `comparisonService`) 테스트를 추가했다. 외부 폴더 읽기는 mock 대신 `sample-code` 를 실제 fixture 로 쓴다.
- 브라우저에서 확인: 패키지 밴드·파일 선택·변경만/전체 전환(63행 ↔ 31행)·문맥 0/3줄·좌우 동기 스크롤 켜기/끄기·diff 포인트 이동·CODE_ROOT 오류 안내.

### 외부 API 변경 여부

**신규 프로젝트라 기존 API 변경 없음.** 이번에 만든 API 는 아래 3개이며 전부 `GET` 읽기 전용이다. 스펙은 [API.md](../API.md) 참고.

## 날짜 폴더명 인식 범위 확대

`yyyyMMdd`(구분자 없는 형식)로도 되는지 확인 요청을 받아 점검했다.

### 확인 결과

`20260801` 은 **원래 동작**했다. 다만 **이름 앞에 다른 숫자가 붙으면 인식하지 못하는 버그**가 있었다.

기존 구현이 "숫자가 아닌 문자를 전부 지우고 앞 8자리"를 쓰다 보니 자릿수가 밀렸다.

| 폴더명 | 고치기 전 | 고친 후 |
| ------ | --------- | ------- |
| `v2_20260801` | 인식 실패 | `20260801` |
| `REL1_20260801` | 인식 실패 | `20260801` |
| `build-3-2026-08-01` | 인식 실패 | `20260801` |

### 수정 내용

`snapshotSortKey` 를 "이름 어디에 있든 **처음 나오는 유효한 날짜**를 찾는" 방식으로 바꿨다.
`/(\d{4})\D?(\d{2})\D?(\d{2})/` 로 훑되, 월·일 범위 검사에 걸리면 한 글자씩 밀며 다시 본다.
정규식은 호출마다 새로 만든다 — 모듈 전역에 두면 `lastIndex` 가 남아 다음 호출 결과가 달라진다.

구분자(`-` `.` `_` `/`)는 있어도 없어도 되고, 접두·접미가 붙어도 된다.
날짜로 안 읽히는 폴더(`trunk` 등)도 **목록에 나오고 비교도 된다.** 날짜 폴더 뒤에 이름 역순으로 놓인다.

### 화면

- 폴더명은 **디스크에 있는 그대로** 보여준다. `20260801` 을 `2026-08-01` 로 바꿔 쓰지 않는다 — 둘 다 존재할 때 구분이 안 되고, 화면에서 고른 이름이 곧 실제 폴더여야 하기 때문.
- 날짜로 인식되지 않은 폴더만 선택 목록에 `· 날짜 아님` 을 붙여, 왜 아래로 밀렸는지 알 수 있게 했다.

### 검증

- 테스트 70개 통과 (63 → 70). 표기법별 단위 테스트 5개 + **실제 임시 폴더를 만들어 정렬을 확인하는 통합 테스트 4개**(`test/snapshotNaming.test.ts`)를 추가했다.
- 실제 화면 확인: `20260601` / `v2_20260701` / `rel_20260801` / `trunk` 로 폴더를 만들어 띄웠고, 최신순 정렬·기본 선택(직전↔최신)·패키지 요약 317줄·유사도 66% 가 하이픈 표기와 동일하게 나왔다. `trunk` 에는 `· 날짜 아님` 이 표시됐다.

### 외부 API 변경 여부

**응답 형태 변경 없음.** `Snapshot.sortKey` 의 *값을 만드는 규칙*만 넓어졌다(기존에 `""` 이던 일부 폴더명이 이제 날짜를 돌려준다). 필드·타입·엔드포인트는 그대로다.

### 함께 처리한 것

- `npm run dev` 가 PowerShell 에서 안 되던 문제 — 프로젝트 문제가 아니라 **PowerShell 실행 정책(기본 `Restricted`)** 이 `npm.ps1` 로드를 막은 것이었다. 해결책은 `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`(보안 설정이라 사용자가 직접 실행) 또는 `npm.cmd` 사용. 세션 중 띄워둔 개발 서버가 5181 포트를 잡고 있어 함께 정리했다.

## 좌우 선택 순서 강제 — `이후` 는 `이전` 보다 최신만

"이후는 이전보다 뒤에 날짜는 안 보이게" 요청을 반영했다.

### 규칙

`이후` 는 항상 `이전` 보다 최신이다. 거꾸로 된 비교를 **애초에 고를 수 없게** 목록 자체를 제한한다.

- `이후` 목록: 고른 `이전` 보다 최신인 날짜만.
- `이전` 목록: 가장 최신 스냅샷 제외 (그보다 뒤가 될 날짜가 없으므로).
- `이전` 을 최신 쪽으로 옮겨 `이후` 가 더 이상 최신이 아니게 되면 `이후` 를 한 칸 더 최신으로 자동 이동.
- 스냅샷이 2개 미만이면 비교 불가 — 안내 배너.

목록은 최신순 정렬이므로 index 가 작을수록 최신이다. 규칙은 전부 index 비교로 처리했다.
날짜로 인식되지 않은 폴더(`trunk` 등)도 목록 맨 뒤에 있으므로 같은 규칙이 자연히 적용된다.

### 구조

좌우를 각각 `useState` 로 들고 있으면 "이후는 이전보다 최신" 이라는 **두 값에 걸친 불변식**을
바꾸는 곳마다 따로 지켜야 한다. 하나의 `Selection` 상태로 묶고,
순수 함수 `normalizeSelection(snapshots, want)` 한 곳에서만 바로잡도록 했다.
(`src/features/snapshots/selection.ts` — `leftChoices` / `rightChoices` 도 여기 둔다)

화면은 이 함수가 돌려준 값만 쓰므로 어떤 조작을 해도 불변식이 깨지지 않는다.

### 제거한 것

- **좌우 바꾸기(⇄) 버튼.** 이 규칙에서는 swap 이 곧 위반이라 눌러도 원래대로 되돌아오는
  무의미한 버튼이 된다. 자리에는 방향을 보여주는 `→` 를 뒀다.
- "좌우가 같은 스냅샷입니다" 경고 배너. 이제 같은 날짜를 고를 수 없어 도달 불가능한 코드다.
  대신 "날짜 폴더가 1개뿐" 안내를 넣었다.

### 검증

- 테스트 87개 통과 (70 → 87). `test/selection.test.ts` 17개 추가.
  단순 케이스뿐 아니라 **불변식 테스트**를 넣었다 — 가능한 모든 입력 조합(목록 밖 값·빈 문자열 포함)에
  대해 결과가 항상 규칙을 만족하는지, 멱등한지, 결과가 항상 화면 목록 안에 있는지.
- 실제 화면 확인:
  - 초기 — 이전 07-01 / 이후 목록 `[08-01]`
  - 이전을 06-01 로 내림 → 이후 목록이 `[08-01, 07-01]` 로 늘어남
  - 이전을 이후와 같은 07-01 로 올림 → 이후가 08-01 로 자동 이동
  - 콘솔 오류 없음, 비교 결과(패키지 4/4 · 317줄 · 66%) 동일
- 타입 검사·빌드 통과.

### 외부 API 변경 여부

**API 변경 없음.** 서버는 여전히 `left` / `right` 를 순서 제약 없이 받는다 (뒤집힌 값도 정상 처리).
제한은 화면에서 고를 수 있는 목록에만 적용된다. 이 점을 `API.md` 에 명시했다.

## 날짜 키보드 입력 + 패키지 변경 예시 보강

### 1) 날짜를 직접 타이핑할 수 있게

`<select>` 로는 날짜가 늘어날수록 스크롤이 길어진다. `<input list>` + `<datalist>` 로 바꿔
직접 치거나 목록에서 고를 수 있게 했다. 브라우저 기본 콤보박스라 ↑↓ 훑기가 그대로 된다.

해석은 순수 함수 `resolveSnapshotInput(choices, raw)` 하나로 모았다. 위에서부터 순서대로 시도한다.

1. 폴더명 완전 일치 (대소문자 무시)
2. **날짜 일치** — 입력을 `snapshotSortKey` 로 읽어 비교. 폴더가 `20260801` 이어도 `2026-08-01` 로 찾을 수 있다
3. 부분 일치 — 후보가 **딱 하나일 때만**. 여럿이면 해석하지 않는다(잘못 고르는 것보다 낫다)

확정은 Enter·포커스 아웃·목록 선택 시. 확정되면 **실제 폴더명으로 정규화**한다
(`20260801` 을 쳐도 칸에는 `2026-08-01` 이 남는다). 해석 실패는 빨간 테두리로 표시하고
확정 시 되돌린다. `Esc` 로도 되돌린다.

`이후` 후보에는 `이전` 보다 최신인 것만 담기므로, **규칙을 어기는 날짜는 쳐 넣어도 해석되지 않는다.**
목록 제한과 타이핑 검증이 같은 데이터를 쓰므로 규칙이 두 곳으로 갈라지지 않는다.

비교 중(`comparing`)에는 입력을 막지 않도록 바꿨다. 타이핑 도중 칸이 비활성화되면 포커스를 잃는다.

### 2) 패키지 변경 예시 — 4가지 상태를 한 화면에

기존 샘플로는 **`삭제된 패키지`와 `동일 패키지` 상태를 볼 수 없었다.**
앞으로 가는 비교에서 패키지가 통째로 사라지는 케이스가 없었고, 뒤로 비교는 이제 막혀 있기 때문.

`2026-09-01` 스냅샷을 추가했다. 시나리오는 "공통 모듈을 사내 표준 라이브러리로 이관".

- `cmm/` **삭제** — 3개 파일이 통째로 빠짐
- `rpt/` **신규** — 리포트 패키지 2개 파일
- `ord/` **변경** — `ord_create.pc` 의 include 가 `cmm_log.h` → `<koscom/log.h>` 로 바뀌고 로그 상수 사용
- `pay/` **변경** — `pay_pg.pks`/`.pkb` 에 조회 함수 추가
- `stl/` **동일** — 손대지 않음

`2026-08-01 → 2026-09-01` 하나로 신규·삭제·변경·동일이 모두 나온다.

### 구현 중 고친 문제

**날짜를 바꾼 직후 없는 파일을 요청해 404 가 나던 문제.**
좌우가 바뀌면 본문 요청 effect 가 즉시 도는데, 그때 파일 목록은 아직 이전 조합의 것이라

그 사이 "파일을 읽지 못했습니다" 가 깜빡이고 요청이 낭비된다.
`comparison.left/right` 가 현재 좌우와 일치할 때까지 기다리도록 고쳤다. 네트워크 로그로 404 사라진 것 확인.

## SSH 원격 소스 · 위치 설정(localStorage) · 코드 글자 크기

### 1) 비교 대상 위치를 로컬/SSH 로 나눔

`snapshotRepository` 가 `fs` 를 직접 만지던 구조를 걷어내고 `SnapshotSource` 인터페이스 뒤로 감췄다.
위 계층은 이제 **어디서 읽는지 모른다** (`코딩가이드.md` 의 "인프라의 노예가 되지 않기").

```
server/source/
  types.ts         SnapshotSource — describe / exists / listSnapshotDirs / listFiles / readFile
  localSource.ts   fs 구현 (기존 코드 이관)
  sshSource.ts     execFile('ssh', ...) 구현
  sshCommands.ts   명령 조립·출력 파싱 (전부 순수 함수)
  resolve.ts       SourceConfig → 구현 + 캐시 키
```

SSH 는 `my-vite-app/server/change/innerDev/RealSshClient.ts` 방식을 따랐다 —
라이브러리 없이 `execFile` 로 실행하고, `quoteRemotePath` 의 틸드 확장 처리도 그대로 가져왔다.

**다운로드하지 않는다.** `scp` 대신 `cat` 표준출력을 받는다.

원격 명령은 POSIX 조합만 쓴다. `find -printf`·`stat -c`·`-maxdepth` 는 GNU 전용이라
AIX·Solaris 에서 안 되므로 `ls -1F` 와 `find … -exec wc -c {} +` 를 썼다.

접속은 `BatchMode=yes` + `ConnectTimeout` 이다. **비밀번호 프롬프트가 뜨면 개발 서버가 통째로 멈추므로**
반드시 필요하다. 호스트 키는 자동 수락하지 않는다(중간자 공격을 못 막는다) — 안내로 유도한다.

### 2) 설정을 localStorage 로

`cd-source` 키에 위치 설정을 저장하고, **요청마다** 쿼리로 서버에 보낸다.
서버는 상태를 두지 않아 창을 여러 개 띄워 서로 다른 위치를 봐도 섞이지 않는다.

저장값은 사용자가 직접 고칠 수 있으므로 `parseSourceConfig` 로 한 겹 검증한다.
**비밀번호 필드는 아예 읽지 않는다** — 저장돼 있어도 설정으로 올라오지 않는다.

로컬 경로를 비우면 아무 파라미터도 안 보내고 서버가 `.env` 의 `CODE_ROOT` 를 쓴다.
설정을 만들기 전에도 그대로 동작한다.

API 가 임의 경로를 받게 됐으므로 개발 서버에 `cors: false` 를 명시했다.

### 3) 코드 글자 크기

옵션 바에 `가− / 값 / 가+` 를 넣고 `--code-size`·`--code-lh` CSS 변수를 갱신한다.
10~22px, 0.5px 단위, 값 칸을 누르면 기본값(12.5px). 줄 높이를 1.6배로 함께 움직여야
좌우 패널 행이 어긋나지 않는다. localStorage(`cd-code-font`)에 남는다.

### 구현 중 고친 문제

- **SSH 접속 실패가 "폴더 없음"으로 안내되던 문제.** `test -d X && echo` 는 경로가 없으면 exit 1 이라
  접속 실패와 구분되지 않았다. `if/else` 로 항상 정상 종료시키고 결과를 표준출력으로 알리게 바꿨다.
  이제 `SSH_UNREACHABLE` 등 실제 원인이 그대로 뜬다.
- **`listFiles` 가 접속 실패를 빈 폴더로 삼키던 문제.** 명령에 `|| true` 를 붙여 항상 정상 종료시키고,
  실패는 그대로 던지게 했다. 안 그러면 접속이 끊겨도 "변경 없음"으로 조용히 보인다.
- **위치를 바꾼 직후 옛 날짜로 비교 요청이 나가던 문제.** 그 요청이 200(빈 결과)을 받아
  `setLoadError(null)` 로 **진짜 SSH 오류 메시지를 지워버렸다.** 스냅샷 목록에 출처(`loaded.source`)를
  함께 담아, 목록이 현재 위치의 것일 때만 비교하도록 했다. 실패해도 출처를 남겨 옛 경로가 화면에 안 남는다.
- Node 의 타입 스트리핑은 **parameter property**(`constructor(private x: T)`)를 지원하지 않아
  `npm test` 가 통째로 실패했다. 명시적 필드 선언으로 바꿨다.

### 검증

- 테스트 132개 통과 (96 → 132). SSH 명령·파싱 21개(셸 주입 방어·틸드 확장·GNU 옵션 미사용·
  POSIX 종료코드 규약 포함), 설정 파싱·직렬화 15개(비밀번호 필드 차단 포함) 추가.

  - 없는 호스트 → `SSH_UNREACHABLE` + 실제 ssh 메시지, 0초

  - 설정 미완성 → `SSH_CONFIG_INCOMPLETE` 400
  - 명령 조립·출력 파싱은 순수 함수 테스트로 커버
- 화면 확인: 설정 패널 모드 전환·필수 항목 안내·적용/저장, SSH 오류 배너와 헤더 위치 표시,
  로컬 복귀 후 정상 동작(패키지 4상태·8파일·84%), 글자 크기 12.5↔14px 적용·저장.

## EUC-KR 인코딩 지원

UNIX 에서 오래 관리된 Pro\*C 소스는 EUC-KR 로 저장된 경우가 많아, 인코딩을 고를 수 있게 했다.
**로컬·SSH 양쪽에 모두 적용**된다.

### 동작

| 설정 | 동작 |
| ---- | ---- |
| **auto** (기본) | UTF-8 로 읽어보고, 유효하지 않으면 EUC-KR 로 본다 |
| **utf-8** | 항상 UTF-8. 깨진 바이트는 `U+FFFD` 로 두고 파일 전체를 살린다 (fatal 을 켜지 않는다) |
| **euc-kr** | 항상 EUC-KR |

기본값을 `auto` 로 둔 근거: **올바른 UTF-8 파일은 항상 UTF-8 로 읽힌다.**
자동 판별이 멀쩡한 파일을 망칠 수 없으므로, 설정 없이도 EUC-KR 소스가 바로 보인다.
EUC-KR 한글 바이트는 UTF-8 로는 거의 항상 잘못된 시퀀스라 판별이 잘 맞는다.
UTF-8 BOM 은 떼어내 소스 첫 줄에 보이지 않는 글자가 남지 않게 한다.

### 구현

`server/source/decode.ts` 한 곳에 모았다. 외부 의존성 없이 Node 내장 `TextDecoder` 를 쓴다.

SSH 쪽은 `execFile` 옵션을 `encoding: 'utf8'` → `'buffer'` 로 바꿔 **바이트로 받고**
`decode()` 에서 설정에 맞춰 한 번만 문자열로 옮긴다. 파일 목록·디렉터리 목록도 같은 규칙을 타므로
한글 파일명도 함께 처리된다. `stderr` 는 ssh 자체 메시지라 항상 UTF-8 로 읽는다.

인코딩이 다르면 같은 파일도 다른 내용으로 읽히므로 `sourceKey`(캐시 키)에 함께 넣었다.

### 실측으로 알게 된 제약

Node 내장 `euc-kr` 디코더는 **표준 완성형(선행바이트 `0xA1`~`0xFE`)만** 옮긴다.
CP949 확장 영역(`0x81`~`0xA0`, 예: `똠`=`0x8C 0x63`)은 처리하지 못한다 —
`windows-949` 로 불러도 같은 디코더이고, `cp949` 라는 이름은 아예 받지 않는다.

처음 주석에 "CP949 까지 처리한다" 고 썼다가 실측으로 확인해 바로잡았다.
일반적인 한글 주석은 전부 완성형 범위라 실사용에는 걸리지 않는다.
확장 글자까지 필요해지면 `iconv-lite` 를 붙여야 한다.

### 예시 파일 추가

눈으로 확인할 수 있도록 `sample-code` 에 **실제 EUC-KR 로 저장한** `pay/rpt_notice.pc` 를
08-01·09-01 두 판으로 넣었다. 한글 주석이 바뀌는 diff 라 인코딩 설정 효과가 바로 보인다.
(UTF-8 로 고정하면 깨지고, 자동·EUC-KR 로 두면 정상)

### 함께 고친 것

`server/source/resolve.ts` 의 `.join()` 구분자에 **NUL 바이트(`\0`)** 가 들어가 있었다.
캐시 키 구분자라 동작에는 지장이 없었지만 소스에 남을 값이 아니라 공백으로 고쳤다.
전체 소스를 제어문자로 훑어 다른 파일에는 없는 것을 확인했다.

### 검증

- 테스트 152개 통과 (137 → 152). 디코딩 단위 테스트 11개 + `sample-code` 의 실제 EUC-KR 파일을
  읽는 통합 테스트 3개. 그중 하나는 **UTF-8 로 고정하면 깨지는 것**을 확인해 설정이 실제로
  먹는다는 증거로 삼는다.
- API 확인: 같은 파일을 `encoding` 없이 / `utf-8` / `euc-kr` 로 각각 요청해 결과가 다른 것 확인.
- 화면 확인: 설정 패널의 자동/UTF-8/EUC-KR 전환 → diff 뷰의 한글이 각각 정상·깨짐·정상,
  localStorage 저장·복원까지.
- 타입 검사·빌드 통과.

## 위치 프리셋 · `.env` 제거 · 설정을 `change/` 로

### `.env` 를 없앴다

설정이 `.env`(문자열만) 와 화면(localStorage) 두 곳에 흩어져 있었다.
`.env` 를 지우고 **`change/config.ts` 한 파일**로 모았다. 타입이 붙고 주석을 달 수 있다.

```
change/
  config.ts    ★ 여기만 고치면 됨
```

| 내보내는 값 | 내용 | 반영 시점 |
| ---------- | ---- | --------- |
| `SOURCE_PRESETS` | 위치 프리셋 (폴더 1 + SSH 1) | **바로** — 화면이 import 하므로 HMR 로 갱신된다 |
| `SCAN` | 비교 대상 확장자 · 최대 파일 크기 | 개발 서버 재시작 후 (플러그인이 시작할 때 읽는다) |

`readSourceDefaults` 를 없애고, 로컬 상대 경로(`./sample-code`)는 서버가 **프로젝트 폴더 기준**으로 푼다.
`CODE_ROOT` 폴백이 사라졌으므로 경로가 비면 `LOCAL_ROOT_EMPTY` 로 알린다.

### 프리셋 선택

⚙ 위치 패널 맨 위에 프리셋 목록을 넣었다. 항목은 `폴더 / SSH / 직접 입력` 세 줄이다.

저장 형태를 `SourceConfig` → `{ presetId, source }` 로 바꿨다. 읽을 때:

- `presetId` 가 살아 있으면 **저장된 사본이 아니라 `change/config.ts` 의 현재 값**을 쓴다.
  파일을 고치면 바로 반영되게 하려면 이래야 한다.
- 프리셋이 없어졌거나 직접 입력이면 저장된 값을 쓴다.

화면에서 값을 손대면 `presetId` 가 `null` 로 풀려 자동으로 "직접 입력"이 된다.
프리셋을 다시 누르면 파일 값으로 되돌아온다.

프리셋을 늘리려면 `SOURCE_PRESETS` 배열에 항목을 하나 더 붙이면 된다. 화면은 그대로 늘어난다.

### 검증

- 테스트 157개 통과 (152 → 157). 프리셋 골격 검사(id 중복 없음·폴더/SSH 각 하나·필수값 채워짐)와
  **"프리셋을 고른 상태면 저장값이 아니라 파일의 현재 값을 쓴다"** 는 규칙을 테스트로 못박았다.
- 화면 확인:
  - 저장값 없이 첫 실행 → 첫 프리셋(내 PC 폴더)으로 동작, `./sample-code` 가 프로젝트 기준으로 풀림
  - SSH 프리셋 선택 → `change/config.ts` 의 host·user·root 가 폼에 채워짐
  - 호스트를 고치면 → "직접 입력"으로 자동 전환
  - 폴더 프리셋 재선택 → 파일 값으로 복원, 저장은 `{"presetId":"local", ...}`
  - **`change/config.ts` 의 label·host 를 고치고 저장 → 재시작 없이 화면에 반영됨** (HMR)
- 타입 검사·빌드 통과.

### 외부 API 변경 여부

**엔드포인트·파라미터 변경 없음.** 다만 `root` 가 로컬에서도 **필수**가 됐다
(`.env` 폴백이 없어졌으므로). 비면 `LOCAL_ROOT_EMPTY`(400). 오류 코드 1개 추가.

| 파일 | 커밋 | 역할 |
| ---- | ---- | ---- |
| `change/config.ts` | ✗ | 실제로 쓰는 설정 |
| `change/config.example.ts` | ✓ | 템플릿(기본 골격) |

### 없으면 자동으로 만든다

코드가 `change/config.ts` 를 **직접 import** 하므로(`vite.config.ts`, `sourceSettings.ts`),
gitignore 만 걸면 새로 받은 사람은 개발 서버가 아예 뜨지 않는다.
`scripts/ensure-config.mjs` 가 없을 때만 템플릿을 복사한다.

- `postinstall` — clone → install 흐름
- `predev` · `prebuild` · `pretest` · `pretypecheck` — 나중에 지웠거나 `--ignore-scripts` 로 설치한 경우

**이미 있으면 절대 덮어쓰지 않는다.** `copyFile` 에 `COPYFILE_EXCL` 을 줘서
동시에 두 명령이 돌아도 사용자 값이 날아가지 않게 했다.

## 기본 프리셋을 SSH 로

처음 열었을 때(저장된 선택이 없을 때) 고를 프리셋을 `change/config.ts` 의
**`DEFAULT_PRESET_ID`** 로 명시하고, 값을 `'ssh'` 로 뒀다.

배열 순서(첫 항목)로 정하면 UI 표시 순서를 바꿀 때 기본값이 조용히 따라 바뀐다.
별도 상수로 빼서 둘을 분리했다. 없는 id 를 적으면 첫 항목으로 떨어진다.
목록 순서도 SSH 를 앞으로 옮겨 화면에서도 먼저 보이게 했다.

### 알아둘 점

기본값이 SSH 라서 **서버 정보를 넣기 전 첫 실행에서는 접속 실패 안내가 뜬다.**
예시 폴더로 둘러보려면 ⚙ 위치에서 `내 PC 폴더` 를 고르거나
`DEFAULT_PRESET_ID` 를 `'local'` 로 바꾸면 된다. 이 점을 README·사용설명서에 적었다.

## SSH 비밀번호 인증 (라이브러리 없이)

### 되는지부터 확인했다

OpenSSH 는 비밀번호를 stdin 이 아니라 **제어 터미널**에서 읽어서 파이프로 넣을 수 없다.
`sshpass` 같은 외부 도구를 쓰지 말라고 했으므로, OpenSSH 자체 기능인 `SSH_ASKPASS` 를 확인했다.

암호 걸린 테스트 키를 만들어 `ssh-keygen -y` 로 실측했다.

| 조건 | 결과 |
| ---- | ---- |
| askpass 없이 | 프롬프트가 뜨고 실패 |
| `SSH_ASKPASS` + `SSH_ASKPASS_REQUIRE=force` | **성공** |
| Windows OpenSSH + `.cmd` 래퍼 | **성공** |
| 특수문자 비밀번호 (`p@ss&w\|o<r>d^%!x`) | **성공** (node 경유라 batch 이스케이프 무관) |

ControlMaster(터미널에서 한 번 로그인 후 재사용)도 후보였지만
**Windows OpenSSH 는 지원하지 않는다**(`getsockname failed: Not a socket`)는 것을 확인해 접었다.

### 비밀번호를 어디서 받는가 — 터미널

브라우저에 비밀번호 칸을 두면 localStorage·URL·devtools 에 노출된다.
요청대로 **터미널에서 받는다.**

```
npm run ssh-login
  → change/config.ts 의 SSH 프리셋에서 대상을 읽음
  → 가린 채로 입력받음 (화면에 안 찍힘)
  → localhost 개발 서버로 POST → 프로세스 메모리에만 보관
```

- 파일·localStorage·URL 어디에도 쓰지 않는다. 서버를 끄면 사라진다.
- 비밀번호는 자식 프로세스 **환경변수로만** 넘긴다 — 명령줄에 넣으면 `ps` 로 남에게 보인다.
- 틀리면 보관 중인 값을 지운다. 안 지우면 틀린 값으로 계속 재시도한다.

### ssh 옵션이 인증 방식마다 갈린다

키 인증은 지금처럼 `BatchMode=yes` 로 잠근다. 비밀번호 인증은 **켤 수 없다** — 켜면 askpass 도 막힌다.
대신 이렇게 막았다.

- `PubkeyAuthentication=no` — 키를 먼저 시도하다 키 암호를 묻는 일을 없앤다
- `NumberOfPasswordPrompts=1` — 틀리면 3번 재시도하지 않고 바로 실패
- `PreferredAuthentications=password,keyboard-interactive`

### API 변경

읽기 전용 GET 만 있던 API 에 **POST 가 하나 생겼다.**

```
POST /api/v1/ssh-credentials   { target, password }
```

원격을 건드리지 않고 이 프로세스 메모리에 담을 뿐이며, 터미널 스크립트만 호출한다.
`auth` 쿼리 파라미터도 추가했다(`key`|`password`, 기본 `key`).
오류 코드 2개 추가: `SSH_PASSWORD_REQUIRED`, `SSH_PASSWORD_REJECTED`.

### 구현 중 고친 문제

`ssh-login` 이 `127.0.0.1` 로 붙어 `ECONNREFUSED` 가 났다. Vite 는 `localhost` 에 바인딩하는데
Node 가 그걸 `::1` 로 먼저 잡는 경우가 있어서다. 이름(`localhost`)으로 연결하도록 고쳤다.
파이프 입력일 때 readline 터미널 제어문자가 출력에 섞이던 것도 `isTTY` 로 갈랐다.
