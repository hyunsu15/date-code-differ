# 테스트 가이드

테스트 파일은 소스 코드와 분리된 별도의 test/ 디렉토리에서 관리한다.

- 엣지 케이스를 신경쓰며 사이드 이펙트를 확인한다. 빈 입력, null, 경계값, 동시성, 실패 경로를 테스트 케이스로 작성한다.

- 문자열이 아니라 출력 행동을 검증하도록 한다. 커버리지만 늘려서는 의미가 없다.

- mock는 외부 경계에서만. 내부 구현 세부를 mocking 금지.

- 테스트를 통과시키기 위해 프로덕션 코드의 캡슐화를 깨거나, 테스트만을 위한 조건문/우회 로직을 프로덕션 코드에 추가하지 않는다. 단, 테스트 과정에서 발견된 실제 버그나 결함은 해당 버그 상황을 재현한 테스트 코드를 작성 후에 사용자에게 보고해서 선택할 권리를 줘야 한다.
