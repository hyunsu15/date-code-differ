# Google UX 가이드라인 (Material Design 기반)

> **충돌 시 우선순위:** 이 문서의 규칙이 `AppleUI가이드.md`와 충돌하면 `UI-UX-가이드라인.md`의 충돌표를 따른다. 예: 애니메이션은 AppleUI 기준 "기능 설명용 금지, 상태 변화만 표현"을 우선한다.

## 개요

Google의 UX 철학은 사용자가 쉽고 빠르게 목표를 달성할 수 있도록 돕는 데 초점을 맞춘다. 특히 Material Design을 통해 일관성 있고 직관적인 사용자 경험을 제공하는 것을 중요하게 생각한다.

---

# 6. 접근성 (Accessibility)

모든 사용자가 서비스를 이용할 수 있어야 한다.

## 원칙

* 충분한 색상 대비 제공
* 키보드 조작 지원
* 스크린 리더 지원
* 명확한 라벨 제공

## 좋은 예시

* 버튼에 aria-label 제공 (WCAG/WAI-ARIA 표준)
* 색상만으로 정보를 전달하지 않음

---

# 10. 자연스러운 인터랙션 (Motion & Interaction)

애니메이션은 기능을 설명하는 수단이어야 한다.

## 원칙

* 움직임에는 목적이 있어야 한다.
* 과도한 애니메이션을 피한다.
* 상태 변화를 자연스럽게 연결한다.

## 좋은 예시

* 화면 전환 애니메이션
* 버튼 클릭 효과
* 모달 등장 애니메이션

---

# 11. 인터랙션 상태 표현 (Interaction States)

M3는 사용자의 모든 인터랙션에 **상태 레이어(State Layer)** 를 통해 즉각적인 시각 피드백을 제공한다.

## 원칙

* Hover, Focus, Pressed, Dragged 상태를 명확히 구분한다. 공식 불투명도: Hover 8% / Focus 10% / Pressed 10% / Dragged 16%. 출처: https://m3.material.io/foundations/interaction/states/state-layers
* 색상 교체 없이 **불투명도 오버레이**로 상태를 표현한다 (브랜드 색상 유지).
* 키보드 포커스 상태는 시각적으로 명확하게 표시해야 한다 (접근성 필수).
* (권장 관행 — M3 명문 규정 미확인) 한 레이아웃에 hover 인스턴스는 최대 1개, pressed 인스턴스는 최대 1개로 제한한다 (단, Hover와 Focus 등 서로 다른 상태 유형은 중첩될 수 있다).

## 상태별 UX 의미

| 상태     | UX 목적                                     |
| -------- | ------------------------------------------- |
| Hover    | "이 요소는 클릭 가능하다"는 신호             |
| Focused  | 키보드 사용자에게 현재 위치 안내             |
| Pressed  | 클릭이 인식됐음을 즉각 확인시켜 줌          |
| Dragged  | 요소가 이동 중임을 elevation 변화로 강조 (16%) |

## 좋은 예시

* 버튼에 마우스 올리면 배경이 미세하게 밝아짐 (Hover 8%)
* Tab 키 이동 시 파란 포커스 링 또는 State Layer 표시
* 버튼 클릭 순간 Ripple 또는 어두워지는 효과 (Pressed 10%)

# 12. 컴포넌트 선택 기준 (Component Selection)

올바른 컴포넌트 선택이 일관된 UX를 만든다.

## 버튼 우선순위

| 상황                        | 권장 컴포넌트       |
| --------------------------- | ------------------- |
| 화면의 주요 액션 (1개)       | Filled Button       |
| 보조 액션                   | Outlined Button     |
| 낮은 우선순위 액션           | Text Button         |
| 화면 전체에서 가장 중요한 액션 | FAB                |

## 규칙

* 한 화면에 Filled Button(또는 FAB) 1개 원칙 — 주의를 분산시키지 않는다.
* FAB는 화면에서 가장 중요한 단일 액션(생성·시작 등)에 사용한다. 삭제·경고 등 파괴적 액션에는 지양한다. *(관행 — M3 명문 규정 미확인)*
* 카드 안에 Filled Button이 여러 개 있으면 우선순위를 재검토한다.

## 좋은 예시

* 이메일 작성 화면: FAB = "편지 쓰기", 나머지는 Text/Outlined
* 설정 화면: 저장 = Filled Button, 취소 = Text Button

# 핵심 체크리스트

* 사용자가 무엇을 해야 하는지 즉시 알 수 있는가?
* 중요한 행동이 눈에 잘 띄는가?
* UI가 일관성을 유지하는가?
* 오류 발생 가능성을 줄였는가?
* 모든 사용자에게 접근 가능한가?
* 빠르고 반응성이 좋은가?
* 불필요한 복잡성을 제거했는가?
* Hover / Focus / Pressed 상태가 시각적으로 구분되는가?
* 한 화면에 주요 CTA(Filled Button 또는 FAB)가 1개인가?
* 키보드 포커스 상태가 명확히 표시되는가?
* FAB를 파괴적 액션(삭제 등)에 사용하지 않았는가?

# 비공식 (공식 문서 미수록 · 일반 UX 원칙)

아래 항목은 공식 Material Design 문서에서 독립 원칙으로 명명·프레임화되지 않은 일반 UX·HCI 원칙(주로 Nielsen 휴리스틱)이다. 개념적으로 유효하나 Material 공식 출처는 없다.

---

# 1. 명확성 (Clarity) — 비공식

사용자는 현재 위치와 가능한 행동을 쉽게 이해할 수 있어야 한다.

## 원칙

* 화면의 목적을 명확하게 전달한다.
* 복잡한 정보를 단순하게 표현한다.
* 중요한 행동은 눈에 띄게 배치한다.
* 이해하기 쉬운 문구를 사용한다.

## 좋은 예시

* "저장", "삭제", "수정" 등 명확한 버튼명 사용
* 현재 진행 상태 표시
* 직관적인 아이콘 활용

---

# 2. 일관성 (Consistency) — 비공식

동일한 행동은 항상 동일한 방식으로 동작해야 한다.

## 원칙

* 동일한 UI 패턴을 유지한다.
* 버튼 위치와 스타일을 통일한다.
* 용어를 일관되게 사용한다.
* 사용자가 학습한 경험을 재사용할 수 있도록 설계한다.

## 좋은 예시

* 모든 화면에서 동일한 뒤로가기 방식 제공
* 동일한 의미의 버튼은 동일한 색상 사용

---

# 3. 사용자 중심 설계 (User-Centered Design) — 비공식

시스템이 아닌 사용자의 목표를 중심으로 설계한다.

## 원칙

* 사용자의 주요 작업을 우선시한다.
* 불필요한 입력을 최소화한다.
* 사용자의 인지 부담을 줄인다.
* 실제 사용 환경을 고려한다.

## 좋은 예시

* 자동완성 제공
* 기본값 설정
* 반복 입력 최소화

---

# 4. 피드백 제공 (Feedback) — 비공식

모든 사용자 행동에는 적절한 피드백이 제공되어야 한다.

## 원칙

* 클릭 결과를 즉시 알려준다.
* 로딩 상태를 표시한다.
* 오류 발생 시 원인과 해결 방법을 안내한다.

## 좋은 예시

* 저장 완료 메시지
* 진행률 표시
* 성공 및 실패 알림

---

# 5. 효율성 (Efficiency) — 비공식

사용자가 최소한의 노력으로 목표를 달성할 수 있어야 한다.

## 원칙

* 클릭 수를 줄인다.
* 반복 작업을 자동화한다.
* 자주 사용하는 기능을 쉽게 접근할 수 있게 한다.

## 좋은 예시

* 단축키 지원
* 즐겨찾기 기능
* 최근 사용 항목 제공

---

# 7. 오류 예방 (Error Prevention) — 비공식

오류를 수정하는 것보다 예방하는 것이 중요하다.

## 원칙

* 위험한 작업은 확인 절차를 제공한다.
* 입력값을 사전에 검증한다.
* 사용자의 실수를 방지하는 UI를 설계한다.

## 좋은 예시

* 삭제 전 확인 모달
* 실시간 폼 검증
* 되돌리기(Undo) 기능

---

# 8. 시각적 계층 구조 (Visual Hierarchy) — 비공식

사용자가 중요한 정보를 먼저 볼 수 있도록 설계한다.

## 원칙

* 중요한 정보는 크게 표시한다.
* 관련 요소를 그룹화한다.
* 적절한 여백을 활용한다.

## 좋은 예시

* 제목 > 부제목 > 본문 구조
* 카드 기반 레이아웃
* 충분한 공백 활용

---

# 9. 반응성과 성능 (Performance) — 비공식

빠른 인터페이스는 좋은 UX의 핵심 요소이다.

## 원칙

* 빠른 응답 속도를 제공한다.
* 사용자가 기다리는 시간을 최소화한다.
* 지연이 발생할 경우 상태를 표시한다.

## 좋은 예시

* Skeleton UI
* Lazy Loading
* Optimistic UI

---

## 결론

Google UX의 핵심은 단순히 예쁜 화면을 만드는 것이 아니라, 사용자가 쉽고 빠르게 목표를 달성할 수 있도록 돕는 것이다. 따라서 명확성, 일관성, 접근성, 효율성, 피드백 제공을 중심으로 설계하는 것이 중요하다.
