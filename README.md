# 환경 · 날짜별 소스 Diff 비교

날짜별로 쌓인 소스 스냅샷을 **좌 / 우** 로 골라 비교하는 도구다.
좌우가 각각 **환경(운영 · 테스트)** 도 고르므로, 한 환경의 두 날짜든 두 환경의 최신끼리든 견줄 수 있다.
패키지 단위 변경을 먼저 훑고, 바뀐 `.pc` 파일을 골라 코드 diff 를 본다.
**내 PC 폴더**와 **SSH 원격 서버** 둘 다 읽을 수 있다.

```
비교 대상 폴더 (change/config.ts 의 root)
├─ prod/                   ← 환경. 안 나뉘어 있으면 이 단은 없어도 된다
│  ├─ 2026-06-01/          ← 날짜 스냅샷
│  │  ├─ ord/              ← 패키지
│  │  │  ├─ ord_create.pc
│  │  │  └─ ord_cancel.pc
│  │  └─ pay/
│  ├─ 2026-07-01/
│  └─ 2026-09-01/
└─ test/
   ├─ 2026-08-01/
   └─ 2026-09-01/
```

## 시작하기

```bash
npm install
npm run dev
```

브라우저에서 http://localhost:5181 을 연다.
처음에는 **SSH 원격** 프리셋이 선택돼 있다 — 서버 정보를 넣기 전에는 접속 실패 안내가 뜬다.
함께 들어있는 예시 폴더로 먼저 둘러보려면 화면 **⚙ 위치** 에서 `내 PC 폴더` 를 고르면 된다.

설정은 전부 **`change/config.ts`** 한 파일에 있다 (`.env` 는 쓰지 않는다).

이 파일은 서버 주소·계정이 들어가므로 **저장소에 커밋되지 않는다**(`.gitignore`).
없으면 [`change/config.example.ts`](change/config.example.ts) 를 복사해 자동으로 만들어 준다
— `npm install` · `npm run dev` · `npm run build` · `npm test` 앞에서 자동으로 돈다.
**이미 있으면 절대 덮어쓰지 않는다.**

```ts
export const SOURCE_PRESETS: SourcePreset[] = [
  { id: 'ssh',   label: 'SSH 원격',   source: { mode: 'ssh', host: 'dev-server', ... } },
  { id: 'local', label: '내 PC 폴더', source: { mode: 'local', root: './sample-code', ... } },
]

/** 처음 열었을 때 고를 프리셋 */
export const DEFAULT_PRESET_ID = 'ssh'

/** 환경 폴더 — 루트 아래가 prod/ test/ dev/ 로 나뉘어 있을 때. 안 나뉘어 있으면 빈 배열 */
export const ENV_FOLDERS: EnvFolder[] = [
  { id: 'prod', label: '운영', path: 'prod' }, ...
]
export const DEFAULT_ENV_ID = 'prod'

export const SCAN: ScanConfig = {
  extensions: ['pc', 'pch', 'h', 'sql', 'pks', 'pkb'],
  maxFileBytes: 2_000_000,
}
```

> 기본값이 **SSH** 라서, 서버 정보를 넣기 전 첫 실행에서는 접속 실패 안내가 뜬다.
> 예시 폴더로 먼저 둘러보려면 `DEFAULT_PRESET_ID` 를 `'local'` 로 바꾸거나,
> 화면 **⚙ 위치** 에서 `내 PC 폴더` 를 고르면 된다 (고른 값은 저장된다).

| 고치면 | 반영 시점 |
| ------ | --------- |
| `SOURCE_PRESETS` | **바로** (화면이 다시 읽는다) |
| `ENV_FOLDERS` | **바로** (화면이 다시 읽는다) |
| `SCAN` | 개발 서버 재시작 후 |

## 비교 대상 위치 — 프리셋

화면 오른쪽 위 **⚙ 위치** 에서 프리셋을 고른다. 값은 `change/config.ts` 에 둔다.
기본 골격은 **폴더 1개 + SSH 1개** 이고, 배열에 항목을 더 붙이면 그대로 늘어난다.

| 상태 | 뜻 |
| ---- | -- |
| 프리셋 선택 | `change/config.ts` 의 값을 그대로 쓴다. **파일을 고치면 바로 반영된다** |
| 직접 입력 | 화면에서 값을 고치면 자동으로 바뀐다. 이 브라우저의 localStorage 에만 남는다 |

처음 열었을 때 고를 프리셋은 `DEFAULT_PRESET_ID` 로 정한다 (기본 `'ssh'`).
없는 id 를 적으면 목록의 첫 항목으로 떨어진다.

고른 결과는 요청할 때마다 개발 서버로 함께 보낸다 (서버는 상태를 두지 않는다).

### 내 PC 폴더

폴더 경로만 넣으면 된다. 상대 경로는 이 프로젝트 폴더 기준으로 푼다.

### SSH 원격

| 항목 | 설명 |
| ---- | ---- |
| 호스트 · 포트 | 포트를 비우면 22 |
| 계정 | 원격 사용자명 |
| 개인키 파일 | 비우면 ssh 기본 키(`~/.ssh/id_*`) |
| 원격 경로 | 날짜 폴더들의 부모. `~/release` 처럼 홈 기준도 된다 |

#### 인증 — ssh 에 맡긴다

이 도구는 **비밀번호를 받지도, 보관하지도, 대신 답하지도 않는다.** `execFile('ssh', ...)` 로
OpenSSH 클라이언트를 그대로 돌릴 뿐이고, 인증은 ssh 가 평소 하던 대로 한다 —
개인키 · ssh-agent · `~/.ssh/config`.

**`BatchMode` 를 켜지 않는다.** 키로 붙지 않으면 ssh 가 비밀번호를 물어본다. 그 프롬프트는
화면이 아니라 **`npm run dev` 를 띄운 터미널 창**에 뜬다 (OpenSSH 는 비밀번호를 stdin 이 아니라
콘솔에서 직접 읽는다). 거기에 입력하면 접속된다.

다만 **접속을 재사용하지 않는다** — 원격 명령마다 `ssh` 를 새로 띄운다.
그래서 명령 수 자체를 줄여 뒀다. 파일 하나에 명령 하나가 아니라, **한 명령에 몰아서** 묻는다.

| 동작 | ssh 접속 수 |
| ---- | ---------- |
| 날짜 목록 로딩 | 2 (폴더 이름 `ls` 한 번 + 전 폴더 `find` 한 번) |
| 좌우 비교 | 1 + 2 × ⌈파일 수 ÷ 200⌉ — 예: 500개면 7 |
| 파일 하나 열기 | 2 |

목록을 먼저 봤다면 비교의 첫 1회는 캐시로 빠진다. 좌우 내용이 같은 파일은 한쪽만 받으므로
접속 수는 그대로여도 오가는 양은 절반 아래로 떨어진다.

그래서 키 없이 쓰면 **명령마다 한 번씩** 묻는다 — 한 번 훑는 데 몇 번이다.
아무도 답하지 않으면 `COMMAND_TIMEOUT_MS`(30초) 뒤에 `SSH_TIMEOUT` 으로 끊긴다 —
터미널 창을 볼 수 없는 환경(IDE 내장 실행·백그라운드)에서는 이 경로로 떨어진다.

프롬프트 없이 쓰려면 공개키를 한 번 등록해 두면 된다.

```bash
ssh-keygen -t ed25519          # 키가 없으면
ssh-copy-id deploy@build-01    # 공개키 등록 (이때만 비밀번호를 묻는다)
```

키에 암호를 걸어 뒀다면 ssh-agent 에 한 번 올려 둔다 (`ssh-add`).
Windows 에서는 `OpenSSH Authentication Agent` 서비스를 켜고 `ssh-add` 하면 된다.

> 접속 재사용(`ControlMaster`)이 있으면 "한 번만 묻기" 가 되지만,
> **Windows 기본 OpenSSH 는 다중화를 지원하지 않는다** (`getsockname failed: Not a socket`).

#### 그 밖에

- 원격에서는 **읽기 명령만** 돈다 — `ls -1F` / `find … -exec wc -c {} +` / `cat`.
  **파일을 내려받지 않는다** (`scp` 를 쓰지 않고 `cat` 표준출력을 받는다).
- 호스트 키를 자동 수락하지 않는다. 처음 접속하는 서버는 터미널에서 한 번 `ssh` 로 접속해
  `known_hosts` 에 등록해 둬야 한다.
- GNU 전용 옵션(`find -printf`, `stat -c`, `-maxdepth`)을 쓰지 않아 AIX·Solaris 계열에서도 동작한다.
- 소스 인코딩은 **자동 판별**이 기본이다 (아래 참고).
- 라이브러리 없이 `execFile('ssh', ...)` 로 실행하며, 원격 경로는 전부 셸 인용을 거친다.

### 소스 인코딩

UNIX 에서 오래 관리된 Pro\*C 소스는 EUC-KR 로 저장된 경우가 많다. 로컬·SSH 모두에 적용된다.

| 설정 | 동작 |
| ---- | ---- |
| **자동** (기본) | UTF-8 로 읽어보고, 유효하지 않으면 EUC-KR 로 본다 |
| **UTF-8** | 항상 UTF-8. 깨진 바이트는 `U+FFFD` 로 두고 파일 전체를 살린다 |
| **EUC-KR** | 항상 EUC-KR |

자동 판별은 안전하다 — 올바른 UTF-8 파일은 **항상** UTF-8 로 읽히므로 멀쩡한 파일이 망가지지 않는다.
EUC-KR 한글 바이트는 UTF-8 로는 거의 항상 잘못된 시퀀스라 판별이 잘 맞는다.
UTF-8 BOM 은 떼어내 소스 첫 줄에 보이지 않는 글자가 남지 않게 한다.

> ⚠️ Node 내장 디코더는 **표준 완성형(선행바이트 `0xA1`~`0xFE`)만** 옮긴다.
> CP949 확장 영역(`0x81`~`0xA0`, 예: `똠` `뷁`)은 처리하지 못한다.
> 일반적인 한글 주석은 전부 완성형 범위라 실사용에는 걸리지 않는다.

## 환경 폴더 — 운영 / 테스트

환경이 루트 아래 **폴더로 나뉘어** 쌓일 때 쓴다.

```
/home/deploy/release/          ← 프리셋의 root
├─ prod/   20260801/  20260901/     ← 운영
└─ test/   20260801/  20260815/     ← 테스트
```

**좌우 칸이 각각 환경을 고른다.** 날짜 칸 왼쪽의 선택을 바꾸면 그 경로가 프리셋의
`root` **뒤에 붙는다**. 왼쪽을 운영으로 두면 그쪽은 `/home/deploy/release/prod` 를,
오른쪽을 테스트로 두면 그쪽은 `/home/deploy/release/test` 를 본다.

```
[운영 ▾ 2026-09-01]  →  [테스트 ▾ 2026-08-15]
```

양쪽을 같은 환경으로 두면 예전과 똑같이 **한 환경의 두 날짜**를 견주는 화면이 된다.

```ts
export const ENV_FOLDERS: EnvFolder[] = [
  { id: 'prod', label: '운영',   path: 'prod' },
  { id: 'test', label: '테스트', path: 'test' },
]

/** 처음 열었을 때 양쪽이 고를 값. 없는 id 면 목록의 첫 항목 */
export const DEFAULT_ENV_ID = 'prod'
```

- `path` 는 여러 단도 된다 (`'rel/qa'` → `<root>/rel/qa`).
- 하나라도 적혀 있으면 **항상 그중 하나가 골라져 있다.** "루트를 그대로" 라는 선택지는 없다 —
  그걸 고르면 날짜가 아니라 `prod` `test` 가 이전/이후 칸에 올라오기 때문이다.
- **환경마다 색이 붙는다.** 이름만으로는 잘 안 걸려서, 날짜 칸과 diff 창 머리의 표시가
  환경별 색을 쓴다. 색은 `ENV_FOLDERS` **순서**로 정해진다 (첫 항목이 주황, 그다음이 하늘색
  — `styles.css` 의 `.env-c*`). 빨강·초록은 안 쓴다: 이 화면에서 그 둘은 이미
  삭제·추가라는 뜻이라, 왼쪽 운영 태그가 "삭제됨" 으로 읽힌다.
- 고른 값은 이 브라우저의 localStorage 에 좌우 한 쌍으로 남는다. 없는 id 는 **첫 항목**으로
  떨어지고, 예전에 저장해 둔 값(환경 하나)은 **양쪽 다 그 환경**으로 읽는다.
- 거르는 게 아니라 **위치를 바꾸는** 방식이라 서버에는 환경이라는 개념이 없다 —
  붙인 결과가 그냥 그 요청의 루트가 된다. 그래서 캐시도 환경별로 저절로 갈린다.
- **같은 날짜끼리로 제한하지 않는다.** 환경마다 배포 시점이 다르니 같은 날짜 폴더가
  양쪽에 다 있으리라는 보장이 없고, 정작 제일 자주 묻는 "지금 운영과 테스트가 얼마나
  벌어져 있나" 는 각 환경의 **최신끼리** 견주는 질문이다.
- 날짜 폴더가 루트에 **바로** 있으면(`release/20260801`) 배열을 **비운다.**
  고르는 자리 자체가 화면에서 사라지고 루트를 그대로 읽는다.
- 템플릿에는 `prod` · `test` 가 들어 있다. 함께 들어있는 `sample-code/` 가 같은 배치라
  아무것도 안 고쳐도 **운영 ↔ 테스트** 를 눌러 볼 수 있다.
- 서버·계정까지 다르면 이게 아니라 환경별 `SOURCE_PRESETS` 항목을 하나씩 두는 편이 낫다.

> 예전에 만들어 둔 `change/config.ts` 에 이 항목이 없으면 환경 고르기는 그냥 숨는다
> (화면은 정상 동작한다). `npm run dev` 가 시작할 때 안내를 한 줄 남긴다.
> 이름 접두사(`prod_20260801`)로 거르던 예전 방식(`FOLDER_PREFIXES`)은 없어졌다 —
> 그 블록을 `config.example.ts` 의 `ENV_FOLDERS` 로 바꿔 넣으면 된다.

## 좌우 선택 규칙

날짜 칸은 **직접 타이핑**할 수도 있고 목록(↓)에서 고를 수도 있다.

- 폴더명을 그대로 치거나, 일부만 쳐도 후보가 하나면 잡힌다 (`06` → `2026-06-01`).
- **표기법이 달라도 된다** — 폴더가 `20260801` 이어도 `2026-08-01` 로 쳐서 찾을 수 있다.
- Enter·포커스 아웃·목록 선택으로 확정된다. 확정되면 실제 폴더명으로 정규화된다.
- 해석되지 않는 입력은 빨갛게 표시되고, 확정 시 마지막 값으로 되돌아간다. `Esc` 로도 되돌린다.

### 좌우가 **같은 환경**일 때

`이후` 는 **항상 `이전` 보다 최신**이다. 거꾸로 된 비교는 애초에 고를 수 없다.

- `이후` 목록에는 고른 `이전` 보다 최신인 날짜만 나온다.
- `이전` 목록에서는 가장 최신 스냅샷이 빠진다 — 그보다 뒤(이후)가 될 날짜가 없기 때문.
- `이전` 을 최신 쪽으로 옮겨 `이후` 가 더 이상 최신이 아니게 되면, `이후` 가 한 칸 더 최신으로 자동으로 끌려 올라간다.
- 날짜 폴더가 1개뿐이면 비교할 수 없어 안내 문구가 뜬다.

### 좌우가 **다른 환경**일 때

순서 규칙이 **없다.** 운영 9/1 을 테스트 8/1 과 견주는 것은 거꾸로 된 비교가 아니라
"테스트가 뒤처져 있다" 는 정상적인 질문이고, 환경마다 배포 시점이 다르니 오히려 그쪽이 흔하다.

- 양쪽 목록 전부가 후보가 된다. 같은 날짜끼리도, 다른 날짜끼리도 고를 수 있다.
- 각자 한 개씩만 있어도 견줄 수 있다 (같은 환경일 때만 2개가 필요하다).
- 칸 앞의 표시가 `이전`/`이후` 대신 **환경 이름**으로 바뀐다 — diff 창 머리도 같다.
  왼쪽이 더 최신일 수 있는데 "이전" 이라고 부르면 거짓말이 되기 때문이다.
- **색도 글자를 따라간다.** 환경 이름이 쓰여 있으면 환경 색, `이전`/`이후` 면 좌/우 색이다.
  글자와 색이 서로 다른 것을 가리키지 않게 한 규칙이다.

규칙은 [`features/snapshots/selection.ts`](src/features/snapshots/selection.ts) 의
`normalizeSelection` 한 곳에만 있다. 화면은 이 함수가 돌려준 값만 쓴다.

## 날짜 폴더 이름 규칙

폴더명 **어디에 있든** 처음 나오는 유효한 날짜를 찾아 최신순으로 정렬한다.
구분자(`-` `.` `_` `/`)는 있어도 없어도 되고, 앞뒤에 다른 글자·숫자가 붙어도 된다.

| 폴더명 | 인식 | 정렬키 |
| ------ | ---- | ------ |
| `20260801` | O | `20260801` |
| `2026-08-01` · `2026.08.01` · `2026_08_01` | O | `20260801` |
| `rel_20260801` · `20260801_v2` · `20260801-hotfix` | O | `20260801` |
| `v2_20260801` · `REL1_20260801` · `build-3-2026-08-01` | O | `20260801` |
| `trunk` · `2026-08` · `2026-13-01`(13월) · `2026-08-32`(32일) | X | — |

날짜로 읽히지 않은 폴더도 **목록에는 그대로 나오고 비교도 된다.**
날짜 폴더들 뒤에 이름 역순으로 놓이며, 선택 목록에 `· 날짜 아님` 으로 표시된다.

폴더명은 디스크에 있는 그대로 보여준다 — `20260801` 을 `2026-08-01` 로 바꿔 쓰지 않는다.

## 화면 구성

| 영역 | 하는 일 |
| ---- | ------- |
| 상단 헤더 | 좌우 각각의 **환경 + 날짜 폴더** 선택, 외부 폴더 다시 읽기(⟳) |
| 패키지 변경 밴드 | 어느 패키지가 신규·삭제·변경됐는지 한 줄 요약. 칩을 누르면 그 패키지로 파일 목록이 좁혀진다 |
| 옵션 바 | 코드 표시 범위(변경만/전체), 문맥 줄 수, 나란히/통합, 무시 옵션, **코드 글자 크기** |
| 왼쪽 목록 | 전체 유사도 요약 + 파일 목록. 기본은 **변경된 파일만** |
| 오른쪽 | 선택한 파일의 diff. 좌우 동기 스크롤, diff 포인트 이동, 코드 검색 |

### 코드 표시 범위

- **변경만** (기본값) — 바뀐 줄과 그 주변 문맥만 보여주고 나머지는 접는다. 접힌 줄은 눌러서 펼친다.
- **전체** — 파일 전체를 diff 색과 함께 보여준다.

문맥 줄 수는 `0 / 3 / 8 / 25` 중에 고른다. `0줄` 은 바뀐 줄만 남긴다.

### 코드 글자 크기

옵션 바의 **글자** `가− / 가+` 로 10~22px 사이에서 0.5px 씩 조절한다.
가운데 숫자를 누르면 기본값(12.5px)으로 돌아간다. 줄 높이도 1.6배로 함께 움직이고,
선택한 크기는 localStorage 에 남는다.

## 알아둘 점

- 대상 폴더는 **읽기만** 한다. 쓰기·삭제 API 는 없다 (로컬·SSH 모두).
- SSH 비밀번호는 **어디에서도 다루지 않는다.** 받지도, 보관하지도, 대신 답하지도 않는다 —
  인증은 ssh 가 개인키·ssh-agent 로 처리한다.
- 패키지 = 날짜 폴더 **바로 아래 디렉터리**. 날짜 폴더에 바로 놓인 파일은 `(루트)` 로 묶인다.
- 파일 목록·유사도는 서버가 계산해 숫자만 보내고, 코드 본문은 **고른 파일 하나만** 받아온다.
- 양쪽 합쳐 60,000줄이 넘는 파일은 비교하지 않는다.

## 예시 폴더로 확인해 보기

`sample-code/` 는 실제 배치처럼 환경으로 나뉘어 있다.

```
sample-code/
├─ prod/   2026-06-01/  2026-07-01/  2026-08-01/  2026-09-01/    ← 운영
└─ test/   2026-08-01/  2026-09-01/                              ← 테스트 (주문 모듈만)
```

**운영**을 고른 상태에서 날짜 조합을 바꿔 가며 각 상태를 확인할 수 있다.

| 비교 | 확인할 수 있는 것 |
| ---- | ---------------- |
| **2026-08-01 → 2026-09-01** | **패키지 4가지 상태가 한 화면에** — `cmm` 삭제 · `rpt` 신규 · `ord`/`pay` 변경 · `stl` 동일 |
| 위 비교의 `pay/rpt_notice.pc` | **실제 EUC-KR 로 저장된 파일.** 인코딩을 UTF-8 로 바꾸면 깨지는 것까지 볼 수 있다 |
| 2026-07-01 → 2026-08-01 | 신규 패키지(`stl`), 파일 삭제(`pay_cancel.pc`), Oracle 패키지 파일 신규(`.pks`/`.pkb`) |
| 2026-06-01 → 2026-07-01 | 파일 수정 위주 + 동일 패키지(`cmm`) |
| 2026-06-01 → 2026-09-01 | 넉 달치 누적 변경 |

`ord/ord_create.pc` 는 네 스냅샷에서 계속 바뀌므로 코드 diff·문맥 접기를 보기에 좋다.

**테스트**로 바꾸면 같은 `2026-08-01 → 2026-09-01` 이 다르게 나온다 — 테스트 서버에만
올라간 변경(`chk_isin_limit`, 종목별 주문 한도)이 하나 더 붙어 있다. 환경 버튼이
목록을 거르는 게 아니라 **읽는 위치를 바꾼다**는 걸 눈으로 확인할 수 있다.
