# 환경 · 날짜별 소스 Diff 비교

날짜별로 쌓인 소스 스냅샷을 **좌 / 우** 로 골라 비교하는 도구다.
좌우가 각각 **환경(운영 · 테스트)** 도 고르므로, 한 환경의 두 날짜든 두 환경의 최신끼리든 견줄 수 있다.
패키지 단위 변경을 먼저 훑고, 바뀐 `.pc` 파일을 골라 코드 diff 를 본다.
**내 PC 폴더**와 **SSH 원격 서버** 둘 다 읽을 수 있다.

```
비교 대상 폴더 (change/config.ts 의 root)
├─ prod/                   ← 환경. 안 나뉘어 있으면 이 단은 없어도 된다
│  ├─ 2026-06-01/          ← 날짜 스냅샷
│  │  ├─ ord/              ← 패키지
│  │  │  ├─ ord_create.pc
│  │  │  └─ ord_cancel.pc
│  │  └─ pay/
│  ├─ 2026-07-01/
│  └─ 2026-09-01/
└─ test/
   ├─ 2026-08-01/
   └─ 2026-09-01/
```

## 시작하기

```bash
npm install
npm run dev
```

브라우저에서 http://localhost:5181 을 연다.
처음에는 **SSH 원격** 프리셋이 선택돼 있다 — 서버 정보를 넣기 전에는 접속 실패 안내가 뜬다.
함께 들어있는 예시 폴더로 먼저 둘러보려면 화면 오른쪽 위 **⚙ 버튼**(지금 읽는 위치가 적힌 버튼)을 눌러 `내 PC 폴더` 를 고르면 된다.

설정은 전부 **`change/config.ts`** 한 파일에 있다 (`.env` 는 쓰지 않는다).

이 파일은 서버 주소·계정이 들어가므로 **저장소에 커밋되지 않는다**(`.gitignore`).
없으면 [`change/config.example.ts`](change/config.example.ts) 를 복사해 자동으로 만들어 준다
— `npm install` · `npm run dev` · `npm run build` · `npm test` 앞에서 자동으로 돈다.
**이미 있으면 절대 덮어쓰지 않는다.**

```ts
export const SOURCE_PRESETS: SourcePreset[] = [
  { id: 'ssh',   label: 'SSH 원격',   source: { mode: 'ssh', host: 'dev-server', ... } },
  { id: 'local', label: '내 PC 폴더', source: { mode: 'local', root: './sample-code', ... } },
]

/** 처음 열었을 때 고를 프리셋 */
export const DEFAULT_PRESET_ID = 'ssh'

/** 환경 폴더 — 루트 아래가 prod/ test/ dev/ 로 나뉘어 있을 때. 안 나뉘어 있으면 빈 배열 */
export const ENV_FOLDERS: EnvFolder[] = [
  { id: 'prod', label: '운영', path: 'prod' }, ...
]
export const DEFAULT_ENV_ID = 'prod'

export const SCAN: ScanConfig = {
  extensions: ['pc', 'pch', 'h', 'sql', 'pks', 'pkb'],
  maxFileBytes: 2_000_000,
}
```

> 기본값이 **SSH** 라서, 서버 정보를 넣기 전 첫 실행에서는 접속 실패 안내가 뜬다.
> 예시 폴더로 먼저 둘러보려면 `DEFAULT_PRESET_ID` 를 `'local'` 로 바꾸거나,
> 화면 **⚙ 설정** 에서 `내 PC 폴더` 를 고르면 된다 (고른 값은 저장된다).

| 고치면 | 반영 시점 |
| ------ | --------- |
| `SOURCE_PRESETS` | **바로** (화면이 다시 읽는다) |
| `ENV_FOLDERS` | **바로** (화면이 다시 읽는다) |
| `SCAN` | 개발 서버 재시작 후 |

## 비교 대상 위치 — 프리셋

화면 오른쪽 위 **⚙ 설정 → 위치** 에서 프리셋을 고른다. 값은 `change/config.ts` 에 둔다.
기본 골격은 **폴더 1개 + SSH 1개** 이고, 배열에 항목을 더 붙이면 그대로 늘어난다.

| 상태 | 뜻 |
| ---- | -- |
| 프리셋 선택 | `change/config.ts` 의 값을 그대로 쓴다. **파일을 고치면 바로 반영된다** |
| 직접 입력 | 화면에서 값을 고치면 자동으로 바뀐다. 이 브라우저의 localStorage 에만 남는다 |

처음 열었을 때 고를 프리셋은 `DEFAULT_PRESET_ID` 로 정한다 (기본 `'ssh'`).
없는 id 를 적으면 목록의 첫 항목으로 떨어진다.

고른 결과는 요청할 때마다 개발 서버로 함께 보낸다 (서버는 상태를 두지 않는다).

### 내 PC 폴더

폴더 경로만 넣으면 된다. 상대 경로는 이 프로젝트 폴더 기준으로 푼다.

### SSH 원격

| 항목 | 설명 |
| ---- | ---- |
| 호스트 · 포트 | 포트를 비우면 22 |
| 계정 | 원격 사용자명 |
| 개인키 파일 | 비우면 ssh 기본 키(`~/.ssh/id_*`) |
| 원격 경로 | 날짜 폴더들의 부모. `~/release` 처럼 홈 기준도 된다 |

#### 인증 — ssh 에 맡긴다

이 도구는 **비밀번호를 받지도, 보관하지도, 대신 답하지도 않는다.** `execFile('ssh', ...)` 로
OpenSSH 클라이언트를 그대로 돌릴 뿐이고, 인증은 ssh 가 평소 하던 대로 한다 —
개인키 · ssh-agent · `~/.ssh/config`.

**`BatchMode` 를 켜지 않는다.** 키로 붙지 않으면 ssh 가 비밀번호를 물어본다. 그 프롬프트는
화면이 아니라 **`npm run dev` 를 띄운 터미널 창**에 뜬다 (OpenSSH 는 비밀번호를 stdin 이 아니라
콘솔에서 직접 읽는다). 거기에 입력하면 접속된다.

다만 **접속을 재사용하지 않는다** — 원격 명령마다 `ssh` 를 새로 띄운다.
그래서 명령 수 자체를 줄여 뒀다. 파일 하나에 명령 하나가 아니라, **한 명령에 몰아서** 묻는다.

| 동작 | ssh 접속 수 |
| ---- | ---------- |
| 날짜 목록 로딩 | 2 (폴더 이름 `ls` 한 번 + 전 폴더 `find` 한 번) |
| 좌우 비교 | 1 + 2 × ⌈파일 수 ÷ 200⌉ — 예: 500개면 7 |
| 파일 하나 열기 | 2 |

목록을 먼저 봤다면 비교의 첫 1회는 캐시로 빠진다. 좌우 내용이 같은 파일은 한쪽만 받으므로
접속 수는 그대로여도 오가는 양은 절반 아래로 떨어진다.

그래서 키 없이 쓰면 **명령마다 한 번씩** 묻는다 — 한 번 훑는 데 몇 번이다.
아무도 답하지 않으면 `COMMAND_TIMEOUT_MS`(30초) 뒤에 `SSH_TIMEOUT` 으로 끊긴다 —
터미널 창을 볼 수 없는 환경(IDE 내장 실행·백그라운드)에서는 이 경로로 떨어진다.

프롬프트 없이 쓰려면 공개키를 한 번 등록해 두면 된다.

```bash
ssh-keygen -t ed25519          # 키가 없으면
ssh-copy-id deploy@build-01    # 공개키 등록 (이때만 비밀번호를 묻는다)
```

키에 암호를 걸어 뒀다면 ssh-agent 에 한 번 올려 둔다 (`ssh-add`).
Windows 에서는 `OpenSSH Authentication Agent` 서비스를 켜고 `ssh-add` 하면 된다.

> 접속 재사용(`ControlMaster`)이 있으면 "한 번만 묻기" 가 되지만,
> **Windows 기본 OpenSSH 는 다중화를 지원하지 않는다** (`getsockname failed: Not a socket`).

#### 그 밖에

- 원격에서는 **읽기 명령만** 돈다 — `ls -1F` / `find … -exec wc -c {} +` / `cat`.
  **파일을 내려받지 않는다** (`scp` 를 쓰지 않고 `cat` 표준출력을 받는다).
- 호스트 키를 자동 수락하지 않는다. 처음 접속하는 서버는 터미널에서 한 번 `ssh` 로 접속해
  `known_hosts` 에 등록해 둬야 한다.
- GNU 전용 옵션(`find -printf`, `stat -c`, `-maxdepth`)을 쓰지 않아 AIX·Solaris 계열에서도 동작한다.
- 소스 인코딩은 **자동 판별**이 기본이다 (아래 참고).
- 라이브러리 없이 `execFile('ssh', ...)` 로 실행하며, 원격 경로는 전부 셸 인용을 거친다.

### 소스 인코딩

UNIX 에서 오래 관리된 Pro\*C 소스는 EUC-KR 로 저장된 경우가 많다. 로컬·SSH 모두에 적용된다.

| 설정 | 동작 |
| ---- | ---- |
| **자동** (기본) | UTF-8 로 읽어보고, 유효하지 않으면 EUC-KR 로 본다 |
| **UTF-8** | 항상 UTF-8. 깨진 바이트는 `U+FFFD` 로 두고 파일 전체를 살린다 |
| **EUC-KR** | 항상 EUC-KR |

자동 판별은 안전하다 — 올바른 UTF-8 파일은 **항상** UTF-8 로 읽히므로 멀쩡한 파일이 망가지지 않는다.
EUC-KR 한글 바이트는 UTF-8 로는 거의 항상 잘못된 시퀀스라 판별이 잘 맞는다.
UTF-8 BOM 은 떼어내 소스 첫 줄에 보이지 않는 글자가 남지 않게 한다.

> ⚠️ Node 내장 디코더는 **표준 완성형(선행바이트 `0xA1`~`0xFE`)만** 옮긴다.
> CP949 확장 영역(`0x81`~`0xA0`, 예: `똠` `뷁`)은 처리하지 못한다.
> 일반적인 한글 주석은 전부 완성형 범위라 실사용에는 걸리지 않는다.

## 환경 폴더 — 운영 / 테스트

환경이 루트 아래 **폴더로 나뉘어** 쌓일 때 쓴다.

```
/home/deploy/release/          ← 프리셋의 root
├─ prod/   20260801/  20260901/     ← 운영
└─ test/   20260801/  20260815/     ← 테스트
```

**좌우 칸이 각각 환경을 고른다.** 날짜 칸 왼쪽의 선택을 바꾸면 그 경로가 프리셋의
`root` **뒤에 붙는다**. 왼쪽을 운영으로 두면 그쪽은 `/home/deploy/release/prod` 를,
오른쪽을 테스트로 두면 그쪽은 `/home/deploy/release/test` 를 본다.

```
[운영 ▾ 2026-09-01]  →  [테스트 ▾ 2026-08-15]
```

양쪽을 같은 환경으로 두면 예전과 똑같이 **한 환경의 두 날짜**를 견주는 화면이 된다.

**🔗 환경 묶기** 를 켜면 오른쪽이 왼쪽 환경으로 맞춰지고, 이후 어느 칸에서 바꿔도 양쪽이 함께 간다
(운영 두 날짜 ↔ 테스트 두 날짜를 오갈 때). **처음은 켜져 있다**(저장값 없음 = 켜짐) — 끄거나 켠 상태는
localStorage(`cd-env-linked`, `'0'`/`'1'`)에 남는다.

```ts
export const ENV_FOLDERS: EnvFolder[] = [
  { id: 'prod', label: '운영',   path: 'prod' },
  { id: 'test', label: '테스트', path: 'test' },
]

/** 처음 열었을 때 **왼쪽**이 고를 값. 오른쪽은 그다음 환경. 없는 id 면 목록의 첫 항목 */
export const DEFAULT_ENV_ID = 'prod'
```

- `path` 는 여러 단도 된다 (`'rel/qa'` → `<root>/rel/qa`).
- 하나라도 적혀 있으면 **항상 그중 하나가 골라져 있다.** "루트를 그대로" 라는 선택지는 없다 —
  그걸 고르면 날짜가 아니라 `prod` `test` 가 이전/이후 칸에 올라오기 때문이다.
- **환경마다 색이 붙는다.** 이름만으로는 잘 안 걸려서, 날짜 칸과 diff 창 머리의 표시가
  환경별 색을 쓴다. 색은 `ENV_FOLDERS` **순서**로 정해진다 (첫 항목이 주황, 그다음이 하늘색
  — `styles.css` 의 `.env-c*`). 빨강·초록은 안 쓴다: 이 화면에서 그 둘은 이미
  삭제·추가라는 뜻이라, 왼쪽 운영 태그가 "삭제됨" 으로 읽힌다.
- 저장된 좌우가 없으면 왼쪽은 `DEFAULT_ENV_ID`, 오른쪽은 목록에서 그다음 환경이다. 다만 **환경 묶기가
  처음 켜져 있어** 열 때 오른쪽이 왼쪽에 맞춰진다 — 처음 화면은 `DEFAULT_ENV_ID` 한 환경의 최근 변경이다.
  묶기를 끄면 그다음부터는 저장된 좌우(운영 ↔ 테스트 등) 그대로 열린다. 환경이 하나뿐이면 양쪽이 같다.
- 고른 값은 이 브라우저의 localStorage 에 좌우 한 쌍으로 남는다. 없는 id 는 **첫 항목**으로
  떨어지고, 예전에 저장해 둔 값(환경 하나)은 **양쪽 다 그 환경**으로 읽는다.
- 거르는 게 아니라 **위치를 바꾸는** 방식이라 서버에는 환경이라는 개념이 없다 —
  붙인 결과가 그냥 그 요청의 루트가 된다. 그래서 캐시도 환경별로 저절로 갈린다.
- **같은 날짜끼리로 제한하지 않는다.** 환경마다 배포 시점이 다르니 같은 날짜 폴더가
  양쪽에 다 있으리라는 보장이 없고, 정작 제일 자주 묻는 "지금 운영과 테스트가 얼마나
  벌어져 있나" 는 각 환경의 **최신끼리** 견주는 질문이다.
- 날짜 폴더가 루트에 **바로** 있으면(`release/20260801`) 배열을 **비운다.**
  고르는 자리 자체가 화면에서 사라지고 루트를 그대로 읽는다.
- 템플릿에는 `prod` · `test` 가 들어 있다. 함께 들어있는 `sample-code/` 가 같은 배치라
  아무것도 안 고쳐도 **운영 ↔ 테스트** 를 눌러 볼 수 있다.
- 서버·계정까지 다르면 이게 아니라 환경별 `SOURCE_PRESETS` 항목을 하나씩 두는 편이 낫다.

> 예전에 만들어 둔 `change/config.ts` 에 이 항목이 없으면 환경 고르기는 그냥 숨는다
> (화면은 정상 동작한다). `npm run dev` 가 시작할 때 안내를 한 줄 남긴다.
> 이름 접두사(`prod_20260801`)로 거르던 예전 방식(`FOLDER_PREFIXES`)은 없어졌다 —
> 그 블록을 `config.example.ts` 의 `ENV_FOLDERS` 로 바꿔 넣으면 된다.

## 날짜 고르기 목록 — 변경 이력(쌍) · 날짜 직접

날짜 칸을 누르면 직접 그린 목록이 열린다(브라우저 `datalist` 로는 탭·두 줄 표시를 못 한다).
같은 환경이면 **변경 이력**이 먼저 — 바뀐 일 하나 = `이전 → 이후` 한 쌍, 누르면 두 칸이 함께 정해진다.
`날짜 직접` 탭은 한쪽씩 고른다. 보기·순서는 localStorage(`cd-date-list`)에 남는다(`features/snapshots/dateList.ts`).

- 예전에는 날짜 하나에 "N개 바뀜(바로 앞 날짜 대비)" 을 붙였는데, 비교는 쌍이라 목록 숫자와 고른 뒤 결과가 어긋났다.
  이력 줄의 숫자는 **그 쌍을 고르면 나올 결과 그대로**다.
- 이력은 날짜별 변경 수(`GET /snapshots/changes` · `/schemas/changes`)에서 만든다(`changeHistory`). 오래된 날부터
  "내용이 같은 날짜 묶음" 을 이어 가서, 배포 없던 날은 따로 줄이 생기지 않고 쌍의 앞쪽은 그 내용이 처음 생긴 배포일이 된다.
- **처음 열 때** 같은 환경이면 최근 변경(앞 배포일 → 최신)으로 맞춘다 — 최신 날짜와 바로 앞 날짜가 똑같은 폴더라
  빈 비교가 뜨는 것을 막는다. 사람이 날짜를 고른 뒤에는 손대지 않는다(코드 탭만 — 스키마는 코드 날짜에 맞추는 규칙이 있다).
- 환경이 다르면 이력이 성립하지 않아 날짜 직접만, 맨 위에 `운영 최신 ↔ 테스트 최신` 빠른 선택. 각 칸에는 자기 환경의 배포일 표시.
- **검색은 보기와 따로** 이 칸의 전체 날짜에서 찾는다.
- 수는 파일 단위·바이트 기준(무시 옵션 미적용), 팀 제외 목록 적용. SSH 는 이미 받은 체크섬으로 — 추가 접속 없음.
  스키마는 **테이블 단위**, 시스템 이름 제약은 파서가 접어 세지 않는다. 숫자 앞에 단위(`파일` · `테이블`)를 적는다.

## 좌우 선택 규칙

날짜 칸은 **직접 타이핑**할 수도 있고 목록(↓)에서 고를 수도 있다.

- 폴더명을 그대로 치거나, 일부만 쳐도 후보가 하나면 잡힌다 (`06` → `2026-06-01`).
- **표기법이 달라도 된다** — 폴더가 `20260801` 이어도 `2026-08-01` 로 쳐서 찾을 수 있다.
- Enter·포커스 아웃·목록 선택으로 확정된다. 확정되면 실제 폴더명으로 정규화된다.
- 해석되지 않는 입력은 빨갛게 표시되고, 확정 시 마지막 값으로 되돌아간다. `Esc` 로도 되돌린다.

### 좌우가 **같은 환경**일 때

`이후` 는 **항상 `이전` 보다 최신**이다. 거꾸로 된 비교는 애초에 고를 수 없다.

- `이후` 목록에는 고른 `이전` 보다 최신인 날짜만 나온다.
- `이전` 목록에서는 가장 최신 스냅샷이 빠진다 — 그보다 뒤(이후)가 될 날짜가 없기 때문.
- `이전` 을 최신 쪽으로 옮겨 `이후` 가 더 이상 최신이 아니게 되면, `이후` 가 한 칸 더 최신으로 자동으로 끌려 올라간다.
- 날짜 폴더가 1개뿐이면 비교할 수 없어 안내 문구가 뜬다.

### 좌우가 **다른 환경**일 때

순서 규칙이 **없다.** 운영 9/1 을 테스트 8/1 과 견주는 것은 거꾸로 된 비교가 아니라
"테스트가 뒤처져 있다" 는 정상적인 질문이고, 환경마다 배포 시점이 다르니 오히려 그쪽이 흔하다.

- 양쪽 목록 전부가 후보가 된다. 같은 날짜끼리도, 다른 날짜끼리도 고를 수 있다.
- 각자 한 개씩만 있어도 견줄 수 있다 (같은 환경일 때만 2개가 필요하다).
- 칸 앞의 표시가 `이전`/`이후` 대신 **환경 이름**으로 바뀐다 — diff 창 머리도 같다.
  왼쪽이 더 최신일 수 있는데 "이전" 이라고 부르면 거짓말이 되기 때문이다.
- **색도 글자를 따라간다.** 환경 이름이 쓰여 있으면 환경 색, `이전`/`이후` 면 좌/우 색이다.
  글자와 색이 서로 다른 것을 가리키지 않게 한 규칙이다.

규칙은 [`features/snapshots/selection.ts`](src/features/snapshots/selection.ts) 의
`normalizeSelection` 한 곳에만 있다. 화면은 이 함수가 돌려준 값만 쓴다.

## 날짜 폴더 이름 규칙

폴더명 **어디에 있든** 처음 나오는 유효한 날짜를 찾아 최신순으로 정렬한다.
구분자(`-` `.` `_` `/`)는 있어도 없어도 되고, 앞뒤에 다른 글자·숫자가 붙어도 된다.

| 폴더명 | 인식 | 정렬키 |
| ------ | ---- | ------ |
| `20260801` | O | `20260801` |
| `2026-08-01` · `2026.08.01` · `2026_08_01` | O | `20260801` |
| `rel_20260801` · `20260801_v2` · `20260801-hotfix` | O | `20260801` |
| `v2_20260801` · `REL1_20260801` · `build-3-2026-08-01` | O | `20260801` |
| `trunk` · `2026-08` · `2026-13-01`(13월) · `2026-08-32`(32일) | X | — |

날짜로 읽히지 않은 폴더도 **목록에는 그대로 나오고 비교도 된다.**
날짜 폴더들 뒤에 이름 역순으로 놓이며, 선택 목록에 `· 날짜 아님` 으로 표시된다.

폴더명은 디스크에 있는 그대로 보여준다 — `20260801` 을 `2026-08-01` 로 바꿔 쓰지 않는다.

| 영역 | 하는 일 |
| ---- | ------- |
| 상단 헤더 | **지난주** 프리셋(지지난주 금요일 → 지난주 금요일 시점, `lastWeekSelection` — 그 주에 새 폴더가 없으면 같은 날짜끼리 골라 "바뀐 것 없음" 을 보인다), 좌우 각각의 **환경 + 날짜 폴더** 선택, 환경 묶기(🔗), 외부 폴더 다시 읽기(⟳), **보고서 내려받기(⬇)**, 지금 읽는 위치가 적힌 **⚙ 설정** 버튼, **? 도움말** |
| 모드 탭 | `코드 비교` / `스키마 비교`. 좌우 선택은 그대로 두고 아래 3단만 갈린다 |
| 패키지 변경 밴드 | 어느 패키지가 추가·삭제·변경됐는지 한 줄 요약. 칩을 누르면 그 패키지로 파일 목록이 좁혀진다 |
| 옵션 바 | 코드 표시 범위(변경만/전체), 문맥 줄 수, 나란히/통합, **보기 옵션 ▾**(무시 옵션 · 줄바꿈 · 코드 글자 크기, 버튼에 켜 둔 무시 수) |
| 왼쪽 목록 | 전체 유사도 한 줄 요약(`자세히 ▾` 로 지표 펼침) + 파일 목록. 바뀐 파일이 위, 동일한 파일은 맨 아래 `▾ 동일한 파일 N개` 로 접힌다(`SameFold`, `lib/changedFirst.ts`). 검색은 접기와 상관없이 전체. 바뀐 것이 하나도 없으면 오른쪽에 "모두 동일 · 펼치기" 안내(`AllSameNotice`) |
| 오른쪽 | 선택한 파일의 diff. 맨 위 한 줄에 파일 경로(왼쪽)와 diff 포인트 이동(이전/다음 · 목록) · 코드 검색 · 파일 이동(오른쪽), 좌우 동기 스크롤 |

### 코드 표시 범위

- **변경만** (기본값) — 바뀐 줄과 그 주변 문맥만 보여주고 나머지는 접는다. 접힌 줄은 눌러서 펼치고,
  펼친 자리 위의 `▴ … 다시 접습니다` 를 누르면 다시 접힌다(`RenderBlock.opened`). 30줄 넘게 펼치면 아래에도 접기 줄을 단다.
- **전체** — 파일 전체를 diff 색과 함께 보여준다.

문맥 줄 수는 `0 / 3 / 8 / 25` 중에 고른다. `0줄` 은 바뀐 줄만 남긴다.

### 제외 목록 — 늘 안 봐도 되는 파일 접어 두기

자동생성물·벤더 코드처럼 매번 봐도 소용없는 파일을 **텍스트 파일**에 적어 두면 목록에서 접힌다.
파일 경로는 **⚙ 설정 → 제외 규칙** 의 `팀 제외 목록 파일` 또는 `change/config.ts` 프리셋의 `excludeFile` 에 적고,
비워 두면 아무것도 접지 않는다.

```
# 왜 뺐는지 적어 둘 수 있다
*_common.h, *_bak.pc
rpt
ord/tmp
```

- 항목은 **쉼표 또는 줄바꿈**으로 구분한다 (`SCAN.excludeSeparators` 로 바꿀 수 있다)
- 이름만 적으면 어느 폴더에 있든, 폴더 이름을 적으면 그 아래 전부, 슬래시가 들어가면 루트부터 맞춘다
- `*` 는 한 폴더 안, `**` 는 폴더를 넘어, `?` 는 한 글자. **정규식은 받지 않는다**
- 대소문자는 가리지 않는다 (같은 규칙이 윈도우와 UNIX 에서 다르게 먹지 않도록)

**거르는 게 아니라 접는 것이다.** 걸린 파일도 비교는 그대로 하고 목록에서만 접으며,
목록 위에 `제외 4 · 변경 1` 처럼 **접은 수와 그중 바뀐 수**가 늘 뜬다. 누르면 펼쳐지고,
접힌 항목에는 어느 규칙에 걸렸는지가 함께 나온다.

운영과 테스트가 얼마나 벌어졌는지 보려고 여는 도구에서 "안 보이는 파일" 은 사고가 된다 —
제외해 둔 자리에 진짜 변경이 들어와도 아무도 모른 채 지나가기 때문이다. 그래서 지우지 않는다.

그 대신 **읽는 양은 줄지 않는다.** 아예 읽지 않으려면 `SCAN` 으로 대상 확장자를 좁힌다
(그렇게 빠진 파일은 목록 위에 `대상 밖 N` 으로 따로 뜬다).

규칙 파일은 한 번 읽어 두고 쓴다 — 내용을 고친 뒤에는 화면의 **⟳ 새로고침** 을 누른다.

### 내 제외 목록 — 화면에서 바로 접기

위 **제외 목록 파일**은 팀이 함께 쓰는 규칙이다. 고치려면 파일을 열어 고치고 새로고침해야 하고,
SSH 로 볼 때는 그 파일이 원격에 있어 손대기도 어렵다. 그런데 실제로 자주 필요한 것은
**"지금 이 파일은 안 볼래"** 다.

파일 목록 항목의 **⊘** 를 누르면 그 파일이 접힌다. **이 브라우저에만 남고**, 팀 규칙 파일은
건드리지 않는다. 되돌리려면 "제외 N" 을 눌러 펼친 뒤 **↩** 를 누른다.

| | 제외 목록 파일 | 내 제외 목록 |
| --- | --- | --- |
| 어디에 | 소스와 같은 자리의 txt | 이 브라우저 (localStorage) |
| 누가 본다 | 팀 전체 | 나만 |
| 고치려면 | 파일 수정 + 새로고침 | 목록에서 한 번 누르기 |

⊘ 를 누르면 오른쪽 아래 알림에 **되돌리기** 가 붙는다(6초).
여러 줄을 한꺼번에 적거나 글로브를 쓰려면 **⚙ 설정 → 제외 규칙 → 내 제외 목록** 에서 편집하고
**적용** 을 누른다. 문법은 규칙 파일과 같다.

**두 목록 모두 거르는 게 아니라 접는 것이다.** 접힌 것 중에 바뀐 파일이 있으면
`제외 5 (내 2) · 변경 1` 처럼 함께 알린다 — 접어 둔 자리에 들어온 변경이 묻히지 않는다.

### 실패는 알림으로 뜬다

스키마를 읽지 못했거나 형식이 안 맞아 못 읽은 줄이 생기면 오른쪽 아래에 알림이 뜬다.
**오류 알림은 저절로 사라지지 않는다** — 직접 닫아야 없어진다.

못 읽은 줄이 있으면 **원인을 짚고 파일의 그 줄을 그대로 보여준다.**

```
⚠ 못 읽은 줄이 4개 있습니다
구분자가 안 맞습니다 — 설정은 '|' 인데 파일은 ',' 로 갈라져 있습니다.
change/config.ts 의 SCHEMA.separator 를 고치고 개발 서버를 다시 시작하세요.

파일에는 이렇게 적혀 있습니다:
  [COLUMN],TB_ORD,ORD_NO,VARCHAR2,20,,,N
```

### 무시 옵션

"이 정도 차이는 같은 것으로 치자" 를 정한다. **공백 · 빈 줄 · 주석 · 작성자 · 죽은 코드가
켜진 채로 열리고**, 대소문자만 꺼져 있다 — C·PL/SQL 에서 `Total` 과 `total` 은 서로 다른
이름이라 켜면 진짜 차이를 덮는다. 고친 값은 localStorage(`cd-ignore`) 에 남는다.

빠진 줄은 화면에서 사라지지 않고 흐린 `무시` 행으로 남는다 — 통계에서만 빠진다.

| 옵션 | 기본 | 무엇을 뺀다 |
| ---- | ---- | ---------- |
| 공백 | 켜짐 | 들여쓰기·공백량 차이 (줄을 빼는 게 아니라 같은 줄로 본다) |
| 대소문자 | 꺼짐 | 대소문자 차이 (같은 줄로 본다) |
| 빈 줄 | 켜짐 | 빈 줄 |
| 주석 | 켜짐 | 주석만 있는 줄 |
| 작성자 | 켜짐 | `작성자 : 홍길동` · `수정자` · `변경자` · `@author` 줄 |
| 죽은 코드 | 켜짐 | 조건이 거짓으로 못박힌 블록 (`#if 0` … `#endif`) |

주석은 **파일을 위에서부터 훑어** 판정한다. 그래야 여러 줄에 걸친 주석이 통째로 빠진다
(줄 하나만 봐서는 블록 안의 글자가 주석인지 알 수 없다). `/* */` · `//` · SQL 의 `--`
를 보고, 문자열 리터럴 안의 주석 기호는 주석으로 보지 않는다.

- `#` 은 주석이 아니다 — 대상 언어에서 전처리기 지시자다. `#include` 는 그대로 비교한다.
- `--` 뒤에 영숫자가 바로 붙으면(`--i;`) 감소 연산자로 본다.
- 줄 끝 역슬래시(`// 주석 \`)는 다음 줄까지 주석을 끌고 간다 — 컴파일러가 그렇게 읽는다.
- **코드 뒤에 붙은 주석은 함께 비교한다.** 주석 "전용 줄" 만 빼는 범위다.

**죽은 코드**는 주석이 아니라 조건부 컴파일이지만, 조건이 거짓으로 못박힌 블록은 어떤
빌드에서도 안 돌아 주석과 같다. `#if 0` · `#if FALSE` · PL/SQL 의 `$IF FALSE $THEN` 을
짝이 맞는 `#endif` / `$END` 까지 뺀다 (안에서 다시 열린 `#if` 는 세어서 넘긴다).

- `#ifdef DEBUG` · `#if VERSION > 2` · 헤더 가드는 **건드리지 않는다.** 빌드에 따라
  실제로 도는 코드다.
- `#if 0` 의 `#else` · `#elif` 가지는 살아 있으므로 거기서 멈춘다.
- `#ifdef NEVER` 처럼 이름으로만 죽여 둔 것은 빼지 않는다 — 정의 여부를 알 수 없다.

### 코드 글자 크기

**보기 옵션 ▾** 안의 **글자** `가− / 가+` 로 10~22px 사이에서 0.5px 씩 조절한다 (스키마 비교는 옵션 바에 바로 있다).
가운데 숫자를 누르면 기본값(12.5px)으로 돌아간다. 줄 높이도 1.6배로 함께 움직이고,
선택한 크기는 localStorage 에 남는다.

## 데이터 스키마 비교

화면 위 **`스키마 비교`** 탭을 누르면 같은 좌우 선택(환경·날짜)으로 **DB 테이블 정의**를 견준다.
"운영과 테스트의 테이블이 지금 같은가" 를 소스와 같은 자리에서 확인하기 위한 것이다.

덤프는 소스와 **다른 자리**에 쌓이므로 위치를 따로 적는다. 프리셋의 `schemaRoot` 를 비워 두면
탭을 눌러도 안내만 뜨고 아무것도 읽지 않는다.

```ts
// SOURCE_PRESETS 안, excludeFile 바로 아래
schemaRoot: '/data/db-schema',
```

```
<schemaRoot>/
├─ prod/  snapshot_prod_2026-08-01.txt      ← 날짜가 폴더가 아니라 파일 이름에 있다
│         snapshot_prod_2026-09-01.txt
└─ test/  snapshot_test_2026-09-01.txt
```

환경 폴더 이름은 위 `ENV_FOLDERS` 의 `path` 를 그대로 쓴다.
접속 정보(호스트·계정·키·인코딩)는 그 프리셋의 것을 그대로 쓰므로, 같은 서버면 경로 한 줄이면 된다.

### 파일 형식

Oracle 딕셔너리를 그대로 흘린 텍스트다. 줄마다 앞머리 `[ ]` 로 종류를 밝히고 나머지를 구분자로 가른다.
종류마다 첫 줄에 헤더를 두면 **필드 순서를 파일에서 읽으므로**, SELECT 목록이 바뀌어도 도구를 안 고쳐도 된다.

```
# 주문·결제계 스키마 — 2026-09 정기배포 반영본     ← 맨 위 # 줄은 화면에 설명으로 뜬다

[COLUMN],TABLE_NAME,COLUMN_NAME,DATA_TYPE,DATA_LENGTH,DATA_PRECISION,DATA_SCALE,NULLABLE
[COLUMN],TB_ORD,ORD_NO,VARCHAR2,20,,,N
[CONSTRAINT],TABLE_NAME,CONSTRAINT_NAME,CONSTRAINT_TYPE,COLUMN_NAME,TO_CHAR(POSITION)
[CONSTRAINT],TB_ORD,PK_ORD,P,ORD_NO,1
[INDEX],TABLE_NAME,INDEX_NAME,UNIQUNESS,COLUMN_NAME,TO_CHAR(COLUMN_POSITION)
[INDEX],TB_ORD,IX_ORD_01,NONUNIQUE,ORD_DT,1
```

이름 규칙과 구분자는 `change/config.ts` 의 `SCHEMA` 에서 정한다 (고치면 **개발 서버 재시작**).

```ts
export const SCHEMA: SchemaConfig = {
  fileName: 'snapshot_{env}_{date}.txt',   // {date} 로 날짜 목록을 뽑는다
  separator: ',',                          // 덤프가 파이프로 나오면 '|'
  systemNamePattern: '^(SYS_|BIN[$])',     // 아래 참고
}
```

### 값을 그대로 견주지 않는다 — 세 자리

딕셔너리 값을 곧이곧대로 비교하면 **없는 변경**이 생긴다. 셋 다 읽는 단계에서 정리한다.

| | 그대로 두면 | 어떻게 |
| --- | --- | --- |
| **시스템 제약** | Oracle 은 NOT NULL 컬럼마다 `SYS_C0011234` 를 만드는데 **번호가 DB 마다 다르다.** 운영↔테스트에서 내용이 같아도 수백 개가 전부 "변경" 으로 뜬다 | `systemNamePattern` 에 걸리면 접는다. NOT NULL 여부는 컬럼 줄에 그대로 있어 잃는 정보가 없다 |
| **길이** | `DATA_LENGTH` 는 문자형에서만 뜻이 있다. NUMBER 는 늘 22, DATE 는 늘 7 인 내부 저장 크기다 | 세 필드를 표시용 타입 하나로 합친다 — `NUMBER(15,2)` · `VARCHAR2(20)` · `DATE` |
| **다중 컬럼 키** | 기본키·인덱스가 `POSITION` 을 단 **여러 줄**로 흩어져 온다. 줄 단위로 보면 컬럼 하나 추가가 "추가 1 + 기존 그대로" 로 갈라진다 | 이름으로 묶고 위치 순으로 이어 `ORD_NO, ORD_SEQ` 한 줄로 |

**접은 것은 조용히 지우지 않는다.** 화면에 늘 `시스템 N 접음` 이 남는다 — 제외 목록에서
"제외 N" 을 남겨 둔 것과 같은 이유다.

### 스키마에서 안 볼 것 접어 두기

코드 비교와 같은 두 겹이다 — **팀 규칙 파일**과 **내 목록**. 여기에 **종류 토글**이 하나 더 있다.

| | 어디에 | 누가 본다 | 고치려면 |
| --- | --- | --- | --- |
| 스키마 제외 목록 파일 | 프리셋의 `schemaExcludeFile` | 팀 전체 | 파일 수정 + 새로고침 |
| 내 스키마 제외 목록 | 이 브라우저 | 나만 | 목록·표에서 ⊘ 한 번 |
| 종류 토글 | 옵션바 체크 3개 | 나만 | 체크 끄기 |

문법은 **코드 쪽 제외 목록과 같다.** 대상만 파일 경로가 아니라 테이블과 그 안의 이름이다.

```
TB_ORD_BAK        그 테이블과 그 아래 전부
TB_ORD.ORD_MEMO   그 테이블의 그 컬럼만
*.REG_DTM         모든 테이블의 그 컬럼 (감사 컬럼을 치울 때)
IX_*_TMP          이름이 맞는 인덱스·제약 (어느 테이블이든)
```

테이블 목록과 컬럼·제약·인덱스 줄마다 **⊘** 가 있다. 누르면 내 목록에 한 줄로 들어가고,
되돌리려면 `제외 N` 을 눌러 펼친 뒤 **↩** 를 누른다. 팀 규칙 파일에 적혀 접힌 것은
⊘ 가 눌리지 않는다 — 고칠 자리가 다르다.

**종류 토글**은 컬럼 / 제약 / 인덱스를 통째로 끈다. "이번 배포는 인덱스 성능 얘기라 안 본다"
처럼 한 종류를 치울 때, 제외 목록에 규칙을 적는 것보다 빠르다.

**셋 다 거르는 게 아니라 접는다.** 접힌 수와 **그중 바뀐 수**가 늘 남는다 —
`제외 5 (내 2) · 변경 1`. 접어 둔 자리에 들어온 변경이 조용히 묻히면 안 되기 때문이다.

> ⚠ 규칙 파일의 **설명 줄에는 쉼표를 쓰지 마세요.** 쉼표로 먼저 가른 뒤 조각마다 `#` 를
> 보므로, 쉼표 뒷부분이 규칙으로 잡힙니다 (코드 쪽 제외 목록도 같습니다).

### 화면

| 영역 | 하는 일 |
| ---- | ------- |
| 밴드 | 변경된 테이블 수 · 접은 제약 수 · 종류 필터 칩 |
| 설명 줄 | 파일 맨 위 `#` 주석의 첫 줄. 좌우가 다르면 둘 다 보여준다 (그것도 변경이다) |
| 왼쪽 목록 | 테이블 목록. 둘째 줄에 종류별 바뀐 줄 수(`컬럼 4 · 인덱스 2`). 배지는 테이블이 통째로 한쪽에만 있을 때만. 검색은 **컬럼 이름까지** 본다. 동일한 테이블은 맨 아래 접힘 줄 — 검색은 접기와 상관없이 전체 |
| 오른쪽 | 고른 테이블의 **컬럼 · 제약 · 인덱스** 3개 섹션. 줄 앞 칩에 무엇이 어떻게 됐는지 말로(`추가` · `삭제` · `타입 변경`), 표 이름 줄에 색·말 범례 |

화면 칩·목록과 보고서 문장은 같은 곳(`features/schema/schemaWording.ts`)에서 말을 만든다 — 화면과 공지가 다른
말을 하지 않게. 말은 **추가 · 삭제 · 변경** 셋뿐이고 늘 왼쪽 → 오른쪽으로 읽는다 — 줄 색(초록·빨강·주황)과 같은 뜻.
환경이 달라도 같다. 예전에 환경 간에만 `테스트에만` · `다름` 을 썼더니 빨간 줄에 `운영에만` 이 붙어 "운영에만 있고 삭제됐다"
로 읽혔다. 대신 **범례**(`changeLegend`)가 각 말을 지금 고른 이름으로 푼다(`삭제 — 운영에는 있고 테스트에는 없음`).
범례 속 이름은 열 머리와 같은 환경 색 **태그**다 — 글자색만 바꾸면 주황 `운영` 이 주황 `변경` 과 섞여 보여서 모양을 맞췄다.
| 옵션 바 | 줄 범위(변경만/전체) · **종류 토글** · 글자 크기 |

**좌우 선택은 코드 비교와 같은 헤더 컨트롤로 한다.** 환경도 날짜도 같은 자리에서 고르고,
양쪽을 같은 환경으로 두면 그 환경의 두 날짜 비교가 된다 (운영↔운영 · 테스트↔테스트).
기본은 코드 비교와 같은 운영 ↔ 테스트다.

**목록만 갈아 끼운다.** 스키마 덤프는 배포와 주기가 달라 날짜가 코드와 다르므로, 탭마다
자기 목록과 자기 선택을 따로 기억한다 — 탭을 오가도 상대 쪽이 흔들리지 않는다.
스키마 탭을 처음 열 때는 **코드에서 고른 날짜에 날 수로 가장 가까운 스키마**를 골라 준다
(앞이든 뒤든. 거리가 같으면 앞의 것 — 그 시점에 이미 걸려 있던 스키마). 그 뒤로는 고른 값이 그대로 남는다.
예전에는 "그 날짜 이하" 만 봐서, 하루 뒤 덤프를 두고 한 달 전 것을 고르거나 이하가 없으면 맨 끝으로 튀었다.

글자 크기는 코드 화면과 **같은 값을 나눠 쓴다** — 탭을 옮길 때마다 글자가 변하면 거슬린다.

**기본키가 바뀌면 `⚠` 를 올린다.** 빈도는 낮고 위험은 크다 (데이터 이관·중복).
추가·삭제된 테이블에는 붙이지 않는다 — 거기서는 당연한 일이라 알림이 흔해지면 진짜 신호가 묻힌다.

### 덤프 만들기 — `shl/schema-dump.sh`

덤프 파일을 **내 PC 에서 만들어 서버에 올리는** 쉘 스크립트다. 웹 도구와 따로 돈다.
윈도우에서는 `.cmd` 래퍼로 PowerShell · cmd 에서 바로 부른다 — 안에서 Git for Windows 의 bash 로 같은 `.sh` 를 돌리므로
로직은 한 벌이다. `.ps1` 이 아닌 이유는 윈도우 기본 실행 정책(Restricted)에서 `.ps1` 은 막히기 때문이다.
DB 는 PC 에서만 붙고 서버는 DB 에 못 붙는 환경이라, 조회는 PC 가 하고 서버는 파일만 받는다.
배포본은 지금처럼 읽기만 하고, 배포 빌드에도 섞이지 않는다.

```bash
shl\install-oracle-client.cmd       # 한 번만 — Instant Client 19(sqlplus)를 shl/oracle/ 에 푼다
shl\schema-dump.cmd prod            # 오늘 날짜로 조회 → shl/out/ 에 저장 → 서버에 업로드
shl/schema-dump.sh prod             # Git Bash · 리눅스에서는 .sh 를 바로
```

| 파일 | 하는 일 |
| ---- | ------- |
| `change/schema-dump.env` | SSH · DB 접속 · 올릴 폴더. **커밋 안 됨**. 설정은 `config.ts` 와 한곳에 둔다. 호출할 때 따로 지정하지 않아도 스크립트가 찾는다 |
| `shl/schema-dump.env.example` | 위 파일의 템플릿 (커밋됨). 위 파일이 없으면 이것을 복사해 만들고 멈춘다 |
| `change/check_table.sql` | 조회 SELECT. **커밋한다** — 사람마다 쿼리가 다르면 같은 DB 를 떠도 날짜끼리 없는 변경이 생긴다. 위 [파일 형식](#파일-형식)(헤더 `PROMPT` + `[종류],…` 줄)만 지키면 고쳐도 된다 |
| `shl/schema-dump.sh` | 위 SQL 앞뒤에 형식 설정(`SET`) · 오류 처리 · 접속을 붙여 실행하고 올린다. 치환 변수는 `&owner`(= `DB_OWNER`, 비었으면 접속 계정) 하나만 받는다 |
| `shl/install-oracle-client.sh` | 설치가 아니라 **압축 해제**. SHA256 을 맞춰 보고 다르면 풀지 않는다 |
| `shl/*.cmd` · `_git-bash.cmd` | 윈도우 래퍼. Git 의 bash 를 찾아 같은 이름의 `.sh` 를 부른다 (PATH 의 bash 는 WSL 일 수 있어 쓰지 않는다) |
| `.gitattributes` | `.sh` 는 LF, `.cmd` 는 CRLF 로 고정 — `core.autocrlf=true` 인 PC 에서 받아도 bash 가 깨지지 않는다 |

- **비밀번호는 저장하지 않는다.** 실행할 때마다 묻고, sqlplus 에는 표준입력으로 넘겨 프로세스 목록에도 안 보인다.
- **덮어쓰지 않는다.** 같은 이름이 서버에 있으면 멈춘다 — 다시 뜨려면 `--force`.
- 임시 이름으로 다 받은 뒤 이름을 바꾸므로, 업로드가 끊겨도 화면이 반쪽 파일을 읽지 않는다.
- DB 오류(`ORA-` · `SP2-`)나 테이블 0개면 아무것도 올리지 않는다. sqlplus 는 `WHENEVER` 를 접속 뒤에 걸면
  접속 실패에도 종료 코드 0 으로 끝나므로 접속 앞에 걸고, 그래도 잡히지 않는 `SP2-` 는 출력 글자로 가린다.
- SQL 파일에 `&owner` 말고 다른 치환 변수가 있으면 실행 전에 멈춘다 — sqlplus 가 값을 물으며 다음 SQL 줄을
  값으로 삼켜 조용히 엉뚱한 결과를 내기 때문이다. 메모장이 붙인 BOM · CRLF 는 걷어내고 넘긴다.
- SSH 는 비교 화면과 같은 규칙 — 키가 없으면 ssh 가 비밀번호를 묻는다 (업로드는 한 번).

## 보고서 내려받기

헤더의 **⬇ 보고서** 가 지금 비교를 공지용 md 로 내려받는다 (`src/features/report/`).
맨 위 표(환경 · 종류 · 변경 건수 · 날짜) 하나와 바뀐 파일·테이블 목록뿐이다.

**나뉜 버튼**이다 — 본 버튼은 **마지막으로 고른 보고서**(처음은 통합), ▾ 메뉴에서 통합 · 소스 · 스키마를
고르면 받으면서 그게 본 버튼이 된다 (`ReportButton.tsx` · `reportPreference.ts`, localStorage `cd-report-kind`).
GitHub 병합 버튼과 같은 방식 — 가장 많이 받는 통합은 한 번에, 다른 걸 자주 받는 사람도 한 번 고르면 한 번에.
스키마 위치가 없으면 본 버튼은 소스로 내려간다(고른 값은 남겨 둔다). 받을 수 없는 항목은 지우지 않고 잠근 채
이유를 적는다(스키마 위치 미설정 · 비교 중). 파일 이름에 종류가 들어간다(`비교보고서_통합_…`).

| 보고서 | 스키마 날짜 |
| ------ | ----------- |
| 스키마 (스키마 탭에서) | 화면에 보이는 덤프 그대로 (`pinned`) |
| 스키마 (코드 탭에서) · 통합 | 소스 날짜에 가장 가까운 덤프 — 한 문서 안에서 시점이 어긋나지 않게 |

- **서버를 거치지 않는다.** 화면이 들고 있는 비교 결과로 만들어 브라우저에서 바로 받는다. API 변경 없음.
- **숫자는 화면과 같다.** 제외 목록·내 목록·스키마 종류 토글로 접은 것은 빼고 센다.
- **스키마는 누를 때 읽는다.** 스키마는 탭을 열 때만 읽으므로, 코드 탭에서 누르면 화면과 같은
  순서(날짜 목록 → 날짜 맞추기 → 대조 → 접기)로 그 자리에서 읽는다. 실패하면 소스만 담고 알림을 띄운다.
- **스키마 날짜는 늘 보고서의 소스 날짜에 맞춘다** (가장 가까운 덤프). 스키마 탭에서 예전에 고른 날짜는
  쓰지 않는다 — 그 뒤 소스 날짜를 바꿨으면 한 문서 안에서 두 시점이 섞인다. 덤프 날짜가 소스와 다르면
  표 아래에 "○○ 대신 △△" 를 적는다.
- **같은 환경에서 두 날짜가 같은 덤프로 맞춰지면 견주지 않는다.** 화면 컨트롤의 순서 규칙(오른쪽이 더 최신)을
  걸면 오른쪽이 다음 덤프로 밀려 7월 소스 비교에 9월 스키마 변경이 실린다. 그때는 `—` 와 사유를 적는다.
- **소스 본문은 넣지 않는다.** 공지로 퍼지는 문서라 코드가 실려 돌아다니면 안 된다.
- UTF-8 BOM 을 붙인다 — 없으면 윈도우 메모장 일부 버전이 한글을 깨뜨린다.

## 명령어

```bash
npm run dev        # 개발 서버 (기본 5181 포트)
npm run build      # 타입 검사 + 프로덕션 빌드
npm run preview    # 빌드 결과 실행 (API 포함)
npm test           # 테스트
npm run typecheck  # 타입 검사만
npm run shots      # 사용설명서 스크린샷 다시 뽑기 (dev 가 떠 있어야 한다)
```

dev·build·test·typecheck 는 시작 전에 `change/config.ts` 가 있는지 확인하고,
없으면 템플릿에서 만들어 준다. 따로 준비할 것이 없다.

`shots` 는 화면을 고친 뒤 설명서 그림이 낡지 않게 하는 용도다. 이미 깔려 있는
Chrome·Edge 를 헤드리스로 띄워 찍으므로 따로 받을 것이 없다 (없으면 `CHROME_PATH` 로
경로를 알려주면 된다). 박스와 번호는 [`scripts/shot.html`](scripts/shot.html) 이
**실제 요소 좌표를 읽어** 그리므로, 화면이 조금 움직여도 엉뚱한 곳을 가리키지 않는다.

## 알아둘 점

- 대상 폴더는 **읽기만** 한다. 쓰기·삭제 API 는 없다 (로컬·SSH 모두).
  서버에 쓰는 것은 따로 실행하는 `shl/schema-dump.sh` 하나뿐이고, 웹 도구는 그것을 부르지 않는다.
- SSH 비밀번호는 **어디에서도 다루지 않는다.** 받지도, 보관하지도, 대신 답하지도 않는다 —
  인증은 ssh 가 개인키·ssh-agent 로 처리한다.
- 패키지 = 날짜 폴더 **바로 아래 디렉터리**. 날짜 폴더에 바로 놓인 파일은 `(루트)` 로 묶인다.
- 파일 목록·유사도는 서버가 계산해 숫자만 보내고, 코드 본문은 **고른 파일 하나만** 받아온다.
- 양쪽 합쳐 60,000줄이 넘는 파일은 비교하지 않는다.

## 예시 폴더로 확인해 보기

`sample-code/` 는 실제 배치처럼 환경으로 나뉘어 있다.

```
sample-code/
├─ prod/   2026-06-01/  2026-07-01/  2026-07-15/  2026-08-01/  2026-08-15/  2026-09-01/  2026-09-05/   ← 운영
└─ test/   2026-08-01/  2026-08-15/  2026-09-01/                                                       ← 테스트 (주문 모듈만)
```

`07-15` · `08-15` · `09-05`(운영)와 `08-15`(테스트)는 **배포가 없던 날**이다 — 앞 배포일 폴더를 그대로 복사해 뒀다.
날짜가 매일 쌓이는 실제 배치처럼, 날짜 고르기의 **변경 이력**이 이런 날을 줄로 만들지 않고 앞 배포일에 묶는 것과,
처음 열 때 빈 비교(09-01 → 09-05) 대신 **최근 변경(08-01 → 09-05)** 이 골라지는 것을 볼 수 있다.

**운영**을 고른 상태에서 날짜 조합을 바꿔 가며 각 상태를 확인할 수 있다.

| 비교 | 확인할 수 있는 것 |
| ---- | ---------------- |
| **2026-08-01 → 2026-09-01** | **패키지 4가지 상태가 한 화면에** — `cmm` 삭제 · `rpt` 추가 · `ord`/`pay` 변경 · `stl` 동일 |
| 위 비교의 `pay/rpt_notice.pc` | **실제 EUC-KR 로 저장된 파일.** 인코딩을 UTF-8 로 바꾸면 깨지는 것까지 볼 수 있다 |
| 2026-07-01 → 2026-08-01 | 패키지 추가(`stl`), 파일 삭제(`pay_cancel.pc`), Oracle 패키지 파일 추가(`.pks`/`.pkb`) |
| 2026-06-01 → 2026-07-01 | 파일 수정 위주 + 동일 패키지(`cmm`) |
| 2026-06-01 → 2026-09-01 | 넉 달치 누적 변경 |

`ord/ord_create.pc` 는 배포일마다 계속 바뀌므로 코드 diff·문맥 접기를 보기에 좋다.


### 스키마 예시 폴더

`sample-schema/` 에 같은 배치의 덤프를 넣어 뒀다.

```
sample-schema/
├─ prod/  snapshot_prod_2026-08-01.txt   snapshot_prod_2026-08-15.txt   snapshot_prod_2026-09-01.txt
└─ test/  snapshot_test_2026-08-01.txt   snapshot_test_2026-09-01.txt
```

`snapshot_prod_2026-08-15.txt` 는 08-01 과 내용이 같고 **SYS_C 번호만 다른** 덤프다 — 날짜 고르기의 변경 이력에서
테이블 변경 0 으로 세져 따로 줄이 생기지 않는 것(시스템 이름 제약은 세지 않는다)을 확인할 수 있다.

| 비교 | 확인할 수 있는 것 |
| ---- | ---------------- |
| **운영 2026-09-01 ↔ 테스트 2026-09-01** | **시스템 제약이 왜 접혀야 하는지.** SYS_C 번호가 양쪽 다 다르지만 진짜 차이는 셋뿐이다 — `ORD_MEMO` 미반영 · `APRV_NO` 널 허용 · `TB_RPT_NOTICE` 없음 |
| 운영 2026-08-01 → 2026-09-01 | 컬럼 추가·삭제, `NUMBER(15,2)`→`NUMBER(18,2)`, **기본키에 컬럼 추가**(⚠), 인덱스 추가 |
| 운영 ↔ 테스트 2026-08-01 | 테이블 자체가 한쪽에만 있는 경우 (정산계 미반영) |

**테스트**로 바꾸면 같은 `2026-08-01 → 2026-09-01` 이 다르게 나온다 — 테스트 서버에만
올라간 변경(`chk_isin_limit`, 종목별 주문 한도)이 하나 더 붙어 있다. 환경 버튼이
목록을 거르는 게 아니라 **읽는 위치를 바꾼다**는 걸 눈으로 확인할 수 있다.
